# 比较替代接口

只有在当前任务确实存在关键设计取舍时使用；沿用 [技能入口](SKILL.md) 的项目边界。

先写明需要保留的行为、真实调用方、依赖、错误和取消语义，必要时按 [依赖参考](DEEPENING.md) 判断测试方法。

默认由单 Agent 比较最有代表性的方案，不强制方案数量、不创建词汇表。只有用户明确要求或适用仓库约定要求时，才使用多代理协作。

每个方案说明：

- 调用方接口及其必须知道的前提、顺序和失败语义。
- 哪些实现细节得到隐藏，哪些仍由现有 Model、Controller、Repository/Gateway 持有。
- 对当前调用方、状态/资源归属和测试的影响。
- 收益、成本及不确定事实。

按调用方负担、改动局部性、职责边界和验证成本推荐最小可行方案；保留现状也可作为候选。不为追求灵活性而新增本次需求用不到的模式、参数或适配器。

比较方案不代表已获实施、提交或发布授权；依原任务范围推进。

适配自 Matt Pocock 的 `DESIGN-IT-TWICE.md`；来源提交与许可证见 [SKILL.md](SKILL.md)。
