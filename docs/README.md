# 文档入口

先读根目录 [AGENTS.md](../AGENTS.md)，了解工作方式、目录归属和通用红线。本文只负责 `docs/` 的分类、状态约定和阅读路由；按任务查对应入口，不必通读全部文档。

## 目录职责

| 位置 | 放什么 | 生命周期 |
| --- | --- | --- |
| `docs/*.md` | 跨模块专题的当前规范、实现说明和操作流程（bigmap、zcds、章节地图、构建、协议等） | 随功能维护；被新实现取代后归档 |
| `agent/` | 协作规范、路由表、审查标准、测试基线与版本库约定 | 长期维护；规则改动同步路由和验证 |
| `design/` | 在用方案、迁移清单、代码优化清单及配套 csv | 方案落地后保留 30 天，再归档 |
| `spec/` | 业务规格、跨端规则、映射表和 docx | 需求有效期内保留；带日期的盘点快照按 90 天口径保留 |
| `reports/` | 一次性审计、扫描和验证报告 | 时点记录保留 90 天，再归档 |
| `history/` | 已失效或被取代的文档 | 永久保留，只维护索引 |
| `ops/` | 打包、热更新、环境等操作流程 | 随流程版本维护 |
| `superpowers/` | SDD 计划和执行记录 | 任务结束后按需归档 |

`docs/` 根目录只放跨模块专题；单模块方案进 `design/`，业务规格进 `spec/`，一次性报告进 `reports/`。不为目录整齐批量改名或搬迁。

## 状态约定

每份非长期规范文档在标题下第一段写状态，便于区分当前信息与历史：

- `> 状态：在用（YYYY-MM-DD 核对）。剩余事项见 §x。`
- `> 状态：实现说明（最后核对 YYYY-MM-DD）。`
- `> 状态：时点报告（YYYY-MM-DD），结论不代表当前状态。`
- `> 状态：已归档（YYYY-MM-DD）。现行版本见 …；归档原因 …。`

常青规范（`AGENTS.md`、架构规范、MVC、开发细则、路由表、审查规范、版本库约定）不写状态头。方案标“已完成”前必须核对代码、配置或测试；没有证据的写“待核实”。

## 维护规则

- 同一规则只维护一处：工作方式与边界在 `AGENTS.md`，分层与运行时在架构规范 §2～§3，类型与命名在开发细则，MVC 在 MVC 设计规范，测试路由在路由表，审查判据在代码审查规范。其他文档引用，不复制整段。
- 路由真源只有 [agent/规范路由与最小验证.md](agent/规范路由与最小验证.md) 和 [zcds-表现层与领地规范.md](zcds-表现层与领地规范.md) 的分节表。其他文档表格不写完整 `tests/xxx.test.ts` 路径；需要提测试时省略 `tests/` 前缀。
- 移动带路由行的文档前，先把路由行迁到主表，再移动，最后跑 `npm run verify:route`。
- 方案完成 30 天后、时点报告 90 天后归档到 `history/YYYY/`；移动前更新所有引用，归档后在该文首段写归档日期、现行版本和原因，并登记 [history/README.md](history/README.md)。
- 文档内链接用相对路径，移动后逐条核对可解析。引用图片前先确认文件存在；当前 `docs/` 下没有 png，历史截图引用已移除，验收写成数值、断言或命令。
- 新增或移动文档后跑 `npm run verify:hygiene`，并检查根目录没有遗留散件。
