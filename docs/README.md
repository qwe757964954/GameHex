# 文档目录约定（2026-11-16 起）

根目录只保留工程入口 `AGENTS.md`、`README.md`；其余文档按用途归档。新增文档先选目录，再写内容。

本次根目录迁移记录见 [`agent/目录组织与根目录治理方案.md`](agent/目录组织与根目录治理方案.md)。

| 目录 | 放什么 | 生命周期 |
| --- | --- | --- |
| `agent/` | AI 协作规范、路由表、代码审查、清理方案 | 长期维护；改动需同步路由与验证 |
| `design/` | 功能/架构/迁移方案，及其配套 csv/清单 | 落地后 30 天归档到 `history/` |
| `spec/` | 业务规格、需求文档、映射表、docx | 需求有效期内保留，过期归档 |
| `ops/` | 打包、热更新、环境、发布流程（html 等） | 随流程版本维护 |
| `reports/` | 一次性审计、扫描报告（含 txt） | 30 天后归档 |
| `history/` | 已失效文档、旧计划 | 永久保留，只维护索引 |
| `superpowers/` | SDD 计划与执行记录 | 任务结束后按需归档 |

## 约束

- 根目录不再新增 `.md`；只允许 `AGENTS.md`、`README.md`。
- `docs/design/布局与外观硬编码迁移方案.md` 是路由真源（5 行）。改名或移动前先同步
  `docs/agent/规范路由与最小验证.md`，并跑 `npm run verify:route`。
- 文档内引用写仓库相对路径（`docs/...`、`assets/...`），不写个人绝对路径。
- 一次性报告、扫描结果不要留在根目录：放 `docs/reports/` 或 `outputs/`。
- 新增/移动文档后跑 `npm run verify:hygiene`，确认根目录没有遗留散件。
