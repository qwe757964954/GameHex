# 代码审查规范

> 适用范围：`D:\City1001\Demo3.8` 全部源码、配置、资源与测试。通用边界见[工程入口](../../AGENTS.md)，本文件只定义「一次改动凭什么放行」，不定义业务参数、颜色、功能范围。
>
> **一句话判据**：本仓库基线长期带红，审查放行看的是**相对基线零新增**，不是「全绿」。

## 0. 为什么不能靠「跑一遍看绿不绿」

`tools/verify/verify.mjs` 头注记录了基线实况：全量约 4294 条用例中 166 条失败、`assets/script` 下 tsc 269 条错误。在这种基线上，「有红灯」不等于本次改坏了，「修掉几个红灯」也不等于本次改对了。

三条不可协商的放行判据：

| 判据        | 取值来源                          | 放行条件                      |
| --------- | ----------------------------- | ------------------------- |
| 新增失败用例    | `verify check` 的「新增失败用例」清单    | 0 条，且按**用例名集合**做双向差集，不看总数 |
| 新增 tsc 错误 | `verify check` 的「新增 tsc 错误」清单 | 0 条；总数下降不作数，只看指纹差集        |
| 验证覆盖      | `verify route` 的「完全无覆盖的改动文件」  | 0 个；非 0 时必须逐个写明人工验证方式     |

`verify` 退出码：`0` 相对基线零新增 / `1` 有新增 / `2` 工具自身出错（无基线、路由真源解析失败也算 2）。**退出码 2 时任何 PASS 都不算数**。

## 1. 风险分级决定审查深度

沿用工程入口的「按风险选择流程」，不因宽泛触发词叠加流程。

| 级别 | 典型改动                     | 审查深度                                 | 是否需同行评审             |
| -- | ------------------------ | ------------------------------------ | ------------------- |
| 低  | 文案、常量、局部样式、文档整理          | 定位 → 修改 → 针对性验证                      | 否，作者自检即可            |
| 中  | 业务规则、状态、异步与生命周期          | 先定义输入/输出/错误/取消语义与不变量，再追调用链；补回归测试     | 是，1 人               |
| 高  | 跨模块、新系统、资源归属重构、协议或配表契约变更 | 简明设计与实施计划 → 分步实现 → 边界验证；先核实契约，禁止单侧修改 | 是，2 人（其中 1 人核对架构归属） |

**无论哪一级，命中以下触发器即升为「高」**：

- 涉及 `.prefab` / UI 节点树 / `@property` 绑定 → 必须走 Cocos Creator 编辑器 MCP，禁止手写 prefab JSON。
- 动到 `svn status` 里已有他人 `M` 的文件 → 先确认归属与 mtime，重施加改动时保持原换行符。
- 改生成文件、配表、`library/temp/build/native` → 需确认工具链与产物归属。
- 改动 `docs/agent/规范路由与最小验证.md` 的路由表 → 影响自动门禁选例，需复核命中数。

## 2. 三道门

| 门        | 责任人         | 必做                      | 放行条件          |
| -------- | ----------- | ----------------------- | ------------- |
| G0 作者自检  | 提交人         | 列改动清单；按第 3、4 节自查；跑最小验证集 | 自检结论写进提交说明    |
| G1 自动门禁  | 提交人         | 执行第 2.1 节命令序列，保留原始输出    | 三条判据全过        |

### 2.1 G1 命令序列（仓库根执行）

- `svn status` —— 标注每个 `M` 的归属。
- `node tools/verify/verify.mjs route` —— 确认路由命中，重点看「完全无覆盖」清单。
- `node tools/verify/verify.mjs check` —— 跑 diff 命中的最小用例集 + tsc，对比基线。
- `node tools/verify/verify.mjs defs` —— 检查改动集内互相引用的符号是否都有导出（跨文件改动「先写定义再写调用点」，规则 402）；有缺失退出码 1。该模式独立收集 `.ts` / `.mjs`，不改变 `check` / `full` 的改动集口径。
- `node tools/verify/verify.mjs gate`（或 `npm run verify:gate`）—— 提交前一键跑 `route → defs → check`，任一门非 0 即不放行，并把三段原始输出与判据汇总归档到 `outputs/audit-<日期>/gate-<时间>.md`；同目录首次会生成 `审查报告.md` 骨架（已存在则不覆盖）。
- `npm run verify:guards` —— 护栏用例的**单一真源**：本地护栏回归只认 `package.json` 里这一份清单。新增护栏用例要同时更新这里与 `verify-gate.test.ts` 的 G7 期望集，两处不一致即红；清单里必须包含 G7 自己，否则守门禁的用例静默不跑。**Git 相关不处理**：不启用 hook、不跑 CI，也不在别处另抄清单。
- 命中视图意图或 caller 改动时，追加绑定用例（见工程入口「验证与交付」）。
- 跨模块或公共契约变更，再跑 `node tools/verify/verify.mjs full`。
- 无基线或基线过期时先 `node tools/verify/verify.mjs baseline`，**不得用它掩盖新增红灯**。

**共享工作副本的口径陷阱**：`verify.mjs` 用 `svn status` 自动收集改动文件，会把同事未提交的 `M` 一起算进「本次改动集」，从而放大待跑用例、污染差集口径。审查报告里的「本轮改动集」必须是**本次实际 touch 的文件白名单**；判据差异用「归一换行符后的 `difflib` 结构化差分」确认，禁止直接拿 `svn diff` 的整文件替换结果当依据。A/B 归因要切同一条基线，取 **B−A 差集**，不要拿快照基线混比。

### 2.2 G2 评审纪律

- 一轮反馈给全，不挤牙膏；先给总体结论与关键风险，再逐条意见。
- 意见必须**具体到行**、说明 Why、给可执行的建议；用「建议考虑 X，因为 Y」，不写「这里写得不好」。
- 区分事实与偏好：能用命令或文档证明的才标 P0；风格偏好最多 P2。
- 好实现要点名，便于团队复用既有模式。
- 意图不明时先提问，别默认对方写错了。

### 2.3 G3 提交与回流

- SVN + Git 双库，提交日志纯中文；SVN 仅用 TortoiseProc 图形通道，**提交按钮由人手动点**，未核实结果前不得声称提交成功。详见[版本库约定](版本库约定.md)。
- 审查报告归入 `outputs/audit-<日期>/`，含改动清单、门禁原始输出、意见汇总、结论、未覆盖风险。
- 本轮踩到的新坑：当日写进 `.workbuddy/memory/YYYY-MM-DD.md`，跨会话复用的规则并进 `MEMORY.md` 既有编号（合并优先于新增）。
- 检查已通过且无新改动时，不重复运行。

## 3. 审查标准（Checklist）

等级：`P0` 阻断合并 / `P1` 建议本轮修 / `P2` 可选。括号内为可复核的依据。

### 3.1 P0 阻断

1. **分层与依赖方向**：`core` 保持纯 TS，禁引入 `cc` / framework / app / platform、禁直接 I/O 与全局服务；`framework` 不依赖 feature 与 `Procedure*`；adapter 不放业务规则。（工程入口「通用红线」、`docs/AI架构与代码规范.md` §2）
2. **MVC 职责**：View 不持有 Controller/Entry、不做业务回调/扣费/网络请求；Model 不引用 Cocos 节点、不广播全局 UI 事件；Page 不创建或释放 Controller。（`docs/agent/MVC设计规范.md`）
3. **异步与取消**：`await` / Promise 回调后判失效与取消；普通组件销毁时 `GameNet.removeCaller(this)`；取消须释放回调并让 Promise 以 `false` 落定；退出时统一解绑事件、缓存与网络请求。同步事件与 `schedule` 回调不重复判 `isValid`。
4. **引用与类型**：必填 Inspector 引用用 `null!`，真可空字段用 `| null`；不用 `as any`、非空断言、静默 `?.` 掩盖错误。`strictNullChecks` 未开启，查表不变量直接访问，可空值先窄化。
5. **资源与配置入口**：正式流程的资源/配置/网络走 `AssetService` / `ConfigService` / `NetworkTransport` 或既有 repository/gateway；feature 禁直调 `resources.load` / `fetch`。
6. **事件与交互**：事件在 `onInit`/`onLoad` 绑定，不加「只绑一次」门闩；交互节点在 prefab 挂 `cc.Button`（NONE、target=null），代码只绑 CLICK，禁止 CLICK/TOUCH_END 兜底。
7. **Prefab 与资源**：prefab/scene 用 Cocos MCP 定位验证并刷新，meta 由引擎生成；脚本造节点须有 UITransform，CUSTOM Sprite 设 `_isTrimmedMode=false`；新增 `.ts` / 目录必带 `.meta`；新增图目录先登记并核 `auto-atlas.pac.meta` 容量账。
8. **导表**：第 2 行导出标志、第 6 行类型声明；改 xlsx 禁 openpyxl，走 zip 级 XML 末尾追加；改动前后核对 mtime 与是否有导出进程在跑。
9. **测试有效性**：测试直接 import 真实函数/常量，不复制算法；结构约束用守卫，业务规则用行为测试；**用例改动一律用失败用例名集合做双向差集**，禁止只看总数。数据驱动测试必须有「列存在性断言 + 解析不到即失败 + 目标数量守卫」，否则列缺失时断言零执行、用例假绿。
10. **契约双侧**：协议、配置、资源事实先核实契约，不能单侧改动；本次变更同步落实到代码、配置和相关测试。

### 3.2 P1 建议

1. render 幂等、全量赋值；动画用 `startedAt` + 纯函数算进度，视图不零散建 tween 或累加 dt；`update` 不加载资源、不查全局配置、不创建临时数组/节点、不混业务规则。
2. 单例明确初始化归属及重置/释放策略；页面、对局、实体状态由宿主持有实例，禁止无归属 static 暂存或借单例绕过分层。
3. `await` 前保存局部引用；组合层统一创建并持有 M/C/V，流程持有组合对象。
4. 优先复用既有模式、类型、文本常量、资源加载器与测试夹具，不另建平行状态机或工具类。
5. 关键路径补回归测试：错误/取消语义、边界值、跨模块契约各至少一条。
6. 删整条 import 前按**当前编译口径**核实（`tests/isolated-compile-import.test.ts` 已固化）：工程为 `module: ES2015` + `isolatedModules`、未开 `verbatimModuleSyntax`，**未使用的 value import 与 `import type` 都会被擦除**；只有「使用中的值导入」和「裸副作用导入 `import './m'`」会产生真实模块加载，后者是唯一「未使用也不能删」的类别。哪天开了 `verbatimModuleSyntax`，结论整体翻转——D1 守卫会先红。

### 3.3 P2 提示

命名与风格、注释与文档缺口、可考虑的替代写法；以 `docs/agent/开发细则.md` 为准，不把偏好升级为红线。

## 4. 静默失效专项（本仓库最高频、零报错）

这类问题**不会报错、不会红用例，只有端到端探针能逮**。审查时逐条问「这条链路断了会怎样」，并要求给出探测手段。

| 失效形态        | 典型根因                                     | 最小探测                                   |
| ----------- | ---------------------------------------- | -------------------------------------- |
| 挂点 / 字段名不一致 | 声明、prefab 绑定、装配、坐标换算任一处留旧字段名             | 端到端探针断言目标非 null，禁止静默 `continue`        |
| 过场门闩吞首条回包   | 请求在途就置 pending，回包 navigate 被吞            | 过场流程用例末段                               |
| 图层不渲染       | `Sprite.spriteFrame = null` 是压根不渲染，不是透明图 | 检查帧赋值而非只检查透明度                          |
| 构建期才切图 / 糊图 | 图目录未登记，或 auto-atlas 容量未同步扩容              | 核 `auto-atlas.pac.meta` 像素账            |
| 整列数据为空      | 导出标志 / 类型声明行错位                           | 抽样核导出 json 列值                          |
| 数据驱动断言零执行   | 列索引 `-1` 未校验、查表未命中即 `continue`           | 目标数量守卫 + 变异测试（把断言改回 `continue`，护栏须立刻红） |
| 中间态跑不起来     | 跨文件改动先写调用点后写定义                           | `svn cat -r HEAD <file>` 核对新符号已入库      |

**表现口径专项**：口径变更必须同批换「视图分支 / 时长真源 / 装配 / prefab 绑定 / 测试 TARGETS」，链上任一处留旧名字即整条不播；改字段名要连**别的测试文件**的 TARGETS 一起换。用户在当轮明确给出的表现口径优先于历史注释与备用曲线；历史方案只留作标注「当前不接线」的备用档案。

## 5. 误报与争议处置

**AI / review 报「运算符、减号被截断换行导致编译报错」时，先按字节核，不要顺着改**：

1. 逐字节打印原行，确认运算符还在；
2. 跑 `tsc --noEmit` 过滤该文件，真有语法错不可能零错；
3. 跑该模块的既有判据（走过的就是那条式子），能绿即判误报。

根因常是源码被送进会把 `*` / `_` 当强调标记吃掉的 markdown 渲染通道。**review 时给纯文本或文件路径，不要把源码塞进聊天渲染通道**。

其他争议：规格、历史与当前需求冲突时说明差异，历史记录不作为必读规则；业务规格以本次需求与本地 `docs/` 为准，有文档先读文档，不把口径问题包装成「待确认」停在原地。

**审查报告里的机制解释同样要自证**：历史报告曾断言「隔离编译下未使用 value import 会保留成 require」，并拿测试夹具里的模块桩当证据；2026-11-05 按真实 `temp/tsconfig.cocos.json` 实测证伪（桩是永不走到的死分支）。凡要把某条机制解释升级为规范或护栏，先跑一次真实编译器 / 真实产物，别把结论直接抄进用例。

## 6. 意见与报告模板

**单条意见**：`等级 | 标题 / 文件:行 | 现象 | Why | 建议 | 判据（命令或文档锚点）`

示例：

> `P0 | 挂点缺失导致奖励不播 | ZCGameRenderWorld.ts:88 | 目标节点取不到时直接 continue | 上游字段名已改为 coinPanel，此处仍读旧名，整段表现静默跳过且无报错 | 对齐字段并补一条 target 非空断言 | 对应端到端探针用例 + 目标数量守卫`

**审查报告**：改动清单（白名单，标注他人 M 归属）→ G1 原始输出（含退出码）→ 三条判据结论 → 意见汇总（P0/P1/P2 计数与处置）→ 总体结论 → 未覆盖风险与后续。

交付简述须写清：修改文件、关键边界、**实际**运行的命令与结果、未覆盖风险。未运行不声称通过，无依据不承诺耗时或 token 降幅。

## 7. 元护栏：规范文档不能污染自动门禁

`tools/verify/verify.mjs` 的 `routeSources()` 会自动扫描根目录 `*.md` 与 `docs/**/*.md`，`parseRows()` 把**连续的以 `|` 开头的行**切成块，挑含 `tests/*.test.ts` 最多的块当路由表，并把解析结果合并进全局路由。因此：

> 本目录及 `docs/` 下新增的 md，**禁止出现「以 `|` 开头且含完整 `.test.ts` 路径」的表格行**；具体命令写在列表项或行内代码里（不以 `|` 开头即可）。否则该文件会被误当成路由表，静默放大 `verify check` 的选例范围。

新增规范文档后自检（仓库根执行，期望 `0`）：

- `node --input-type=module -e "import {parseRows} from './tools/verify/verify.mjs'; import fs from 'node:fs'; console.log(parseRows(fs.readFileSync('docs/agent/<新文件>.md','utf8').split(/\r?\n/)).length)"`

另一条：`tsconfig.json` 无 `include`、扫全工程，`tmp/` 下的 `.ts` / `.d.ts` 会被 tsc 收进去报上千条无关错误。临时产物落 `tmp/` 且扩展名改成 `.txt` 或 `.mjs`。

## 8. 度量与持续改进

只取 `verify` 已输出的量，不新建指标系统：

| 指标         | 来源                  | 目标          |
| ---------- | ------------------- | ----------- |
| 新增失败用例数    | 「新增失败用例」清单长度        | 0           |
| 新增 tsc 错误数 | 「新增 tsc 错误」清单长度     | 0           |
| 完全无覆盖改动文件数 | `verify route` 末段汇总 | 0，或逐个说明人工验证 |
| P0 复发数     | 报告里与历史同一根因的条目       | 下降；复发即补护栏用例 |

改进闭环：每个 P0 至少对应一条可执行的护栏（守卫用例或探针），规则回流到当日日志与 `MEMORY.md` 既有编号；一轮反馈给全；检查通过且无新改动不重复跑。
