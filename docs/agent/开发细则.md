# 开发细则

按本次涉及的条目读取。通用约束与需求边界见 [AGENTS.md](../../AGENTS.md)；分层、异步、渲染、Prefab 与工具链见[架构规范](../AI架构与代码规范.md)；MVC 职责见[MVC 设计规范](MVC设计规范.md)。本文只维护引用与类型、命名与风格、代码风格与交付，路径相对仓库根。

## 引用与类型

- Cocos Inspector 必填引用用 `null!`，真可空字段写 `| null` 并在边界处理。不用 `as any`、非空断言或静默 `?.` 掩盖绑定错误。
- 工程 `strict: false`（`strictNullChecks` 关闭）：组件、节点查询与查表不变量直接访问，不写 `!`，也不加只为消音的 `if (!x) return`。真可空值先判空窄化；`await` 之后属性窄化失效，先把字段取到局部变量。
- 单例访问点返回非空类型：`EventMgr.instance` / `CacheMgr.instance` / `PopupManager.inst` 构造不出来就在 getter 里 throw。调用点写 `Xxx.inst.doThing()`，不写 `inst?.` 或 `if (!mgr) return`。`?.` 只留给真可能为空的查询，例如 `PopupManager.inst.get(SomePanel)?.close()`。
- `@property` 绑死的 `Node` / `Sprite` / `Label` / 自定义组件直接取用，不写 `if (this.x)` / `this.x?.`。例外只有四种：字段注明可选或老端兼容、同一脚本被多个 prefab 复用但并非每个都绑、动态实例或第三方层级的查询缓存、入参本身允许 `null`。
- 「绑没绑」读对应 prefab 核对：找 `__type__` 等于脚本 cid 的对象，检查字段 `__id__` 是否指向真实对象。公共组件常在同一 prefab 挂多个实例，必须逐个核。
- **按使用阶段判断可空性**：字段由构造、`onInit`、`onLoad` 或装配入口必定赋值，且所有合法使用路径均在赋值之后、清空之前时，直接使用，不再写 `if (value)`、`if (!value) return`、`?.` 或默认值兜底。声明时暂为 `null` 不代表使用阶段可空；生命周期必赋值的引用用具体类型与 `null!` 声明，不用 `| null` 制造假可空，也不用访问点非空断言掩盖时序问题。例如 `CardUpgradePage.upgradeLabelColor` 在 `onInit` 保存，`setUpgradeEnabled` 直接选取并赋色。
- **删除守卫先证明时序**：核对全部赋值、调用、清空及缓存重开路径；方法名叫 `render` 或 `onXxx`、测试手动先初始化，都不能证明生产调用顺序。初始化可能跳过或失败后继续、字段允许缺省、首次渲染早于赋值、销毁清空后仍可进入、懒加载未完成时，须保留真实边界处理或修正初始化契约。跨 `await` / Promise 的失效与取消仍遵守架构规范 §3.2，初始化保证不能代替宿主有效性检查。
- **函数签名使用具名契约**：参数、返回值及跨模块契约优先直接引用已有的领域类型、展示类型或资源契约，不通过外层对象的多层索引路径表达已具名的数据。例如 `card: CardUpgradePresentation['data']['card']` 实际是 `ZCDeckCard | null`，应以 `import type` 引入 `ZCDeckCard` 并显式写出 `card: ZCDeckCard | null`；签名由参数的含义决定，不依赖它恰好放在某个 Presentation 的哪一层。引用必须符合依赖方向，不为缩短类型路径新增越层依赖。
- **复用类型，不制造别名壳**：已有类型直接复用，不复制字段、不新增仅包装 `Outer['data']['item']` 的别名。确有独立语义且被多处使用的匿名结构，才在原契约所属模块提取具名类型，并让原字段与使用方共同引用；不为了所有签名一律具名而增加类型文件、重导出层或单次使用的接口。替换时保留原有 `null` / `undefined`、可选性、只读性、联合与泛型约束；不要借机重命名存量类型或改变运行时传值。
- **索引访问类型有适用场景**：泛型键值关联（如 `T[K]`）、映射类型、元组/数组元素提取，以及必须随源契约变化且没有合适具名类型的类型推导，可以保留。单层 `Contract['field']` 也需核实是否已有应直接复用的具名类型；扫描只标记候选，不按方括号数量机械替换，也不一律改写 `Pick`、`ReturnType`、`Parameters` 等类型工具。
- 判据：`grep -rn "[A-Za-z0-9_)]!\." assets/script --include=*.ts` 与 `.inst?.` / `instance?.` 应为 0 命中（讲解规则的注释除外）。存量按模块清，每清一个文件先对完它的 prefab 实例，再补护栏；不要一把梭。

### 全工程扫描提示词

以下提示词统一扫描生命周期冗余防护与函数签名中的类型表达；执行结果必须区分实际检查范围与未覆盖范围。

```text
请扫描本工程 assets/script 下的全部自有 TypeScript 源码，清理生命周期与初始化契约已保证的冗余防护，并规范函数签名与类型引用，不增加业务功能、不改变运行时传值和协议。

1. 先检查工作区并保留已有改动，读取 AGENTS.md、docs/agent/开发细则.md「引用与类型」及 docs/AI架构与代码规范.md §2.1.1、§3.2；涉及 prefab、caller 或其他模块时再按入口加载对应规范。存在 .codegraph/ 时先用 CodeGraph 定位调用链，不自行建索引。
2. 按模块枚举两类候选：一是 if (value)、if (!value) return、&& 短路、可选链、?? / || 兜底、假可空字段、重复初始化门闩、关闭时额外递增的异步版本号；二是参数、返回值和导出契约中的多层索引类型（如 Presentation['data']['card']）、绕过已有具名类型的单层索引、重复匿名结构及只包装类型路径的别名。搜索结果只是候选，不能作为修改依据；不要修改第三方或生成代码。
3. 逐项追踪真实生产路径：字段何时创建和赋值，所有调用者是否可能提前进入，何时清空，初始化异常后是否继续，关闭、销毁、缓存重开和异步返回时是否仍成立。Inspector 引用需核对对应 prefab / scene 的全部实例。记录文件、符号及关键调用位置作为证据。
4. 类型候选逐项追溯到原始声明，核对字段实际含义、现有命名类型、所属层与全部使用方。优先 import type 复用已有类型；例如确认 card 的原始声明为 ZCDeckCard | null 后，将参数写为该类型。仅在存在独立复用语义时提取匿名契约，并同步原字段、调用方与导出；不得新增别名壳、复制字段、扩大参数范围或制造循环/越层依赖。保留真实泛型关联和必要类型推导。
5. 将候选分成「可修改」「必须保留」「证据不足」，分别记录生命周期或类型契约证据。不能因通常不为空或类型声称非空就删除检查；不能用新增默认值、as any、访问点非空断言或另一个守卫替代原检查。保留外部输入校验、业务条件、真实可选项、错误处理，以及必要的异步取消、节点有效性、作用域和防乱序保护；版本号在同次打开内的防覆盖用途须独立核实。
6. 只修改已证实的项，同步纠正假可空声明和受影响的调用、类型导入、导出、测试夹具；保持 null / undefined、可选性、只读性、联合和泛型约束。生命周期绑定错误应在初始化边界暴露，不在每次渲染时静默跳过。不要顺手格式化、重构、重命名存量类型、增加包装工具或批量正则替换。
7. 每模块完成后运行相关最小验证集；类型改动需核对类型检查结果，有生命周期、取消或复用风险时补必要回归。测试真实实现，不复制算法，也不让夹具绕过正式初始化。公共契约或跨模块变更再扩展验证；区分既有失败与本次新增失败。最后运行 npm run verify:hygiene 和 npm run verify:layout。
8. 在 docs/reports/生命周期与类型契约扫描-YYYY-MM-DD.md 记录实际扫描的模块与文件数量、每项分类及理由、修改位置、验证命令与结果、证据不足项和未覆盖范围。类型问题附原始声明与替换依据，生命周期问题附初始化和调用顺序。未逐项核对或未运行验证的部分不能标为完成；交付时概述改动及剩余风险。
```

## 命名与风格

- 文件与类：`PascalCase`，文件名与导出类名同名；一个文件一个清晰职责，禁止 `Utils.ts` / `Common.ts` / `Manager.ts` 收容箱。
- 接口与类型：`PascalCase` 且 `I` 在最前（`IMailRepository`、`IZCSnapshot`，不是 `ZCISnapshot`）；枚举成员 `PascalCase`；常量 `UPPER_SNAKE_CASE`。
- 常量与枚举替代：推荐使用 `const X = { ... } as const` 配套 `type X = typeof X[keyof typeof X]` 导出联合类型，杜绝传统 TypeScript enum 转译后的双向映射闭包开销。视觉颜色统一定义在 `Theme.ts`，使用 `Object.freeze(new Color(...))` 预实例化，禁止在渲染分支内联重复 `new Color(...)`。
- 变量与函数：`camelCase`；布尔值以 `is` / `has` / `can` 开头；私有属性 `private` + `camelCase`，不用 `m_` 前缀。函数名体现动作（`load…`、`build…`、`present…`、`handle…`），不用 `doIt`、`data`、`temp`。
- 对局玩法 `zcds` 内的类以 `ZC` 开头；全仓不用拼音。
- TypeScript：4 空格缩进、单引号、显式分号；纯类型依赖用 `import type`；接口与入参优先 `readonly`（需要在内部替换数组引用的除外）；用 `unknown` 替代 `any`。

## 代码风格与交付

- 注释遵循「三不写、三必写」：
  - 三不写：不复述代码字面行为（如 `// 设置位置`）；不在生产代码中堆砌变更日志、需求口径或用户对话历史（迁至 Git 日志或规范文档）；不保留大段废弃注释代码（由版本控制追溯）。
  - 三必写：必写业务决策原因与「Why」（非直觉设计）；必写引擎与平台时序陷阱（如 Sprite Trim 影响渲染尺寸、updateRenderData 强刷时序）；必写数学几何不变式与临时分支删除条件。
- Lambda 与闭包治理：
  - 热路径零分配：`update(dt)`、`step(dt)` 与对局帧循环中严禁使用内联 Lambda / `filter` / `map`，使用原生循环与预分配结构以规避 Minor GC 掉帧。
  - 监听绑定必须带宿主：事件与网络订阅必须传递具体方法引用与宿主 `this`（如 `addEvent('Msg', this, this.onMsg)`），页面销毁时统一调用 `offTarget(this)` / `removeCaller(this)`，严禁传递无法精确解绑的匿名箭头函数。
  - 异步闭包安全：长生命周期异步操作（Promise / scheduleOnce）中，闭包尽量仅捕获基础类型 ID；`await` 之后必须进行宿主有效性与竞态校验（`if (!this.isValid) return;`）。
- 禁止冗余别名赋值：`const x = y;` 中右侧只是现成标识符或属性访问、无转换，且 `x` 只用一次时，直接内联。右侧是函数调用或计算结果、声明与使用之间有 `await`、变量被闭包捕获、先保存再清空字段、名字承担时序语义、循环或多次复用时保留局部变量。
- 玩家可见文案和魔法数移到常量或文本表。
- 函数体换行：新增或修改的具名函数、方法、构造函数、getter/setter 及块体回调，非空函数体从下一行开始，不得把首句拼到签名后；简单表达式箭头函数（`x => x.id`）可保持单行，未触及的历史单行函数不强制批量展开。门禁 `npm run verify:layout`（A 类阻断、B 类仅报告）。
- 有规则、边界、取消、资源或回归风险的改动，新增或更新测试，并运行与改动相关的最小用例集。完成时说明改了什么、关键边界、实际运行的命令与结果、未验证的风险；未运行不写「通过」。
