### Chrome DevTools MCP 配置与范围

- 配置位置：当前用户的 `~/.codex/config.toml`，服务名 `chrome-devtools`，跨项目可用；没有覆盖原有 CodeGraph、Cocos、蓝湖等配置。
- 使用 Codex 官方 `mcp add` 注册，以 Windows `cmd.exe /d /c` 启动 `npx --yes --ignore-scripts chrome-devtools-mcp@1.12.0`。使用精确版本，不随 `latest` 自动升级。
- 参数：`--headless --isolated --memory-debugging --no-usage-statistics --no-performance-crux`，并设置 `CHROME_DEVTOOLS_MCP_NO_USAGE_STATISTICS=1`。独立临时 Chrome 配置不复用个人浏览器会话；关闭工具统计及向 CrUX 发送性能页 URL。
- npm 缓存中准备了该工具；没有修改本工程 `package.json` 或锁文件。环境 Node.js `24.16.0` 满足包要求，检测到本机 Chrome。
- 本次采用官方支持的 MCP 接入方式，没有安装上游面向 Claude 的整套技能插件，也没有复制 CLI 技能。重新打开 Codex 后加载新服务；若当前运行时未刷新，当前对话不能直接调用新工具。
- Chrome DevTools 负责浏览器运行时证据。Cocos Scene/Prefab、Inspector 绑定、节点归属与资源刷新仍由现有 Cocos MCP 处理。普通网页操作继续使用现有浏览器工具。
- Headless Web 预览指标不等于真机或原生包性能；确认性能结论还需实际场景、目标设备和现有 Cocos 性能数据。

## 实际验证与剩余边界

- `npx --yes --ignore-scripts chrome-devtools-mcp@1.12.0 --version` 返回 `1.12.0`，`--help` 确认所用参数存在。
- 对已保存配置启动实际 MCP：`initialize` 返回 `chrome_devtools 1.12.0`；`tools/list` 返回 45 个工具，包含性能 trace、控制台、网络以及堆快照和保留路径分析。
- 调用 `list_pages` 成功启动独立 headless Chrome，返回初始 `about:blank` 页；验证结束已关闭检查进程。
- Context7 实际完成一次 Cocos 库解析和一次指定 `3.8` 版本的文档查询，连接和文档返回已验证。
- 原版技能及许可证按固定提交核对；新增模块设计和五维审查技能为明确标注的项目适配版，不再声称与上游逐字一致。
- 新增两项技能使用 `skill-creator/scripts/quick_validate.py` 验证元信息，检查全部本地引用、来源标记和文档状态。此类静态验证不等于真实任务行为评测；未进行独立模型对照实验。
- 本轮属于技能、工具与文档接入，没有修改游戏源码、资源、业务配置、测试路由或依赖；没有运行游戏单测，也未测实际游戏场景的 FPS、内存泄漏或端到端流程。
- 未提交 Git/SVN，未新增 CI、Git hook、多代理默认流程，也未替换既有门禁。
