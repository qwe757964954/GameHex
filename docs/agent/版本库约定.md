# 版本库约定

仅提交或操作版本库时读取。工作区保护与交付要求见[工程入口](../../AGENTS.md)。

## 版本库（SVN 与 Git 并存）

- SVN 工作副本根：`D:\City1001`；当前项目地址：`https://192.168.2.250:8440/svn/City1001/trunk/Demo3.8`。Git 仓库：`D:\City1001\Demo3.8\.git`，远端为 GitHub。
- SVN 提交日志必须纯中文，禁止英文或中英混排。同一变更提交到两库时，Git 使用相同中文日志。
- SVN 提交仅使用 TortoiseProc 图形通道，禁止命令行 `svn commit`。当前 `svn.exe` 的内联日志、UTF-8 日志文件及宽字符参数均已实测乱码；服务器未开放 `pre-revprop-change`，无法事后修改提交日志。
- **增量改动暂存与零扫描提交（核心约定）**：
  1. **实时暂存**：开发过程中，AI 修改或新建任何文件后，必须同步执行 `node tools/dev/svn-stage.mjs add <file...>`（或记录至 `tmp/svn-staged.txt`）。若涉及 `assets/` 资源与代码，自动伴生纳入 `.meta` 文件。
  2. **严禁发散审计（全盘扫描阻断红线）**：工作区中未在暂存单里的文件属于“保留/进行中”状态。**严禁自主对未暂存文件逐一执行 `svn diff`、全文代码检索、追溯历史或跑无关测试**！
  3. **提交方式（唯二允许的极速动作，严禁事前逐个 diff 分析代码）**：
     - **模式 A（默认·仅提暂存）**：直接以 `tmp/svn-staged.txt` 为准校验门禁并调起 TortoiseProc 提交弹窗（日志已预填，提交按钮必须由用户手动点击，AI 不代点）：
       ```powershell
       node tools/dev/svn-stage.mjs commit -m "纯中文日志"
       ```
     - **模式 B（全量变动对齐）**：若用户要求提交当前全部改动或暂存单未更新，**直接运行 `commit --all`**（脚本耗时 < 0.2 秒自动收集路径并唤起弹窗，由用户在 GUI 窗口勾选确认）：
       ```powershell
       node tools/dev/svn-stage.mjs commit --all -m "纯中文日志"
       ```
     参数传输规则：路径总长安全时优先直传 `/path:file1*file2` 避开文件解析；长列表使用无 BOM 的 UTF-16LE `/pathfile`（TortoiseProc 官方规定严禁带 BOM，否则 BOM 会被作为路径首字符导致断言崩溃）。
  4. **确认与清空**：启动后明确说明「窗口已弹出，请点确认」；未核实结果前不宣称 SVN 提交成功。用户确认提交后，运行 `node tools/dev/svn-stage.mjs clear` 清空暂存单。

- 新增本地工具目录时，同步维护 `.gitignore` 与 `Demo3.8` 目录的 `svn:ignore` 属性。根目录忽略项包括：`.superpowers`、`.codegraph`、`.codex-artifacts`、`.codex-tmp`、`.creative-design`、`.skill_tmp`、`.trae`、`.workbuddy`、`.tmpwork`、`data/outputs`、`*.log`。`logs/` 本身纳入版本控制，其 `archive`、`2026-*`、`*.log` 由 `logs` 目录的 `svn:ignore` 忽略。
