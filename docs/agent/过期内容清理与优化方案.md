## 2. 判定模型（四类共用）

### 2.1 什么叫"过期"

"过期"不等于"旧"。满足以下任一条件才算：

| 代号 | 条件 | 说明 |
| --- | --- | --- |
| E1 | **对象失效**：被引用的源码/资源/测试/入口已不存在 | 文档死链、测试死引用 |
| E2 | **已被替代**：存在明确继任者，且继任者覆盖其职责 | 旧方案被新规范替代 |
| E3 | **一次性且已吸收**：过程产物，结论已进入报告/文档/提交 | 日志、审计中间件 |
| E4 | **超期且可再生/无证据价值**：超出保留期，删除后可由命令重建 | 缓存、脚手架 |

只有 E4 可以只凭时间判定；E1–E3 必须有可复核的证据链。

### 2.2 结论等级

| 等级 | 含义 | 允许动作 |
| --- | --- | --- |
| **K（Keep）** | 现行有效/唯一证据/活路径 | 不动 |
| **A（Archive）** | 不再现行，但有追溯价值 | 移动到 `docs/history/` 或 `outputs/` 归档，保留链接 |
| **D（Delete）** | 失效且可再生/无价值 | 删除，记录台账 |
| **U（Unconfirmed）** | 证据不足或归属不明 | 挂起，指定 owner 后再判 |

### 2.3 证据等级

| 等级 | 证据 | 示例 |
| --- | --- | --- |
| R1 | 机器可验证 | 文件不存在、`verify route` 命中 0、路径不在 `package.json` |
| R2 | 交叉引用可验证 | 文档引用→文件缺失；路由表→测试缺失；README 计数≠实测 |
| R3 | 需人工确认 | "这份报告还有没有人看""这个备份还要不要回滚" |

**规则**：D 级至少需要 1 条 R1 或 2 条 R2；只有 R3 时一律 U。

### 2.4 三条硬规则

1. **时间只作触发器**：>30 天只代表"进入候选"，不代表"可删"。
2. **删除必须有 owner**：D 级和 A 级都要有人签字；无 owner 转 U。
3. **可再生产物优先于人工产物**：能靠命令重建的（缓存、构建产物、日志）先清；人工写的文档、测试后清。

### 2.5 判定矩阵

| 类别 | 主判据 | 辅助判据 | 可用阈值 | 反例（不能据此删除） |
| --- | --- | --- | --- | --- |
| 文档 | E1/E2/E3 | 是否被 `AGENTS.md`、路由表、README 引用；是否有明确继任者 | 阶段方案完成 >30 天；时点报告 >90 天 | "旧"、"文件名带 2026"、"没人打开过" |
| 测试 | E1/E2 | 被测源码是否存在；是否有路由/import/字面量可达；是否重复覆盖 | 源码删除后 7 天内未同步 | "失败"、"跑得慢"、"重名"、"文件大" |
| 日志 | E3/E4 | 是否仍被写入；结论是否已落文档；是否被 docs/outputs 引用 | 即时日志 0–7 天；任务证据 30 天；发布审计 180 天 | "体积大"、"看起来没用" |
| 临时文件 | E4 | 是否可再生；是否是活路径；是否 junction/外部依赖 | 脚手架 14 天；备份 14 天；缓存按需 | "在 tmp 下"（tmp 里也有白名单活文件） |

## 3. 分类策略

### 3.1 过期文档

#### 3.1.1 文档分型与生命周期

| 类型 | 识别特征 | 生命周期 | 归档位置 |
| --- | --- | --- | --- |
| 常青规范 | `docs/agent/*`、`docs/AI架构与代码规范.md`、`zcds-*`、`bigmap-*` | 长期有效，季度复核 | 不归档 |
| 阶段方案 | 标题含"方案/迁移/切分/实施计划"，带日期 | 任务完成 + 30 天 | `docs/history/YYYY/` |
| 时点报告 | 标题含"报告/梳理/清单/盘点"，带日期 | 90 天 | `docs/history/YYYY/` |
| 历史存档 | 已在 `docs/history/`，首段声明"历史参考" | 永久 | 不删，只维护索引 |
| 一次性工作稿 | 仓库根目录的 `.md/.csv`，未入库或临时入库 | 结论合并后 14 天 | 合并进规范或删除 |

#### 3.1.2 判定步骤

1. **查引用**：是否被 `AGENTS.md`、`docs/agent/规范路由与最小验证.md`、README、其他文档引用。
2. **查继任者**：同主题是否有更新的文档，且新文档已覆盖旧文档职责。
3. **查死链**：文档中引用的 `assets/`、`tests/`、`tools/` 路径是否仍存在（只认带目录前缀 + 扩展名的完整路径）。
4. **查路由**：该文档是否含 `tests/*.test.ts` 表格。若是，它已是机器路由真源，**任何移动/删除必须先迁移路由行**。
5. **定级**：K/A/D/U，写入台账。

### 3.2 过期测试

#### 3.2.1 判定标准

| 代号 | 判据 | 取证方式 | 结论 |
| --- | --- | --- | --- |
| T1 | 被测源码/资源已删除或改名，测试未同步 | 测试内 `readSource()`/`readFileSync()`/`existsSync()` 路径检查 + 人工读断言 | D（删除）或修复 |
| T2 | 被测功能已下线，路由行、源码、资源三处均无 | `verify route` 无命中 + 源码搜索 0 命中 | D |
| T3 | 重复覆盖：新测试的断言集严格包含旧测试，且旧测试无独有断言 | 逐条比对断言与夹具 | 合并后删旧 |

| T6 | 结构债（巨型文件、单源被围猎） | 行数/用例数/覆盖同一源码的文件数 | 拆分，不删 |

**明确禁止的删除理由**：文件老、跑得慢、当前失败、标题重名、体积大、覆盖率数字不好看。

| 场景 | 动作 | 验证 |
| --- | --- | --- |
| 源码删除 | 同一个提交内删除/改写对应测试与路由行 | `verify route` 命中 >0；`verify check` 零新增 |
| 重复覆盖 | 先补旧测试独有断言到新测试，再删旧文件 | 新旧单跑对比；`verify full` 用例数变化可解释 |
| 永久红 | 先单跑复核；真红则修或登记"已接受"并写理由 | `verify reds` 重算；`baseline-accept.log` 有记录 |
| 无入口 Python 测试 | 补 `package.json` script，或在 README 标注 `manual` 并写命令 | 手动跑一次通过 |
| 巨型文件 | 按语义块拆 3–4 个文件，不改断言 | 拆分前后单跑结果一致 |
| 环境耦合（如 `hang.test.ts` 读 `../client`） | 增加前置存在性检查并显式 skip，或在 README 标注"需同级 client 仓库" | 在无 `client` 的副本上不硬崩 |

#### 3.2.4 删除流程（单个测试文件）

1. 找被测对象：源码/资源/协议/配置是否仍存在。
2. 读断言：区分"正向断言"和"负向守卫"；负向守卫不得按文件缺失删除。
3. 单跑：`npx tsx --test tests/<file>.test.ts`，记录结果。
4. 查路由：`node tools/verify/verify.mjs route`，确认删除后无其它行依赖它。
5. 删除并同步路由/README/import 路径。
6. `npm run verify`（相对基线零新增）→ `npm run verify:full`（用例数变化可解释）。
7. 一个域一个提交，中文日志，说明"删除原因 + 替代覆盖"。

## 5. 执行步骤与顺序

> 顺序原则：**先只读盘点 → 再可逆/本地 → 再版本库跟踪内容 → 最后重型缓存**。每阶段结束即验证，不等到最后。

### Phase 0：冻结与快照（只读）

```powershell
$root = 'D:\City1001\Demo3.8'

New-Item -ItemType Directory -Force -Path $audit | Out-Null
# 体积/文件数基线
Get-ChildItem -LiteralPath $root -Force -Directory | ForEach-Object {
  $m = Get-ChildItem -LiteralPath $_.FullName -Recurse -Force -File -ErrorAction SilentlyContinue |
       Measure-Object Length -Sum
  [pscustomobject]@{ Name=$_.Name; MB=[math]::Round($m.Sum/1MB,1); Files=$m.Count }
} | Export-Csv -LiteralPath (Join-Path $audit 'size-before.csv') -NoTypeInformation -Encoding utf8BOM
# 版本库状态
git -C $root status --short | Set-Content -LiteralPath (Join-Path $audit 'git-status-before.txt') -Encoding utf8BOM
```

### 7.5 文档生命周期

1. 新建：标题带日期（报告/方案），首段写"状态/适用范围/依据"。
2. 生效：被 `AGENTS.md`、路由表或 README 引用即视为生效。
3. 替代：新文档首段写"替代 `<旧文档>`"；旧文档加"已被替代"。
4. 归档：完成 +30 天 / 报告 +90 天；移动到 `docs/history/YYYY/`。
5. 删除：仅限"无引用、无历史价值、owner 确认"的一次性工作稿。
6. **非路由文档禁止在表格单元里写 `tests/*.test.ts` 完整路径**：`verify.mjs` 会自动扫描 `docs/**/*.md` 与根目录 `*.md`，任何含该模式且带 `assets/`、`tools/`、`docs/` 键的表格都会被当成路由真源。需要提测试文件时写 `xxx.test.ts`（省略 `tests/` 前缀），或放在非表格段落。本方案编制时曾因此被误解析为 3 行路由，已修正。

### 7.6 测试生命周期

1. 源码删除的同一个提交，必须同步删/改测试与路由行；不允许"先删源码，测试以后再说"。
2. 新增测试必须满足至少一条可达性：进路由表、被 import 反向可达、路径字面量引用。
3. 同名用例必须带域前缀；改名与基线重算同批。
4. 基线红必须有 owner；两周未认领升级到负责人。
5. 每季度重算一次基线，`VERIFY_BASELINE_ACCEPT=1` 必须留 `baseline-accept.log`。

### 7.7 日志规范

1. 任何脚本/命令不得把日志写到仓库根；统一 `tmp/<task>-<YYYYMMDD>/`。
2. 单文件 >5 MB 轮转，保留最近 2 份。
3. 发布/热更日志写 `outputs/hotupdate-logs/<type>-<YYYYMMDD-HHMMSS>.log`。
4. 日志中出现的结论，必须同步进报告或提交说明；日志只是证据，不是结论载体。

### 7.8 临时文件规范

1. 任务开始建 `tmp/<task>-<YYYYMMDD>/`，任务结束在台账登记"保留/删除"。
2. 备份目录必须带日期与主题，14 天内清理；不得用 `_bak`、`_bak2` 这类无信息名字。
3. 禁止在 `assets/`、`docs/` 下创建临时文件；`docs/.tmp-*` 发现即清。
4. 不在 `tmp/` 里放 `node_modules` 以外的依赖副本；链接必须登记在白名单。
5. 禁止 `git clean -fdx`；禁止删除 `library/temp/build` 时编辑器在跑。

## 8. 风险与回滚

| 风险 | 触发 | 预防 | 回滚 |

```powershell
Get-ChildItem -LiteralPath (Join-Path $root 'docs') -Recurse -File -Filter *.md |
  ForEach-Object {
    $doc = $_; $txt = Get-Content -LiteralPath $doc.FullName -Raw -Encoding utf8
    foreach ($m in [regex]::Matches($txt, '`([^`]+\.(ts|py|md|json|prefab|png))`')) {
      $p = $m.Groups[1].Value
      if ($p -notmatch '[*?<>| ]' -and $p -match '/' -and
          -not (Test-Path -LiteralPath (Join-Path $root $p))) {
        "{0} -> {1}" -f $doc.FullName.Replace($root + '\',''), $p
      }
    }
  }
```

## 附录 C：术语

| 术语 | 含义 |
| --- | --- |
| 可再生 | 通过命令/导入/构建可重建，删除不造成信息损失 |
| 活路径 | 被当前代码、脚本、文档实际使用，删除会破坏功能或发布 |
| 白名单 | 明确禁止清理的对象清单，随目录变更维护 |
| 路由真源 | `verify.mjs` 读取的含 `tests/*.test.ts` 表格的文档 |
| 负向守卫 | 断言"某文件必须不存在"的测试，用于防止死代码复活 |
| U 级 | 证据不足/归属不明的挂起状态，不是"默认删除" |
