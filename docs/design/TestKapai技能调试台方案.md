# TestKapai 技能调试台方案

> 状态：待评审方案（2026-11-20）。本文只写这次要推动的决定、范围与验收；落地前不代表当前实现。

## 一、结论先说

现在 TestKapai 的问题不是「倍率算错了」，而是**它验证的是"一个模型 + 一个特效 + 一条公式"**，而战斗里真正决定观感和数值的是「同一相机下的参照物、真实战斗链路、可改的参数、可下钻的伤害」。

建议把 TestKapai 从「卡牌 / 技能验证台」升级成**技能调试台（Skill Sandbox）**，四个工作区一次到位：

1. **沙盘**：真实六边格 + 真实相机 + 可布置的靶子，模型 / 特效 / 弹体 / 范围圈同尺度可比；
2. **释放**：驱动真实战斗循环（真实 tick、真实命中、真实飘字），而不是点一下播一次特效；
3. **调参**：运行时覆盖关键字段，改完立刻重放，可一键还原、可导出补丁；
4. **读数**：每次命中都能拆出 6 个乘数，汇总出单次伤害 / DPS / TTK。

一句话验收：**任意技能，30 秒内走完「选卡 → 布靶 → 释放 → 看明细 → 改一个参数 → 再释放」，全程不重开场景、不改表、不重新编译。**

## 二、现状：三处「同源」为什么还是看不出实战效果

| 现状 | 证据 | 为什么不够 |
| --- | --- | --- |
| 尺寸确实同源：`69.4 / 骨架 canvas 高 × prefabSize × battleScale`，特效 `zcEffectNodeScaleOf × battleScale` | `ui/ZCTestKapaiStage.ts` | 比例没错，但**只有一个模型、没有参照物**。battleScale 4.2 是"整体放大到看得清"，屏幕上看到的不是战场尺寸；没有敌兵、弹体、范围圈、血条做对比，"这个大不大"根本判断不了 |
| 舞台画了 36×42 的战斗格 | 同上 | 格子和模型都在同一套倍率里，**只能证明两者比例对**，不能证明"和实机战场上看到的一样"。相机的适配模式、画布缩放一旦和战场不同，px 值同源也会观感不同（待核实） |
| 伤害用真实公式 `ZCCombatSystem.unitDamage` 复算 | `model/ZCTestKapaiModel.ts` | 但代进去的是 `counterMultiplier = 1`、`neutralBonuses()`（攻击/生命/移速全 1）、品级取卡牌稀有度。**克制、羁绊、阵容、暴击、溅射递减、守方减伤全部没有**，看到的是一条"无 buff 单体"伤害 |
| 技能行按 `damageRate` 与冷却展示 | 同上 | 展示的是**单次**伤害；实战里同一条技能可能打 3 个目标、5 波、命中递减、触发连锁。现在没有"命中几个 / 总共多少" |
| 点按钮播一次 `effectPrefabPath` | `ui/TestKapaiView.ts` `playSkillEffect` | 只有"播特效"这一步。没有出手 → 飞行 → 命中 → 伤害 → 状态（减速/眩晕/护盾/召唤）→ 波次/连击的链路，也没有命中点与范围的可视化 |
| 参数只能改表再重来 | `config/testkapai.json` 只存布局 | 调一个 `damageRate` 要改配表、重编译运行时配置、重开预览。**这正是"调试技能"最贵的一步** |
| 技能已有 17+ 条车道（扇形、爆发、连锁、冲锋、风弹、弹幕、召唤…） | `docs/design/技能全量研发档案_20261116.md` | 验证台只当成"一行一个按钮"，车道差异（打几个、打多远、命中顺序）全部看不出来 |

**判断**：尺寸要解决的不是倍率，是**参照系**；释放要解决的不是播放，是**链路**；数值要解决的不是公式，是**上下文**和**可调性**。

## 三、产品目标与验收口径

目标用户：策划（判断数值与手感）、研发（核对配置与表现）、美术（核对模型 / 特效与格子关系）。

三条硬验收，先立在这里，后面所有设计都围着它：

1. **可判尺寸**：任一模型 / 特效 / 弹体，能在同一屏里和「六边格 + 敌兵 + 范围圈」比对，并直接标注「px / 格数」。切换 1:1 与放大视图，**相对比例误差 < 1%**。
2. **可判数值**：任一伤害数字能下钻到乘数明细；把 `damageRate` 从 1 改成 2，单次伤害必须正好 ×2（同品级、同克制、同阵容）。
3. **可改可还原**：覆盖过的字段一律高亮，退出即还原；不把调试值写回真源。

## 四、方案

### 4.1 沙盘：先给尺寸一个参照系

- **同一相机**：沙盘直接采用战场的坐标映射与相机参数（而不是另建一套 UI 布局），并提供视图切换：
  - `1:1 实机`：按战场 px 显示，用来判断"手机上到底多大"；
  - `放大 N 倍`：整体同乘，只用于看清细节；
  - **两者共用同一个倍率乘子**，禁止分别调模型和特效。
- **参照物固定三件**：六边格（36×42）、一只标准敌兵、一格范围圈。任何模型进沙盘都自动落在这三件旁边。
- **标注直接写数字**：模型高 = `69.4 × prefabSize` → 换算为 `1.65 格`（69.4/42）；特效取 prefab 包围盒宽高 → 换算格数；弹体按 `zcEffectNodeScaleOf` → 格数。这一行就是美术和策划对话的语言。
- **对照模式（P1）**：同屏并排 3 个兵种，全部按 `prefabSize` 归一显示，用来回答"这一批兵谁偏大 / 谁偏小"。
- **布靶**：靶子可调数量（1 / 3 / 5）、站位（近 / 中 / 远）、血量、阵营与职业（用来触发克制）。默认给一组"前排近战 + 后排远程"，避免永远只测单体。

### 4.2 释放：跑真实战斗，而不是播特效

- 复用真实战斗子系统（`ZCCombatSystem` / `ZCAttackResolutionSystem` 的事件与结算），**不新写一套模拟器**；沙盘只负责装配一个"无网络、无存档、无匹配"的最小战斗会话。
- 时间控制：暂停 / 单步（1 tick）/ 0.5× / 1× / 2×，固定随机种子（暴击可复现）。
- 一次释放要能看到：**出手点 → 飞行轨迹 → 命中点 → 命中人数 → 每个目标的伤害飘字（暴击 / 克制 / 抵抗前缀沿用真实飘字口径）→ 状态挂载 → 死亡**。
- 范围可视化：`areaRadius` / `splashRadius` / 扇形角度 / 冲锋路径 / 连锁跳数，直接画在六边格上，和格子同尺度。
- 事件时间轴（P1）：按时间列出"第 0.2s 出手、0.4s 命中 3 人、0.6s 减速"，可回放某一段。

### 4.3 调参：这一版真正的核心

分两层，界面上必须一眼分得清：

- **只读层（真源）**：来自编译后的 `IZCRuntimeCatalogs`（pvpCard / pvpSkill / pvpGlobal），灰字显示，不可改；
- **覆盖层（临时）**：黄字 + 黄框，仅本次会话有效，可一键"还原全部"。

P0 开放的白名单（不够再加，不一次铺满）：

| 组 | 字段 | 用来回答 |
| --- | --- | --- |
| 单位 | `unitAttack` / `unitMaxHp` / `unitAttackInterval` / `unitAttackRange` / `prefabSize` | 打得疼不疼、活得久不久、够不够得着、模型大不大 |
| 技能 | `damageRate` / `cooldown` / `empoweredEvery` / `areaRadius` / `splashRadius` / `waves` / `projectileSpeed` / `slowRatio` | 倍率、节奏、范围、波数、弹速、减速 |
| 全局 | `combatDamageMultiplier` / `unitAttackPerTier` | 整体缩放与品级曲线（只读优先，慎改） |

每个字段固定显示三列：`配置值 / 覆盖值 / 生效值`；改完立刻重算并允许立即释放，**不重新加载场景**。

导出：把改过的字段导成一份补丁 JSON（列名 + 旧值 + 新值），可直接贴进配表流程（P1 再接表工具）。覆盖值永远不写回真源——这是防止"调试台调绿了、线上还是红"的唯一闸门。

### 4.4 读数：把一次释放讲清楚

- **单次释放卡**：命中目标数、每个目标一条明细（`基础攻击 × 品级 × 阵容 × 克制 × 全局 × 技能倍率 × 暴击 × 溅射递减 × 守方减伤`），最后给"实际扣血 / 溢伤"。
- **汇总**：单次总伤害、理论 DPS（按 `attackInterval` 与技能节拍算）、击杀时间 TTK（当前靶子血量下）、平均命中人数。
- 和现在的差别：现在给的是"这条技能打一下多少"，这里给的是"这条技能在什么阵容、什么克制关系下，打几个、多久打死"。

### 4.5 诊断：把配置错误前置

- **资源核对表**：模型 prefab、特效 prefab、弹体、骨架动画名（idle / move / attack）逐项检查存在性与缩放，缺项红标，不阻断其它卡。
- **车道契约核对**：按技能所属车道检查必需参数是否配齐（扇形要有角度与人数上限、冲锋要有距离、弹幕要有发数与间隔…）。现在的"半径 / 波数 / 减速"摘要只能说明"配了什么"，说明不了"配全了没有"。
- **一屏信息架构**（沿用现在的纵向排版，只换内容顺序）：
  `诊断条 → 选卡 → 沙盘（占最大高度）→ 释放控制条 → 技能参数区 → 结果 / 日志`

## 五、范围与分期

| 阶段 | 内容 | 价值 |
| --- | --- | --- |
| **P0** | 真实相机 + 三件参照物 + 尺寸标注；单靶 + 3 个我方单位；暂停 / 单步 / 1× / 2×；覆盖面板（上表白名单）；单次伤害明细 | 直接解决"看不出实际大小 / 释放不像实战 / 改参数太贵" |
| **P1** | 多靶布阵与克制选择；事件时间轴与回放；导出补丁；兵种对照模式；DPS / TTK 汇总 | 从"能看"到"能比较、能提交" |
| **P2** | 批量回归（按技能档案逐条跑并断言命中数与伤害区间）；录制回放；配表回写工具联动 | 把 175 条技能的验收从人眼挪到脚本 |

## 六、这次不做

- 不做第二个战场：不接匹配、联机、存档、结算，不做对局回放系统。
- 不新增第二套伤害公式：所有数字必须由真实公式算出。
- 不把调试值写回真源：只导出补丁。
- 不覆盖经济数值（产金、建造耗时、城墙耐久）：那是经济调试台，另开。
- 不为了调试台去优化战斗循环性能：帧率不是这里的验收项。

## 七、真源与口径（不可在调试台自建常量）

| 维度 | 真源 | 调试台只允许 |
| --- | --- | --- |
| 尺寸 | `ZC_SPINE_CANVAS_TARGET_HEIGHT`（69.4）、`pvpCard.prefabSize`、`zcEffectNodeScaleOf`、六边格 36×42 | 读 + 乘同一个倍率 + 标注换算 |
| 数值 | 编译后的 `IZCRuntimeCatalogs`、`ZCCombatSystem.unitDamage` | 读 + 临时覆盖 + 展示明细 |
| 表现 | 真实 prefab、骨架动画名、真实飘字 prefab | 加载 + 播放 + 报错 |
| 布局 | `config/testkapai.json` | 只扩字段，不改已有语义 |

## 八、风险与对策

| 风险 | 对策 |
| --- | --- |
| 复用真实战斗后，调试台慢慢长成第二个战场 | 明确"只装配战斗子系统"，匹配 / 网络 / 存档一律不接；新增能力先问"这是调试需要还是玩法需要" |
| 覆盖值让人误以为线上就是这个数 | 黄色高亮 + 常驻"当前有 N 项覆盖"提示 + 退出还原 + 导出补丁才生效 |
| 车道太多，面板放不下 | 通用 4 个参数常显 + 车道专属 2~3 个参数折叠；按当前卡实际车道动态出参数 |
| 预览画布与战场适配不同，1:1 也只是"看起来 1:1" | P0 必须先核对两边 Canvas 适配与相机参数；对不上就以战场为准改预览，不改战场 |
| 数值调试吸引过多需求，拖慢技能落地 | 分期交付，P0 只做单靶单体，不做批量回归 |

## 九、验收清单

1. 同一张卡在「1:1」与「放大」下，模型高与六边格高的比值一致（误差 < 1%），且界面标注出的格数与实测一致。
2. 任一技能选择"近战靶 / 远程靶 / 克制靶"三种目标，伤害明细的克制乘数随目标变化，且与 `ZCCombatSystem` 手算结果一致。
3. 覆盖 `damageRate = 2` 后单次伤害正好翻倍；"还原全部"后回到配置值。
4. 暂停状态下点释放：不推进战斗；单步一次：只推进 1 tick；2× 与 1× 在固定种子下终局伤害一致。
5. 删掉一个 `effectPrefabPath` 或一个弹体路径：1 秒内红标定位到具体技能，其余卡仍可正常释放。
6. 覆盖 3 个字段后退出场景再进入：原有配置未被改写（可用 `pvpSkill` 快照比对）。

## 十、待确认（会影响 P0 排期，但不定方向）

1. **最小战斗会话的装配入口**：现有战斗逻辑能否在没有网络 / 存档的情况下直接跑 tick？需要一个研发确认的接入点（这是 P0 的关键依赖）。
2. **预览与战场的相机 / 适配是否一致**：需要在实机和编辑器预览各截一次同卡对比，确认"1:1"是不是真的 1:1。
3. **靶子的"守方减伤"口径**：当前公式里守方乘数来自克制 statId，是否需要额外模拟护甲 / 减伤字段（如果要做，必须先有配置列，不能在调试台自造）。
