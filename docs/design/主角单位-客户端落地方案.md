## 4. 模型层

### 4.1 状态字段（`model/ZCGameTypes.ts`）

```ts
// ZCUnitState 追加（全部可选，存量单位逐字不变）
captain?: boolean;
captainPhase?: 'patrol' | 'combat' | 'return';
captainAnchorHexId?: number | null;   // null = 无锚点（己方建筑全失）
captainPatrolX?: number;
captainPatrolY?: number;
captainPatrolWaitUntil?: number;
```

**不加枚举值**：`spawn` = `battleState='born'`、`dead` = `battleState='dead'`、战斗动作仍是 `move/attack`。`captainPhase` 只承载"巡逻/战斗/归位"三态。

### 4.2 注册表（`model/systems/ZCUnitRegistry.ts`）

```ts
markCaptain(unit: ZCUnitState): void {
    if (!this.alive.has(unit.id) || unit.captain !== true) return;
    this.regularCounts[unit.owner] = Math.max(0, this.regularCounts[unit.owner] - 1);
}
```

**为什么不能复用 `markSummon`**：它 `if (unit.summonMasterId === undefined) return;`，主角没有 `summonMasterId`，照抄等于空操作。放在 `register()` 之后、`spawnCaptain` 里调用一次（与 `summonUnits` 同模式）。

### 4.3 产出（新增 `model/systems/ZCCaptainSystem.ts`）

```ts
export function tickCaptains(state: ZCSnapshot, dt: number, ctx: ZCCaptainContext): void {
    for (const owner of ctx.owners) {
        const hqId = ctx.homeId(owner);                 // 单主城口径，不用遍历所有 hq 格
        const hq = state.hexes[hqId];
        if (!hq || hq.building !== 'hq' || hq.owner !== owner || !ctx.isOperational(hq)) continue;
        const interval = ctx.spawnSecondsOf(owner);     // hqCard.soldierAddSeconds
        if (!(interval > 0)) continue;                  // 0/空 = 该主城不产
        const key = `captain:${hq.id}`;
        if (ctx.captainOf(owner)) {                     // 场上最多 1 个：封顶不累加
            state.spawnClocks[key] = interval;
            continue;
        }
        if (state.spawnClocks[key] === undefined) {     // 首次：开局立即产
            ctx.spawnCaptain(owner, hq);
            state.spawnClocks[key] = 0;
            continue;
        }
        state.spawnClocks[key] = Math.min(interval, state.spawnClocks[key] + dt);  // 封顶防积压
        if (state.spawnClocks[key] < interval) continue;
        state.spawnClocks[key] = 0;
        ctx.spawnCaptain(owner, hq);
    }
}
```

四条不变量：

1. **键含主城 id**：`captain:${hqHexId}`，双方各一份。
2. **封顶不积压**：`Math.min(interval, …)`；不能照抄 `ZCEconomySystem.advanceCycle`（无上限累加 + `while` 扣减 ⇒ 积压会连产多只）。
3. **阵亡置 0 不删键**：`markDead` 之后 `state.spawnClocks[key] = 0`。删键会被「首次即产」误判成立刻复活。
4. **主城被毁**：`ZCDamageResolutionSystem.damageBuilding` 补一行 `delete state.spawnClocks['captain:' + building.id]`（现有只删 `mine:`/`barracks:`/`tower:`/legacy id）。

`spawnCaptain` 内部：`spawnUnit(owner, hqCard, hq.tier, hq.id, true)` → `unit.captain = true`、`captainPhase='patrol'`、`captainAnchorHexId = hq.id`、`registry.markCaptain(unit)`、`pushSummonSpawnFx` 同款 area 事件。

**塔防**：`if (config.pveDefence)` 在 `tickCaptains` 入口整体 return（判断放产出入口，不放行为分支）。

### 4.4 锚点

| 时机 | 动作 |
| --- | --- |
| 初始 | 主城格 |
| 主城被毁 | `damageBuilding` 回调 → `invalidateCaptainAnchor(owner)` |
| 重算 | `owner===self && building!=='none' && hp>0` 中取**世界距离最近**（同距取 id 小）；无则 `null` |
| 复核 | 每 0.5s：当前锚点格已不属于自己/建筑已毁 ⇒ 重算 |

**禁用 `cardId`、`state==='occupied'` 判己方**：主城被拆后 `owner` 会改成攻击方（`ZCDamageResolutionSystem.ts:102-104`），只能按 `owner + building + hp`。

### 4.5 行为（`model/systems/ZCUnitSystem.ts`）

挂点：`updateUnit` 里 **硬控 / 冲刺 / dashChain / born 之后、`refreshPriorityTarget` 之前**：

```ts
if (unit.captain) { this.updateCaptain(unit, dt, context); return; }
```

`updateCaptain` 判定顺序（**定稿**，逐条 return）：

```
1 dead / hp<=0            → 交回通用死亡流程（已在上游处理，这里直接 return）
2 硬控 controlOf          → 冻结（上游已处理）
3 born 未满 0.2s          → 站住
4 锚点复核（0.5s 节流）    → 更新 captainAnchorHexId
5 无锁定 && phase∈{patrol,return} && 仇恨有效 → 强制锁攻击者（跳过评分与半径）
6 已有锁定                → combat/move · combat/attack（不换目标、不设时限与距离）
7 120px 内最近敌方单位     → 锁定 → combat
8 有锚点 && 距锚点 > R     → return
9 其余                    → patrol/move · patrol/idle
```

第 5 条必须在第 6 条**之前**但带「无锁定」前提——否则战斗中受击即换目标（原文 §3 的 bug）。

### 4.6 索敌（`model/systems/ZCUnitTargeting.ts`）

新增 `acquireCaptainTarget(unit, radius, context)`，**不复用 `acquire`**：

```ts
// 1) 强制仇恨：直接返回，不进评分
const hater = hatredValid(unit, context) ? context.unitById(unit.hatredUnitId!) : null;
if (hater && context.canTargetUnit?.(unit, hater) !== false) return hater;
// 2) 半径内最近：复用 acquire 的过滤条件（同阵营/dead/hp<=0/flying），但距离不用 valueFactor 权重
```

理由：`acquire` 的仇恨是 `distance² × 0.25` 的权重加成，近处敌人仍可能胜出（已验证 `ZCTargetingSystem.ts:100-120`），达不到"强制锁"。评分规则一行不改，只加这一条新通道。

### 4.7 巡逻与移动

**采样方案 A（推荐，与格距口径一致）**：在 `hexGridDistance(anchor, candidate) ≤ 3` 的格里均匀挑一格 → 格内 ±`0.35×步长` 抖动。好处：不会出现"上下 3 格、左右 3.5 格"的观感偏差（方案 B 的圆采样 `r = R×√random()` 会有此问题，原文用的是 B）。

**无锚点（己方建筑全失）**：采样中心取**地图包围盒中心**、半径取对角线一半，落点在包围盒内均匀取；不要用"主角当前坐标"当圆心——那是随机游走，主角会长期黏在角落（原文字面实现如此）。

**移动**：`advanceTowardPoint`（`ZCMovementSystem.ts:107`），不走 BFS、不写 `targetHexId/progress`；阻挡用可选 `blockedAt?(x,y)`（敌方建筑 / 未破城墙），默认不判，不影响存量单位。

**巡逻减速**：`最终移速 × captainPatrolSpeedScale`；归位用全速。

### 4.8 快照与读档（`model/ZCSnapshotCodec.ts`）

- 新字段**天然透传**（`clone()` 全量复制，无白名单），不需要登记。
- `normalizeUnits` 补两条：① `captain === true` 时 `captainPhase` 缺省补 `'patrol'`；② `captainAnchorHexId` 指向的格已不是己方建筑 ⇒ 置 `null` 交给 §4.4 重算（**这是真正的读档坑：不重算会让主角围着敌人主城巡逻**）。
- 校验侧加 `check(optional(unit.captainPhase, v => oneOf(['patrol','combat','return'], v)))`，防脏数据。

### 4.9 结算剔除（`model/systems/ZCOutcomeSystem.ts:48`）

```ts
const units = state.units.filter(u => u.owner === owner && u.battleState !== 'dead' && u.captain !== true);
```

`unitCount` / `totalUnitHp` 同时生效。**必须先与策划确认**（§11-1），因为这会改变平局判定口径。

## 5. 表现层

### 5.1 皮肤：两个方案，先选一个

现状：单位预载按 `unitId` 单 prefab（`ZCGameLoader.ts:409` `units.set(definition.unitId, prefab)`），池也按 `unitId` 取。一个 unitId 要多套外观，只有两条路：

- **方案 A（推荐，改动小）**：美术交 **1 个主角 prefab**，内部放 3 个皮肤模型子节点；视图按「使用中皮肤 id」只 `active` 一个。代码加一个纯表现字段 `captainSkinId`（不进战斗判定、不进快照数值），零预载成本。
- **方案 B（美术只能给 3 个 prefab 时）**：预载计划按 `unitId#skinId` 出 3 条，池 key 同步改；代价是 `ZCGameLoader` / `ZCVisualResourcePlan` / 池三处都要动，且首帧多两次加载。

**未定之前不要写代码**——这是唯一会返工的模块。

### 5.2 主角标识

`ZCOutlineLayer` 复用现有描边通道 + 头顶小图标（走 `icon.json`/zarts，不新起加载器）。尺寸/颜色由美术给，先按「普通兵描边 + 14px 图标」占位。

### 5.3 出生 / 复活

复用 `pushSummonSpawnFx` 的 area 事件形态（`ZCGameModel.ts:3278`），主城格为中心、一次性播放，不新增事件类型。

### 5.4 复活倒计时（可选，不阻塞）

主城头顶小进度条，读 `spawnClocks['captain:'+hq.id] / soldierAddSeconds`。放 P4 末尾，做不做不影响上线。

## 6. 养成数值注入

### 6.1 分层约束

`zcds/model` 禁止 import `app/role/*`（会带进 cc），所以天赋聚合**不能**在 model 里算。链路：

```
MilitiaRepository（role，带 cc）
  → MilitiaTable.talentRatesOf(rows, level, modifiers) : { attackRate, hpRate }   // 新增
  → 上层组装 captainRates: Record<'66014', IZCBattleRates>
  → buildZCClientCombatConfig(source, battle, selfRoleId, options, captainRates)
  → config.unitRates[owner]['66014']
  → resolveZCUnitDefinition(...) 逐单位取
```

### 6.2 注入点（`application/ZCClientCombatConfig.ts`）

新增第 5 个可选参数 `captainRates?: Readonly<Record<string, IZCBattleRates>>`，在 `unitRatesOf` 之后合并：

```ts
const rates = unitRatesOf(unit, heroes, waveUnits);
const merged = captainRates ? { ...rates, ...captainRates } : rates;   // 主角单独一条，不覆盖英雄
if (merged) unitRates[owner] = merged;
```

**为什么用参数而不是在函数里 import `MilitiaRepository`**：`application` 层仍属 zcds，import `role/*` 会把 cc 依赖带进战斗配置；且测试需要能直接喂数值。调用方（`ZCBattleEntryBuilder` 或对局入口）本来就有玩家数据。

### 6.3 公式落点

天赋/皮肤只给 `attackRate` / `hpRate` 两个乘区（与 `IZCBattleRates` 现成字段对齐）；品级加成仍走 `unitHpPerTier` / `unitAttackPerTier`（现有通道），**不要在 `unitRates` 里再乘一次**，否则重复计算。

皮肤收集加成 = Σ 已拥有皮肤（按 id 去重）；切换使用中的皮肤**只改 `captainSkinId`**，不进 `unitRates`。

### 6.4 一期范围

只接 `民兵伤害增幅` + `民兵生命百分比`（表与字段都现成）。攻速/移速/暴击需扩 `IZCBattleRates`（改契约），二期做。

## 7. 每拍顺序与归属

| 顺序 | 调用 | 归属 | 说明 |
| --- | --- | --- | --- |
| 1 | `flushPendingSummons` | 现有 | — |
| 2 | `updateEconomy` / `updateBarracks` / `updateTowers` | 现有 | — |
| 3 | **`tickCaptains(dt)`** | 新增 | 排在 `updateUnits` 之前：当拍产出的主角当拍即可索敌（同 `flushPendingSummons` 口径） |
| 4 | `updateUnits` → `ZCUnitSystem.update` | 现有 | 主角走 `updateCaptain` 分支 |
| 5 | `removeDeadUnits` | 现有 | 阵亡此处触发计时器归零 |

不变量（写成测试）：① 同屏每方存活主角 ≤ 1；② `spawnClocks['captain:'+hq]` 永不超过 `soldierAddSeconds`；③ 主角不计 `regularCounts`（`unitCapPerSide` 不受影响）；④ 主角不进 `scoreFor` 的 `unitCount/totalUnitHp`。

## 10. 风险登记

| 风险 | 触发条件 | 兜底 |
| --- | --- | --- |
| 主城行带单位列被闸拦 | 只改表不改 §3.2 | 两步必须同一次提交；反向用例保证不误放行 |
| 主角越过人口上限 | `markCaptain` 漏调（`register` 后没补） | 断言 `regularCounts` 不增；P0 用例覆盖 |
| 复活变"瞬活" | 阵亡时 `delete` 而非置 0 | 代码注释写死；用例钉 29.9s/30.1s |
| 计时器积压连产 | 照抄 `advanceCycle` 无上限累加 | `Math.min` 封顶；用例：存活 5 分钟后不出现多只 |

| 评分口径变化 | 剔除主角后平局变多 | 上线前与策划对数；该行可独立回退 |
