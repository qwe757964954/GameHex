## 二、“看似冗余但暂时保留”的逐段复核

| 项 | 结论 | 审核范围与依据 |
|---|---|---|
| `SevenDayTable.listDayTabs` / `listRowsOfTab` | **保留** | 全仓 `rg` 确认默认路径不消费（`SevenDayPage.SHOW_PAGE_TAB_BAR = false`），但它们是 `SHOW_PAGE_TAB_BAR` 的显式备用渲染分支：`SevenDayPage.ts` L227-L249 同时保留两条分支，`seven-day.test.ts` L1588/L1601/L1624 明确锁定“关闭页签栏时走单列表、打开时数据层仍可用”。删除会移除一个有测试契约的渲染模式，不属于无引用死代码；保留成本仅为纯函数 |
| `SevenDayPointBox.redDot` | **保留为可空** | prefab 原稿故意不建宝箱红点节点，`render` 必须判空，否则渲染路径 `null.active` 抛错；已从 `null!` 回退为 `Node | null = null`，这是真实可空字段，不是防御性冗余 |
| `SevenDayRewardSlot.frame` 的同节点自取 | **保留兜底** | `frame` 是“本节点自己的 `cc.Sprite`”，`onLoad` 里 `getComponent(Sprite)` 兜底；prefab 未序列化该字段时仍能工作，删除会让奖励格在部分 prefab 变体上直接空引用 |
| `SevenDayPageTab.background` / `SevenDayDayTab.background` 自取 | **保留兜底** | 同为“同节点指自己”的 `@property`，新建/复制 prefab 时编辑器未必写入字段；`render` 内自取是兼容路径，已绑定则不会走到 |
| `GuideController.skipAll/skip` 对 `options.steps` 非空的依赖 | **保留** | `GuideProgress` 构造器对空表直接抛错（`guide-progress.test.ts` “空表直接抛”锁定），`start()` 失败后不会进入 skip；加显式空表保护反而掩盖配置错误，且无实际调用路径 |
| `LoginPage.statusLabel` 可空 + `onLoad` 恢复 | **保留** | prefab 当前已绑定 `statusLabel`，但 `login-page-lifecycle.test.ts` 明确锁定“restores optional status binding”；`render` 仍判空，兼容没有 status 节点的登录 prefab 变体。删除会破坏既有测试契约 |
| `LoginRoot.hasSavedSession_` | **保留** | `bootstrap/login/LoginComposition.ts:121` 将其转发给登录流程，属于生产消费；不是无引用 getter |
| `OSArtStrip._ensurePool` 的 `if (!this.itemPrefab)` | **保留** | 必填引用仍可能在 prefab 漏绑；这里不是静默兜底，而是 `console.error` 明确报错后返回，用于暴露配置错误 |

## 四、结论

- 本轮修改均以“删除无消费代码、统一必填引用写法、去掉不可达判空、消除重复逻辑”为主；正常 prefab 绑定路径下的业务行为与原有实现一致。
- 已删除的 API/常量：`boxHasRedDot`、`anyDayHasRedDot`、`isSpecialProgressTarget`、`pendingRewards`、`CL_PAY_SDK_AVAILABLE`、`CL_READ_TIMEOUT_MS`、`CL_WRITE_TIMEOUT_MS`、`rewardsOfTarget`、`shopBranchOf`、`setFrameSliced`、`OSShopItem.soldOutTip`。
- 仍需在提交前处理的范围外事项：根目录 18 个日志文件的归档（`npm run verify:hygiene` 阻断项）、`BigMapConfigLoader.ts` 的既有类型错误。上述均未在本轮擅自修改。
