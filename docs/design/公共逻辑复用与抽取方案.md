# 公共逻辑复用与抽取方案

> 状态：公共实现已落地；本轮迁移收尾（调用方迁移、兼容导出退场、ClickBinding 删除）已完成，最终 fresh 门禁结果见 [公共逻辑复用与抽取收尾报告](../reports/公共逻辑复用与抽取收尾报告_2026-11-16.md)。工作区仍有 zcds/territory/card 等并行未提交改动导致的失败，不把历史通过数字当作当前全绿。
>
> 范围：`assets/script` 下全部非生成 TypeScript 源码的跨模块重复审查。
> 原状态：只读审查与方案设计，未修改任何源码；方案落地前需按本文的分阶段顺序执行。
> 结论：重复量最大、风险最低的收益不在“把相似函数合成一个”，而在**把寄居在 feature 里的公共件归位、把纯逻辑下沉到 core、把网络/配置读取收口到单一入口**。直接合并同名函数会破坏现有测试钉死的差异契约。

## 0. 结论摘要

### 0.1 五个先做

| 顺序 | 事项 | 原因 | 预期收益 |
| --- | --- | --- | --- |
| 1 | `parseItemRows` / `parseRolePropertyRows` / `rewardGoodsOf` / `IActivityGoodsInfo` 从 `activity/LayerActivityTable.ts` 移到 `app/common/ResTypes.ts` | battletoken / celebration / hang / mail / league / showReward 反向依赖 activity；这是分层问题，不只是重复 | 消除 6 个 feature 对 activity 的反向依赖；保留原导出名，调用方可零改动 |
| 2 | `resolveRewardIconRef` / `resolveItemIconRef` / `splitIconPath` 从 activity / sevenDay 移到 `app/common/RewardIcon.ts` | 奖励图标“唯一入口”寄居在 activity，sevenDay 的 item 图标解析又被 gift / hang / league 复用 | 消除 activity / sevenDay 对奖励图标的路径垄断；showReward / battle / territory 不再依赖 activity |
| 3 | `toCount` / `toIdString` / `toPositiveInt` / `toText` 下沉到 `core/value/Coerce.ts`，`RequestGuard` 保留 re-export | `app/common/ResTypes.ts` 目前反向 import `app/net/RequestGuard`；common 不应依赖 net | 修正 common → net 的反向依赖；56 个既有 import 不需要改 |
| 4 | 14 个 `readRows` 收口为 `app/common/TableRead.ts` 的 `readRefRows` / `readRefRowsSafe`（source 由 repository 传入；`FirstRechargeRepository` 因用户改动延后） | 14 个 3 行精确副本 + ItemDetail 的 8 行 try/catch 变体；错误处理与空值兜底只留一处 | 其余 13 个 repository 先统一；FirstRecharge 稳定后补第 14 个；迁移 `ConfigService` 时改一行 source 参数，不再复制错误处理 |
| 5 | `parseRows` / `parseRewards` 的循环骨架抽到 `core/table/RowParse.ts`、`core/table/RewardRows.ts` | 9 处 `parseRewards`、多处 `asRow` / `parseRows` 的循环完全同构，但校验口径不同 | 去掉重复循环，保留每个 feature 的校验策略；不强行合并语义 |

### 0.2 三个不要做

1. **不要把 `formatText` 五处合成一个无参数函数**：Chat 缺参补空串、Friend/Mail 缺参保留原样、Gift 缺参保留但 null 转字符串、ItemDetail 只替换已传参数。`tests/chat.test.ts` 与 `tests/friend.test.ts` 已把差异钉成契约。
2. **不要把三个 `parseItemRows` 合为一个**：activity（后出现覆盖、quality 缺省 0）、sevenDay（先出现保留、quality 缺省 1）、itemdetail（后出现覆盖、quality 缺省 1）是三种明确不同的表契约，`tests/seven-day.test.ts` 与 `tests/itemdetail.test.ts` 分别钉住。
3. **不要把 `afterWrite` / `beginWrite` 抽成页面基类或通用写门闩**：`afterWrite` 内含页面专属的 `reload()`，`beginWrite()` 是页面 `busy` 状态；`tests/league-task.test.ts`、`league-apply-edit.test.ts`、`league-north.test.ts` 直接检查页面源码。抽取的收益低于测试改造与继承风险。

### 1.2 方法

1. 用仓库自带 `node_modules/typescript` 建 AST 扫描器，提取函数体、常量初始化、接口/类型字段。
2. 做两套归一化哈希：
   - **精确归一化**：去注释、空白、尾逗号，保留标识符与字面量；
   - **结构归一化**：再把标识符与字面量替换为占位符，用于发现“结构相同但语义可能不同”的候选。
3. 输出精确组、结构组、同名组、同名常量组、同构类型组。
4. 对每个候选做三件事：
   - 读原始函数体，确认是否真的同义；
   - 找调用方，确认是否跨 feature；
   - 找测试断言，确认是否钉住源码文本或导出路径。
5. 只有同时满足“语义同义 + 调用方明确 + 行为可等价”的项才进入 P0/P1；仅有结构相似的项进入 P2 或不抽。

## 3. 抽取原则与边界

### 3.1 放置规则

| 目录 | 放什么 | 禁止 |
| --- | --- | --- |
| `core/**` | 纯 TS、零引擎、零 `framework/app/platform`、无直接 I/O 的算法与类型 | 不得 import `cc`、`framework`、`app`、`platform`；不得取全局单例 |
| `app/common/**` | 跨 feature 的 cc/资源/UI 公共件；可 import `cc`、`core`、`framework`、`app/net` 的纯类型 | 不得 import 任何 `app/<feature>`（尤其 activity / sevenDay / showReward） |
| `app/net/**` | 网络协议壳、请求守卫、超时与状态映射 | 不得 import 具体 feature；不得混业务规则 |
| `app/<feature>/**` | 仅本 feature 使用的解析、文本、布局、页面辅助 | 不得把“已被多个 feature import 的件”继续留在这里 |

硬约束：一个文件只承担一个清晰职责；禁止 `Utils.ts`、`Common.ts`、`Manager.ts` 大杂烩。类型名按仓库规范用 `I` 前缀，常量 `UPPER_SNAKE_CASE`。

### 3.2 行为等价约束

抽取时必须逐条保留：

1. **公开导出名与路径**：先在旧路径 re-export，再逐步改 import；不要同一次提交同时删旧导出和改所有调用方。
2. **错误语义**：`readRows` 的 14 个副本不吞异常；ItemDetail 的变体吞异常并降级空数组。不能合并成一个“统一吞异常”的函数。
3. **重复键策略**：`parseItemRows` 的 first/last 策略随 feature 不同；共享 helper 必须显式传策略，不能默认一套。
4. **数值边界**：`clamp01` 的 NaN 行为、`toMillis` 的 Long 优先级、`formatHms` 的 `Math.ceil` 与负数钳 0，必须保持。
5. **缺参/缺字段文案**：`formatText` 的“补空串 / 保留占位 / null 转字符串”差异不能合并。
6. **请求状态映射**：`'ok' | 'offline' | 'failed'` 的判定顺序（先连接、再超时、再异常）不能变；额外状态 `'noInstance'` / `'rejected'` 保留。
7. **页面写锁与刷新顺序**：`beginWrite()` 先判 `busy` 再置位；`afterWrite()` 先判 `alive`、`ok` 时 `reload()`、否则提示。不要用通用基类改变执行顺序。
8. **资源路径字符串**：`ArtPaths` 常量与现有硬编码值必须逐字相同；不改资源目录、不改 meta。

### 3.3 不抽 / 缓抽判据

满足任一条则不进入本轮抽取：

- 同名但语义不同，且没有统一参数化方案；
- 函数体只有 1～3 行，抽取后调用方仍需传 3 个以上参数；
- 页面专属状态（`busy` / `alive` / `reload` / `qualityFrames` 缓存字段）与函数体强耦合；
- 测试直接钉住页面源码文本，且该文本是业务契约（按钮分流、写锁、奖励接线）；
- 已有权威文档明确结论“不抽”（如好友页面基类）。

## 11. 后续复用规范

### 11.1 新增公共件前先查

1. 先搜 `assets/script/core`、`assets/script/app/common`、`assets/script/app/net`，确认没有同义实现。
2. 再看是否已被 2 个以上 feature import；如果是，禁止留在 feature，按第 3.1 节归位。
3. 如果只是“结构像”，先写一张差异表（输入/输出/错误/边界/重复键），再决定抽不抽。
4. 不要新建 `Utils.ts` / `Common.ts` / `Manager.ts`；用职责名命名文件。

### 11.2 API 设计规则

- 纯逻辑进 `core`；cc/资源/UI 进 `app/common`；网络/协议进 `app/net`；feature 私有逻辑留在 feature。
- 入参用 `unknown` 做边界，内部窄化；返回类型显式；接口/类型 `I` 前缀；常量 `UPPER_SNAKE_CASE`。
- 不用 boolean 参数堆叠；用 options 对象，默认值写在签名上，注释说明每个默认值的业务口径。
- 不静默吞异常；需要降级时由调用方显式选择 `safe` 版本。
- 不改变公开导出名；迁移期用 re-export，退场条件写进注释。
- 一个函数只做一件事：`RowParse` 不做业务校验，`RewardRows` 不做 UI 映射，`TableRead` 不做缓存。

### 11.3 测试与审查规则

- 公共件测试直接 import 真源，不复制算法；feature 测试保留行为契约。
- 源码文本断言只用于“接线”（import/调用点/页面生命周期），不要用于钉函数体实现细节；函数体差异应由公共件的行为测试覆盖。
- 移动代码时，先加/改公共件测试，再改调用方；测试用例名集合做双向差集，禁止只看总数。
- 审查清单：
  - 是否有 feature 反向 import？`rg "from '../activity|from '../sevenDay|from '../showReward" app/common app/net`
  - 是否有 `common -> net` 反向依赖？`rg "app/net/RequestGuard" app/common`
  - 是否有重复 `readRows` / `asRow` / `toCount` / `easeOutCubic` / `clamp01`？
  - 是否有同值常量散落（5000 / 800 / 86400000 / 86400 / 0xffffffff）？
  - 是否有同形 `*RequestResult` / `I*Reward` 新定义？

### 11.4 定期扫描

- 本轮临时 AST 扫描器未入库；建议后续落到 `tools/audit/` 并纳入 `verify:guards`，至少每季度跑一次。
- 扫描口径固定：排除 `app/generated`、`lib`、`framework/dts`；精确组阈值 150 字符/4 行；短函数 50 字符/2 行。
- 新扫描结果先人工分类，不把结构克隆直接当缺陷；同名组只作线索，不作结论。
- 每次重构后复测同一口径，记录“消除的组数 / 新增的组数”，不要只报总数。
