## 3. 治理边界与五层唯一真源路由

常量规范的权威条款维护在 [开发细则.md](../agent/开发细则.md)「常量归属与防泛滥」。本工程落地按以下五层模型划分真源：

| 层级 | 承载内容 | 真源载体 | 禁止放入 |
| --- | --- | --- | --- |
| **L1 配表与协议** | 数值公式、解锁/掉落参数、ID 枚举 | `assets/remoteRef/*.json`、`RefEnum.ts` | 代码侧静默维护第二份可调业务表（缺列兜底须标注覆盖列名） |
| **L2 引擎资产** | 固定宽高、坐标、边距、网格步进、静态色号 | `.prefab` / `.scene`、`@property` | 在 `assets/script` 留存已进 Prefab 的旧 `*Layout.ts` 几何常量 |
| **L3 跨模块纯契约** | 跨 feature 表名、Bundle/图集目录、公共按钮/提示、时间/几何基数 | `TableNames.ts`、`BundleCatalog.ts`、`ArtPaths.ts`、`TimeMs.ts`、`HexGridLayout.ts`、`app/common/*`、`Timeouts.ts` | 单 feature 私有常量、旧模块二次 `re-export` 转发壳 |
| **L4 Feature 域契约** | 领域默认值（`model/`）、意图事件（`Events.ts`）、冻结主题与样式字典（`view/`、`ui/`） | 单对象 `as const` / `Object.freeze` 字典 | 逐条散导几十上百个原子常量；UI `*Style` 进 `model/` |
| **L5 文件内私有** | 仅本文件使用的局部门限与内部配置 | 不加 `export` 的文件顶部 `const` | 对外 `export` 暴露内部细节 |

**四项明确不做**：
1. 不建跨领域全仓 `Constants.ts` 常量坟场；
2. 不抽离 `0` / `1` / `-1`、`1e-6`、数组下标、数学恒等式、动态世界坐标与帧插值；
3. 不强行合并语义或测试契约明确不同的同名/同值文案（遵循 [公共逻辑复用与抽取方案.md](公共逻辑复用与抽取方案.md) §0.2）；
4. 不在未完成核对的情况下批量格式化或覆盖当前工作区（`bigmap/`、`bootstrap/`、`zcds/`、`remoteRef/`）在途改动。

## 4. 分阶段实施路线

### Phase 0：规范落地与工作区划界（已落地）

1. 在 [开发细则.md](../agent/开发细则.md) 固化「常量归属与防泛滥」条款（已完成同步）。
2. 执行**白名单增量治理**：先绕开当前 `svn status` 中他人/在途 `M` 集密集的模块，优先推进独立且零业务变更的清理项。

### Phase 1：死导出清算与过渡壳退场（1～2 天，低风险）

1. **剥离布局迁移残骸**（首批已落地，见 §6）：
   - 清理 `MonthCardGiftLayout.ts` 与 `LayerActivityLayout.ts` 中已被 Prefab/Layout 接管的坐标尺寸常量：仍在生产使用的公式保留，仅测试几何对齐需要的数值移入对应 `tests/fixtures/` 夹具（参考 `store-section-layout.ts` 范式）。
   - 用 CodeGraph 核实其余全仓零引用常量（优先无在途冲突的模块），逐批删除。
2. **退场兼容壳与冗余 `re-export`**（未落地）：
   - 删除 0 引用的 `ZCWindBoltFx.ts`，分批让其余 17 个 `ZC*Fx.ts` 兼容壳退场并直连 `ZCEffectCatalog.ts`。
   - 收口 `ResTypes.ts` 对 `TableNames` 4 常量的重复导出、6 个 `*Art*` 对 `ArtPaths` 的同名 `*_ART_ROOT`、以及 `QualityFrameArt` 的多层转发；先核全仓引用，一次性切换上游 `import` 后删除转发壳。

### Phase 2：收拢多真源、折叠原子导出与 MVC 归位（2～3 天，中风险，未落地）

1. **公共真源闭环**：
   - 将散落多处的 `'item'`、`'open'`、`'gameConfig'`、`'equip'` 等跨模块表名收口到 `TableNames.ts`；单 feature 私有表名留在各自唯一 `Repository`。
   - 对齐 `BundleCatalog.ts` 与 `ArtPaths.ts` 的共用根目录路径；在 `app/common/` 收拢跨模块公共图名（如 `TY_btn10/21/23`、`zx_btn01`、`img_Touxiang_01`、`title_brown`、`公用_按钮_关闭01`）与统一失败/确认提示文案。
   - 替换高频裸数字：`86400` 统一走 `TimeMs.MS_PER_DAY`，资源/属性/技能 ID 优先引用 `RefEnum.ts` 或领域目录表。
2. **折叠原子碎裂文件**：
   - 将 `LeagueArt.ts`（161 导出）、`LeagueTexts.ts`（124 导出）、`FriendTexts.ts`（47 导出）、`FriendArt.ts`（34 导出）、`ChatArt.ts`（32 导出）、`StoreTable.ts`（26 导出）按功能面板/语义拆分为冻结字典对象，同步更新对应单测（如 `league.test.ts`、`store.test.ts`）。
3. **完成 `zcds` 治理与 MVC 归位**：
   - 接续 [zcds-硬编码与注释治理方案.md](zcds-硬编码与注释治理方案.md) P2：建 `ZCCombatDefaults.ts`、删除裸 `42` 改用 `HEX_GRID_LOGICAL_ROW_STEP`、剥离 `30845`/`68010` 等魔法 ID 分支。
   - 将 `app/zcds/model/` 中 UI 专属 `*Style.ts` 迁至 `app/zcds/view/` 或 `ui/`；扩展 `tests/helpers/zcds-view-fixtures.ts` 的纯数据模块解析白名单，使 `ZCSkillAnnounceStyle.ts` 直接复用 `ZCBattlePresentationQueue` 单一真源，删除第二份 `2.3`。

### Phase 3：颜色冻结、Enum 退场与不可变加固（1～2 天，按模块渐进，未落地）

1. **主题色冻结与归位**：先为 `ZCTheme.ts`、`BigMapTheme.ts` 补齐 `Object.freeze(new Color(...))`；随后按模块收拢分散在 82 个文件的 293 处非 Theme `new Color(...)` 至各模块 `*Theme.ts` 或文件内冻结色板。
2. **自有 `enum` 退场**：将 16 个自有非 `const` `enum`（先框架/路由/弹窗如 `GameRoute`、`PopupDef`，再业务表/事件）分批改为 `as const` + 联合类型，同步更新类型消费方与验证用例。
3. **不可变与命名收敛**：为 188 个可变导出对象/数组补充 `as const` / `Object.freeze`；梳理非 `UPPER_SNAKE_CASE` 导出（明确区分 `camelCase` 服务单例、`PascalCase` 事件字典与 `UPPER_SNAKE_CASE` 纯常量）。

### Phase 4：增量自动化门禁（已落地，0.5 天）

新增只读结构守卫 `tools/verify/constant-guard.mjs`，已纳入 `package.json` 的 `verify:guards` 与 `tests/verify-gate.test.ts` 的 `GUARD_TESTS` 清单，采用“**存量建基线、增量零新增**”机制（基线 `tools/verify/constant-baseline.json` 随仓库走，指纹为 `rule|file|symbol`，不含行号）：

| 规则 | 拦截内容 |
| --- | --- |
| C1 / C2 / C11 | 新增 `export const` 全仓零引用（死导出）/ 仅本文件消费（应去掉 `export`）/ 仅测试与工具引用（生产零消费）；`typeof` 派生公共类型时豁免 C2 |
| C3 / C10 | 与 `TableNames` / `ArtPaths` / `BundleCatalog` / `TimeMs` / `Timeouts` / `HexGridLayout` 同值（error）；跨文件导出同名（warn） |
| C4 | 非 `*Theme.ts` 文件新增裸 `new Color(...)` |
| C5 / C6 | 新增非 `const` `enum`；导出的对象/数组字面量缺 `as const` / `Object.freeze` |
| C7 / C8 | `model/` 下新增 `*Style.ts` 或字号/色号词法；非 `common` 的跨 feature 直连 `*Art.ts` / `*Texts.ts` |
| C9 | 单文件扁平 `export const` 超 15 个（新文件，或较基线净增超 15）——仅提示 |

命令：`check`（增量门禁）、`audit`（全仓统计，方案数据复核口径）、`baseline`（清理完成或接纳存量后重算）。基线按 `rule|file|symbol` 定位（不含行号）；**文件搬迁或批量折叠后需重算基线**，否则存量会按新路径被判为新增。
