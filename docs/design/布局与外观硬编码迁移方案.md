## 1. 判定口径

### 1.1 什么算本次要迁移的“布局与外观硬编码”

满足以下任一条件，且值属于设计稿而非运行时数据，纳入迁移：

- 直接写节点 `position / contentSize / anchorPoint / scale`，值是设计稿尺寸或版面位置。
- 用模块常量保存设计尺寸、间距、步进、页签/面板坐标，再在 `render / refresh / apply` 里写进节点。
- 用 `visibleSize.height`、`screen.windowSize` 做“长屏补偿”，把固定节点上下平移或拉高。
- 在代码里创建节点并用字面量搭版式（宽高、锚点、字号、间距）。
- 代码回写 prefab 已经存在的静态值，形成第二真源。

### 1.2 什么不算，保持现状

| 类型 | 例子 | 原因 |
|---|---|---|
| 世界/战斗坐标 | `BigMapWorldView`、`TerritoryMapView`、`ZCHexView`、`ZCUnitView`、`ZCEffectPool` | 由地图数据、相机、帧同步驱动，prefab 无法静态表达 |
| 数据驱动尺寸 | 进度条 `fill.width = ratio * trackWidth`、血条、经验条 | 宽度是数据函数，不是设计常量 |
| 动画过程 | `setScale` 弹跳、`tween` 位移、透明度渐变 | 目标值可配置，过程必须逐帧算 |
| 中性复位 | `setPosition(0,0)`、`setScale(1,1)`、`anchor(0.5,0.5)` | 0/1 是变换单位元，不是设计值 |
| 安全区/导航覆盖 | `MainHudLayout`、`BigMapPageLayout`、`GuideDialogView` 的 `widget.bottom/top` | Widget 的正确用法是 prefab 给默认值，运行时按环境覆盖 |
| 已声明的 `@property` 真源 | `Toast` 的 `fontSize/lineHeight/barWidth`、`OSArtStrip` 的 `itemWidth/gap` | 代码写 Label 是为了让 `@property` 成为唯一真源，prefab 只是副本 |

### 1.3 迁移后的真源规则

- **静态值**：只存在 prefab 节点属性里；代码不写、只在必要时读。
- **两态值**（领先/普通、倒计时/空闲、自己/他人）：prefab 存主态；次态用 `@property` 或第二个状态子节点，不在代码里写两个坐标。
- **间距/内边距**：节点没有“间距”属性，必须落 `@property`，由 prefab 序列化；不要留在模块常量里。
- **自适应**：`cc.Widget` 负责“贴边/拉伸/居中”；`cc.Layout` 负责“子节点之间怎么排”；两者不要放在同一个节点上互相打架。
- **代码只保留**：`active` 切换、数据文案、贴图替换、`@property` 读取、进度/动画计算。

- 外层 `Widget` 负责容器贴边/定宽；
- 内层 `Layout` 负责子节点排布；
- `Layout.resizeMode=CONTAINER` 只让容器随内容长高，不再让 Widget 拉它。

## 3. 每一处硬编码到 prefab/Widget 的对应方式

### 3.1 Widget 配置速查

Cocos `cc.Widget` 的 `AlignFlags`：

| 组合 | 数值 | 适用 |
|---|---:|---|
| TOP + CENTER | 17 | 贴顶、水平居中（标题、关闭键、顶部装饰） |
| BOT + CENTER | 20 | 贴底、水平居中（底栏、页签、底部宝箱） |
| TOP + BOT + CENTER | 21 | 上下拉伸、水平居中（面板、列表、行容器） |
| LEFT + RIGHT + MID | 45 | 四边满屏（根节点、PageRoot） |

换算公式（父节点高 `H`、节点高 `h`、节点 y、锚点 y=`0.5`）：

```text
top    = H/2 - (y + h/2)
bottom = (y - h/2) - (-H/2)
hCenter = x
```

对 `anchorY=1` 的节点（如 ListView、RowView）：

```text
top    = H/2 - y
bottom = (y - h) - (-H/2)
```

三个页面的具体值已在 2.1 表中给出，可直接照填。填完后必须核对：

- `_alignFlags` 是十进制，不是位运算表达式；
- `_alignMode=2`（ALWAYS），不要用 ONCE；
- `_isAbsLeft/_isAbsRight/_isAbsTop/_isAbsBottom` 为 `true`（绝对像素），不是百分比；
- 节点自身 `_contentSize` 保持设计态，Widget 只负责在父容器变化时改写它。

### 3.2 静态属性：prefab 节点属性 vs `@property`

优先级从高到低：

1. **节点自身就有的属性** → 直接写 prefab：`_lpos`、`_lscale`、`_contentSize`、`_anchorPoint`、`cc.Label._fontSize/_lineHeight/_color/_spacingX`、`cc.Sprite._sizeMode`。
2. **组件之间的间距/内边距/两态值** → `@property`，在 prefab 的组件面板序列化：如 `speedUpIconGap`、`openLabelCenterY`、`activeBadgeLeft`、`nameRightPad`。
3. **需要读取 prefab 现值作为基准** → `onLoad` 缓存，不在 `render` 里重复写：如 `ChestSlot/TimeText` 的初始 `107×24`、`BtnLabel` 的初始宽 94、`SpeedUpIcon` 的初始宽 28。

反例：`ChestSlotView` 把 `107/24/94/28` 写成模块常量，再在 `render` 里 `setContentSize`。即使数值和 prefab 一样，也构成第二真源；prefab 一改，代码就把旧值写回去。正确做法是 `onLoad` 读一次、缓存，之后只写“当前需要的宽度”，不写“设计上限”。

### 3.3 Layout 配置速查

| 场景 | `type` | `resizeMode` | 关键参数 | 备注 |
|---|---|---|---|---|
| 单行等距（奖励格、日牌） | HORIZONTAL | NONE | `spacingX`；子节点预摆 | 容器宽固定，超出由父级 Mask 裁 |
| 多行网格（奖励、头像墙） | GRID | NONE | `startAxis=HORIZONTAL`、`constraint=FIXED_COL`、`constraintNum=4`、`cellSize`、`spacingX/Y` | 槽位预摆，代码只切 active |
| 纵向列表（获取途径、匹配条、建造行） | VERTICAL | CONTAINER | `spacingY`、`paddingTop/Bottom` | 外层 Widget 定宽，不再拉高 |
| 分段商城 | VERTICAL | CONTAINER | `spacingY=10` | 段高仍由数据算，Layout 只管段间距 |
| 双态版面 | 不用 Layout | — | 两个子组或 `@property` | 自己/他人不是等距镜像，Layout 无法表达 |

`cc.Layout` 本身没有“整体居中”选项：`resizeMode=NONE` 时内容从容器左上角开始排；要复现代码里的“整块居中”，让 Layout `resizeMode=CONTAINER` 收缩到内容，再由父节点 Widget/锚点居中，或把余量写进 `paddingLeft/Top`。不要指望 Layout 自动居中，否则第一版会整体偏到左上角。

### 4.2 prefab 侧操作顺序

必须在 Cocos Creator 编辑器内用 MCP 完成，不要手写 `.prefab` JSON。推荐顺序：

1. 备份当前 prefab（MCP 的 prefab 编辑默认会建备份；改前再确认一次工作区 diff）。
2. 打开目标 prefab，按 2.1/3.2 表改节点属性；先改 `_contentSize/_lpos`，再加 `cc.Widget`。
3. 加 `cc.Widget` 后设置 `alignFlags`、`top/bottom/left/right/horizontalCenter`、`alignMode=ALWAYS`；不要先设 `bottom` 再设 `top` 后保存两次，避免中间态把 `_bottom` 按旧位置重算。
4. 保存前检查节点的 `_contentSize` 有没有被 Widget 改写；带 Widget 的节点在编辑器里保存可能按当前对齐重算尺寸（工程里 `QueueText` 被重算成 `0×30` 的旧例）。如果被改写，先把 Widget `_enabled=false` 或临时移除，保存节点尺寸后再启用。
5. 保存后刷新资源、校验 prefab 引用；再用编辑器打开一次，确认 Widget 面板数值与表一致。
6. 三页改完后，把 `topAlignedNodes/bottomAlignedNodes` 从组件上清空；不要在代码里保留“名单兜底”。

### 4.3 三页改完后的运行链

改前：

```text
onOpen → loadData → _applyScreenLayout()
  → 读 visibleSize.height
  → root.setContentSize
  → panelBg.setContentSize/Position
  → list.setContentSize
  → bottomBar/backBtn/tabBar.setPosition
```

改后：

```text
onOpen → loadData → render
  → root 由 prefab Widget 满屏
  → panelBg/list/rowView 由 Widget 拉伸
  → bottomBar/backBtn/tabBar 由 Widget 贴底
  → 代码只写 barFillWidth(ratio)、宝箱 x(ratio)、文案、active
```

判断标准：在 720×1280、720×1555、1080×2400 三种高度下，三页的顶部标题、面板、列表、底栏都不需要代码参与，且没有节点被拉出屏幕。

### 4.4 状态切换写法

两态/多态版面不要“算两个坐标再 setPosition”。推荐两种写法：

1. **prefab 双态子组**：`NormalGroup` / `ActiveGroup` 各摆一套，代码只切 `active`。适合差异大、子节点多的（聊天自己/他人、好友普通/删除、卡牌技能格）。
2. **`@property` 双值**：`normalX/activeX`、`normalWidth/activeWidth`。适合差异只有 1~3 个数值的（宝箱格、角标、按钮文案）。

无论哪种，`render` 必须幂等：每次全量设置 `active`、文案、贴图；不要“上次是 A 态才改”式的增量判断，否则复用节点会残留上一态的位置。

### 4.5 外观默认值

颜色、字号、行高、字距、描边这些“默认外观”优先放 prefab 的 `cc.Label/cc.Sprite`：

- 常态色：prefab `Label.color`；
- 字号/行高：prefab `_fontSize/_lineHeight`；
- 描边：prefab `_enableOutline/_outlineColor/_outlineWidth`；
- 九宫/拉伸：prefab `Sprite._sizeMode`、`_isTrimmedMode`。

代码只保留“错误态/高亮态”的覆盖值，且落 `@property`，不要在 `render` 里写 `new Color(...)`。

## 5. 注意事项与风险

### 5.1 Widget 与 ScrollView / 虚拟列表

- `cc.Widget` 不要挂在 `ScrollView.content` 上。`content` 的高度由 `Layout` 或虚拟列表算，Widget 再拉一次会打架。
- 虚拟列表（`VScrollView`）的 `itemHeight/spacing` 必须与 prefab 里的 item 尺寸一致；Layout 化后要同步改 `VScrollView` 的配置，否则回收位置会错。
- 三页的 `ListView2/ListView3` 是 `ScrollView` 还是普通节点，实施前要确认；如果是 `ScrollView`，Widget 应挂在 `ScrollView` 节点或 `view` 上，不要挂 `content`。

### 5.2 prefab 保存会重算 `_bottom` / `_contentSize`

工程里已有两次踩坑记录：

- `prefab_edit save` 会按 Widget 当前 `position` 重算 `_bottom`，prefab 里存的 172 不一定是设计值；
- 带 Widget 的节点保存可能改写 `contentSize`，`QueueText` 曾被重算成 `0×30`。

对策：

1. 先写 `_contentSize`，再加 Widget；加完 Widget 立刻读回 `_contentSize`。
2. 保存前把节点 `position` 设成设计态，不要用“先拖到大概位置再靠 Widget 拉”的操作。
3. 保存后 `dump` 一次目标节点，核对 `_lpos/_contentSize/_alignFlags/top/bottom` 四项；不一致就以 dump 结果为准修回。
4. 每次只改一个 prefab，改完立即校验，不要批量保存三个再一起看。

### 5.3 两态布局不能只烘一个位置

`ChestSlot` 的倒计时态/空闲态、`ChestDetailPanel` 的两行态/中心态、`ChatRecruitRow` 的自己/他人态，都是**同一节点两套位置**。prefab 只能存一套，另一套必须：

- 用第二个子节点（推荐，Inspector 可见、无代码魔法）；
- 或 `@property` 双值（差异很小时）；
- 不能“prefab 存 A 态，代码写 B 态”，否则改 prefab 的人永远不知道 B 态在哪。

### 5.4 设计分辨率与长屏

- 工程设计分辨率是 `720×1280`，三页根节点高度由 Widget 拉伸到实际屏幕。代码里不要再用 `view.getVisibleSize()` 当基线；`visibleSize` 在刘海屏/折叠屏上不等于设计高。
- 安全区（刘海、底部横条）用 `Widget` 的 `top/bottom` 运行时覆盖，prefab 只存默认值。不要把安全区高度写成模块常量。
- 长屏适配的目标不是“把 1280 的内容拉满”，而是“顶部贴顶、底部贴底、中间列表拉伸”。三页表里的 `top/bottom` 就是按这个原则算的。

### 5.5 代码删除的边界

- 删除常量前先全仓 `rg` 一次，确认没有测试、生成器、文档引用。例如 `HEAD_ITEM_STEP_X` 被 `tmp/gen_playerinfo.mjs` 和 `tests/playerinfo.test.ts` 引用，不能直接删；要先改生成器与测试。
- `LayerActivityLayout` / `FirstRechargeLayout` 的部分常量同时被测试钉住几何；删除时要同步改测试断言，不能把测试改成“只测存在”。
- `BattleTokenTable.buyButtonPos` 可能被单元测试直接调用；改为读 prefab 后，测试要么改成行为测试，要么保留一个纯函数作为“设计态快照”。
- 工程有 111 个基线失败测试（见 `代码优化事项梳理.md`），本次改动不能用“全绿”作为通过条件；要对照基线，只保证本次相关测试不新增失败。

### 5.6 守卫测试必须先改

三页的旧适配方法不是“没人管”的代码，测试里有**存在性守卫**。直接删方法会让相关测试编译或断言失败；这些守卫本身也在阻止“删了适配但没换 Widget”的半成品。执行顺序必须是：先把守卫改成读 prefab 的 Widget 配置，再删代码。

| 测试 | 断言 | 处理 |

### 5.8 Widget 与 Layout 同节点的冲突

- `PanelBg` 用 Widget 拉伸，内部子节点用 Layout 纵向排：可以，但 Layout 必须在子容器上，不要和 Widget 同节点。
- `RowView` 用 Widget 拉伸，`RowTemplate/RewardBar` 用 Layout 横排：可以，两层分开。
- 如果 `Layout` 的 `resizeMode=CONTAINER` 且父节点是 Widget 拉伸，Layout 会不断改自身高度，Widget 又按父高改回来，形成循环。对策：Layout 节点的 `resizeMode` 用 `NONE`，高度由 Widget 决定；或 Widget 只定宽、Layout 决定高。

### 5.9 运行期生成节点的池化

`HeroFragmentBadge`、`SpawnRegionHint`、`SpendFloat` 抽 prefab 后，优先用现有池化/实例化工具，不要每次 `instantiate` 新节点。战斗内高频创建会带来 GC 与 draw call 抖动；这三处正好都在高频路径上。

## 8. 结论

本次迁移的核心不是“把数字搬个地方”，而是**取消代码里的第二真源**：

- 三页的长屏适配是“Widget 已经在做，代码又在做”，删代码即可，prefab 只补中间面板/列表/底栏的 Widget；
- 宝箱格、宝箱详情、大地图标记、战斗 HUD 是“prefab 已有值，代码又回写”，删回写即可，prefab 只补少量差异值；
- 奖励格、日牌、头像墙、商城段、匹配条是“代码逐格算坐标”，改 `Layout` 后代码只切 `active`；
- 三个运行期生成节点是“没有 prefab 可配”，先建 prefab，再把尺寸/字号/间距迁进去。

按 P0 → P1 → P2 → P3 分批执行，每批用 `dump` 核对 prefab、用 `tsc` + 相关测试核对代码，最终可以把 UI 布局写值压到“数据/动画/世界坐标/安全区”四类，工程不再保留这类设计硬编码。
