# 资源目录扁平化方案

> 状态：未执行（2026-11-16 核对）。`assets/bundles/battle/units/projectiles` 仍有 57 个带 `atlas/` 的子目录；本文是迁移方案，落地按第 7 节执行。
>
> 分析日期 2026-11-16。范围 `assets/**` 的目录层级与资源组织方式。
> 本次为**只读分析 + 迁移方案**，未移动/删除任何资源；落地动作待确认后按第 7 节执行。

## 1. 结论

1. 全工程 **516 个资源目录**，最深 **7 级**（相对 `assets/`）。其中 **133 个目录（占 26%）位于 6~7 级**。
2. 6~7 级目录 **100% 集中在两棵树**：`bundles/battle/units/projectiles`（116 个 6 级）与 `bundles/battle/units/effects`（11 个 6 级 + 5 个 7 级），另加 `bundles/bigmap/image/concept/ui/popup` 1 个。
3. 深度的成因不是"资源多"，而是两条历史习惯：**① 在单元目录里再按资源类型分 `atlas/`、`anim/` 子目录；② 用两层同义分类**（`effects/受击特效`、`concept/ui/popup`）。
4. **关键结论：扁平化这两棵树不需要改任何 prefab 路径字符串。** prefab 自身路径（`units/projectiles/镭射飞龙_普攻/镭射飞龙_普攻`）不含 `atlas/`、`anim/`；`atlas/`、`anim/` 里的碎图与动画靠 uuid 被 prefab 引用。目录收缩后，引用这些 prefab 的路径常量（**16 个脚本文件、46 处**）**一行不用改**，只有 2 个做物理目录断言的测试要跟着改。
5. 明确**不做**的树：`resources/icons/**`、`resources/image/**`、`resources/塔防/音效/**`、`resources/skel/**` —— 它们的路径来自 Excel 表（`item.icon` / `roleProperty.icon` / 卡表 `unitPrefabPath` / `audioConfig`），改目录要连带 `tools/config` 导表 + `tools/ref` 校验，成本远大于收益。

## 3. 过深的五个原因

| 编号 | 原因 | 证据 | 代价 |
| --- | --- | --- | --- |
| R1 | **按资源类型分层**：单元目录里再放 `atlas/`、`anim/` | 57 + 59 个目录为纯类型层；每个单元 +2 级 | 类型已由扩展名与导入器决定，这一层不携带信息；还派生出"pac 放 `atlas/` 里"和"pac 放单元根"两套写法 |
| R2 | **两层同义分类**：`units/effects/受击特效/...` 中 `effects` 与 `受击特效` 语义重叠；`bigmap/image/concept/ui/popup` 中 `concept`、`ui`、`popup` 三层 | `受击特效` 是 `effects` 的子集；`concept/ui` 8 张底图 + `popup` 17 张，本可同级 | 多一级就多一个"该往哪放"的判断点，且图集边界要重新对 |
| R3 | **历史迁移残留，未收口**：同一层四种写法（见 2.3） | `磁电菇_劈雷技能` 双 pac、`射手枪口发射子弹` 孤儿 | 新人照抄哪一套都"看起来有先例"，复制错误结构 |
| R4 | **数据驱动目录"看起来能压，其实不能动"** | `props.item.icon` / `roleProperty.icon` / 卡表 `unitPrefabPath` / `audioConfig` 里存的是相对 `resources` 的完整路径 | 移动要重导 Excel + `tools/config` + `tools/ref` + `pvp_card_check.py`，收益低风险高 |
| R5 | **图集拓扑把目录变成了构建参数** | `auto-atlas.pac` 递归覆盖子目录、禁止父子同放、`image/` 根禁 pac、单页 1024/2048 | 任何扁平化若不同步图集账，就是"构建期切图/糊图"，且运行期零报错 |

## 4. 动之前必须守住的 6 条红线

| 约束 | 依据 | 迁移时怎么做 |
| --- | --- | --- |
| 静态引用按 uuid，不按路径 | `.prefab` / `.anim` 里写的是 `"__uuid__": "a6485d9b-…@f9941"` | 每个文件**连同它的 `.meta`** 一起搬；uuid 不变，prefab 引用自动保持 |
| 路径字符串加载 | `ArtPaths.ts`、`ZCGameResourcePlan.ts` + 16 个脚本文件里的 46 处 `units/projectiles|effects` 常量 | 本次只删 `atlas/`、`anim/` 层，prefab 路径不变 ⇒ 常量不动 |
| bundle 路由按前缀 | `core/asset/BundleCatalog.ts` 的 `BUNDLE_DIRECTORIES` | 只在本 bundle 内搬，顶层目录（`units`/`image`/`ui`）不变 ⇒ 前缀继续命中 |
| `loadDir` 需要一个"同类容器"目录 | `ZC_BATTLE_FX_PATHS.hitDirectory = 'units/effects/受击特效'`，`ZCGameLoader` 用它按职业拼 prefab 并入公共预热集 | `受击特效` 这一层**保留**（它承载 loadDir 语义，不是纯容器） |
| 图集覆盖与容量 | `auto-atlas-topology.test.ts`（覆盖/父子同放）、`auto-atlas-capacity.test.ts`（单页容量、单图超尺寸） | 每个单元目录保留且仅保留**一份** pac；删除 `atlas/` 时把 pac 搬到单元根 |
| 测试里写死的物理路径 | `zcds-beam-effect.test.ts`（`${SET_DIR}/atlas/*`、`${SET_DIR}/anim/*`）、`zcds-hit-fx.test.ts`（`HIT_FX_ROOT` 下按 `anim/` 取帧） | 跟着改这两处路径前缀；其余测试用的是 prefab 路径，不受影响 |

## 5. 目标口径

### 5.1 分层原则（一层只表达一个维度）

```
assets/<bundle>/<用途>/<领域>/<单元>/<文件>        # 常态 5 级
                    │       │      └ prefab + 帧 + pac + anim 同目录
                    │       └ 单元名 = prefab 名（`<单元>.prefab`）
                    └ ui / image / icons / units / skel
```

- **类型不进路径**：`atlas/`、`anim/` 一律取消；图集由 pac 声明，动画靠 uuid 引用。
- **pac 命名统一**：每个单元目录一份 `auto-atlas.pac`（不再用 `<单元>.pac`；重命名时 meta 一起改，uuid 保留）。
- **anim 落点**：`<单元>/<单元>.anim`（与 prefab 同名同目录；多动作用 `<单元>-<动作>.anim`，现行 `-loop` / `-once` 后缀沿用）。
- **容器目录只放同类单元**：`受击特效/`（4 个职业）、`projectiles/`（69 个弹道）这类"同构单元集合"保留，它不是类型层，是 `loadDir` / 人眼分组的锚点。

### 5.2 深度预算

| 级别 | 允许 | 说明 |
| --- | --- | --- |
| 1~4 | 常态 | `bundle/用途/领域/单元` |
| 5 | 上限（默认） | 单元目录内直接放 prefab + 帧 |
| 6 | **仅限**"同构单元集合 + 单元" | 当前只有 `受击特效/<职业>受击` 属这一类 |
| 7+ | 禁止 | 出现即说明又加了类型层或同义层 |

迁移后：**目录 516 → 388；≥6 级目录 133 → 5；7 级目录 5 → 0。**

## 7. 迁移方式（不破坏引用）

### 7.1 为什么不会破坏

| 引用类型 | 载体 | 搬动后的状态 |
| --- | --- | --- |
| prefab / scene / anim → 碎图、动画 | `.prefab`、`.anim` 里的 `"__uuid__": "<uuid>@f9941"` | **不变**：uuid 存在 `.png.meta` / `.anim.meta` 里，meta 跟着文件走 |
| 代码 → prefab | 46 个脚本文件里的 `'units/projectiles/<单元>/<单元>'` | **不变**：本次不重命名单元目录、不改 prefab 名 |
| 代码 → bundle | `bundleForPath()` 按 `units/` 前缀路由 | **不变**：`units` 顶层还在 `battle` bundle 里 |
| 代码 → 目录 | `hitDirectory = 'units/effects/受击特效'`，`loadDir` 取 prefab | **不变**：这一层保留 |
| 图集 → 纹理 | pac 在构建期打包，不含引用 | **不受影响**，只需保证每单元仍有一份 pac |

唯一会坏的写法是"删掉 `.meta` 让编辑器重建"——那会生成**新 uuid**，所有 prefab 引用当场断链。**规则：`.meta` 与实体文件必须原子同移，绝不删除重建。**

### 7.2 执行顺序

1. **P0 基线**：`git status` 确认工作区改动可辨识（当前有 celebration/firstRecharge 等未提交改动，**不要**把它们混进本次提交）；记录 `git stash` 或另开分支 `feat/resource-layout-flatten`。
2. **P1 dry-run**：用 7.3 的脚本跑一次（默认只打印，不动盘），核对计划条目数与 M1/M2 的 57/59 是否吻合。
3. **P2 单树试点**：先只做 `units/effects`（20 个目录、113 个文件，改动面最小），跑第 8 节验证；绿了再动 `projectiles`。
4. **P3 执行移动**：加 `-Execute` 真正搬（文件 + `.meta` 成对移动，目录空了再删目录及其 `.meta`）。
5. **P4 特殊件人工处理**：M3（`磁电菇_劈雷技能` 双 pac 去重，先按 uuid 比对确认 prefab 用的是哪一套）、M4（孤儿目录，确认后删除）、M9/M10（补 pac，从同 bundle 的兄弟目录复制一份 `auto-atlas.pac` + `.meta`）。
6. **P5 编辑器重导入**：Cocos 里刷新 `db://assets`（或用 Funplay Cocos MCP 触发），确认没有"missing spriteFrame"、`atlas/` 目录不再出现在资源面板。
7. **P6 收口**：改第 4 节列的两处测试路径，提交（`git` 会自动识别为 rename，历史可追）。

### 7.3 迁移脚本（默认 dry-run）

放在仓库根执行；`-Execute` 才真正移动。脚本只做"上提一层"，不改名、不删非空目录。

```powershell
# 资源扁平化：把 <单元>/atlas/* 与 <单元>/anim/* 上提至 <单元>/，.meta 与实体同移
param([switch]$Execute)

$ErrorActionPreference = 'Stop'
$assets  = Join-Path $PWD 'assets'
$unitRoots = @(
    'bundles/battle/units/projectiles',
    'bundles/battle/units/effects'
)

$moved = 0; $skipped = @(); $dirsRemoved = 0

foreach ($unitRoot in $unitRoots) {
    $absRoot = Join-Path $assets $unitRoot
    $units = Get-ChildItem -LiteralPath $absRoot -Directory -Force |
        Where-Object { $_.Name -notlike '*.meta' }

    foreach ($unit in $units) {
        foreach ($type in @('atlas', 'anim')) {
            $sub = Join-Path $unit.FullName $type
            if (-not (Test-Path -LiteralPath $sub -PathType Container)) { continue }

            $files = Get-ChildItem -LiteralPath $sub -File -Force |
                Where-Object { $_.Name -notlike '*.meta' }

            # 双 pac 现场：单元根已有 auto-atlas.pac，且 atlas 里还带 pac -> 交给人工处理
            if ($type -eq 'atlas' -and
                (Test-Path -LiteralPath (Join-Path $unit.FullName 'auto-atlas.pac')) -and
                ($files | Where-Object { $_.Extension -eq '.pac' })) {
                $skipped += "$($unit.Name)（双 pac，需人工去重）"
                continue
            }

            foreach ($f in $files) {
                $target  = Join-Path $unit.FullName $f.Name
                $targetM = "$target.meta"
                if (Test-Path -LiteralPath $target)  { $skipped += "$($unit.Name)/$type/$($f.Name)（目标已存在）"; continue }
                if (Test-Path -LiteralPath $targetM) { $skipped += "$($unit.Name)/$type/$($f.Name).meta（目标已存在）"; continue }

                $pacRename = ($type -eq 'atlas' -and $f.Extension -eq '.pac')
                $finalName = if ($pacRename) { 'auto-atlas.pac' } else { $f.Name }
                $finalPath = Join-Path $unit.FullName $finalName

                Write-Output ("{0} {1}/{2}/{3} -> {1}/{4}" -f `
                    ($(if ($Execute) { 'MOVE' } else { 'PLAN' })), $unit.Name, $type, $f.Name, $finalName)

                if ($Execute) {
                    Move-Item -LiteralPath $f.FullName -Destination $finalPath
                    if (Test-Path -LiteralPath "$($f.FullName).meta") {
                        Move-Item -LiteralPath "$($f.FullName).meta" -Destination "$finalPath.meta"
                    }
                }
                $moved++
            }

            if ($Execute) {
                $left = @(Get-ChildItem -LiteralPath $sub -Force)
                if ($left.Count -gt 0) { $skipped += "$($unit.Name)/$type（未搬空，保留）"; continue }
                Remove-Item -LiteralPath $sub -Force
                if (Test-Path -LiteralPath "$sub.meta") { Remove-Item -LiteralPath "$sub.meta" -Force }
                $dirsRemoved++
            }
        }
    }
}

Write-Output ("`n计划/执行条目：{0}  已删空目录：{1}  跳过：{2}" -f $moved, $dirsRemoved, $skipped.Count)
$skipped | ForEach-Object { Write-Output "  ! $_" }
```

`磁电菇_劈雷技能` 去重前的判定（只读，先用它确认 prefab 引用的是根目录那套还是 `atlas/` 那套）：

```powershell
$set = 'assets/bundles/battle/units/projectiles/磁电菇_劈雷技能'
$refs = (Select-String -Path "$set/磁电菇_劈雷技能.prefab" -Pattern '"__uuid__": "([0-9a-f\-]+)' -AllMatches).Matches |
         ForEach-Object { $_.Groups[1].Value } | Sort-Object -Unique
'根目录套 = (' + (Get-ChildItem "$set" -Filter '*.png.meta' | Measure-Object).Count + ' png)'
Get-ChildItem "$set" -Filter '*.png.meta' | ForEach-Object {
    $u = (Get-Content $_.FullName -Raw | ConvertFrom-Json).uuid
    if ($refs -contains $u) { "被引用(根): $($_.Name)" }
}
Get-ChildItem "$set/atlas" -Filter '*.png.meta' | ForEach-Object {
    $u = (Get-Content $_.FullName -Raw | ConvertFrom-Json).uuid
    if ($refs -contains $u) { "被引用(atlas): $($_.Name)" }
```
