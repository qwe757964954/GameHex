## 4. 保留项与理由

| 保留项 | 理由 |
| --- | --- |
| `CardPreviewScale` 的 `Math.max(1, sourceHeight * visibleRatio)` | 纯函数对 0/负数输入的除零护栏，不是「源高度默认值」；调用方已保证 36 套 runtime 高 > 0。测试 A3 明确要求 0/负数不出 `Infinity`。若未来要求「源高为 0 必须报错」，应在调用方入口校验，不应删掉纯函数护栏。 |
| `CardUnitPreview.show` 的「缺 `spine` / 缺 Skeleton / 缺 SkeletonData / height<=0 / 缺 idle」抛错 | 一次性生产方契约校验，不是数值兜底；B4 已固化。`show(null)` 仍返回 false，保留「prefab 加载失败」的真实可空状态。 |
| `CardUnitPreview.clear` 的 `this.visual?.destroy()`、`show` 早退的 `this.visual?.isValid` | `visual` 是真实的「未建立预览」可空字段；不是必填组件。 |
| `ZCUnitView.visualNode?.`、`visualSkeleton?.getCurrent`、`healthBar.barSprite?.` | 对象池复用/轮廓副本未建立时确实可为空；`barSprite` 是引擎 ProgressBar 的可选字段。 |
| `ZCHexView` 的 `neutralResourceFrames?.get`、`ruinsFrame ??=`、`buildingFrameResolver?.(...)`、`groundGlowBaseSize` | 资源帧表可能未加载、`groundGlowBaseSize` 在 `onDisable` 会清空，均为真实生命周期/查表可空。 |
| `MonthCardGiftEntry` 的 `onBuy?.` / `onClaim?.` | 组合层注入的可选回调，未注入是合法状态。 |
| `ZCUnitView.gateScale ?? 1`、`castLiftPx ?? 0`、`completedAttackCount ?? 0` | 对局定义/表现参数的可选业务字段，缺省 1/0 是语义默认值，不是组件兜底。 |
| `HeroObtainPage._preview?.`、`frames.* ?? null` | 预览懒创建；帧加载失败返回 null 是合法状态。 |

## 7. 工作区边界与未覆盖风险

1. 工作区为 Git + SVN 双库且 dirty，存在大量并行未提交改动；本轮保留既有改动，未格式化、未回退无关文件，只改上述源码/测试。
2. `CardUnitPreview.show` 的 API 语义：`prefab === null` 仍返回 false；结构/数据错误改为抛错。`LineupBoardSlot`、`CardUpgradePage` 等调用方不检查返回值，坏资源会直接暴露而不是静默退回静态图。若产品要求「未来非 Spine 资源也静态兜底」，应新增显式资源类型分支，不能靠「有没有 Skeleton」猜测。
3. `CardPreviewScale` 的 `Math.max(1, ...)` 仍会把 0 源高变成有限大系数；当前调用方已保证 > 0，测试 A3 只要求不产生 Infinity。该护栏是否改为「0 源高直接抛错」需产品/调用方口径确认。
4. 29 处 `getComponent(...)?.` 与 35 处尺寸 `??` 中，仍有 §5 列出的证据不足项；本轮未修改，未声称全部核实。
5. 全量测试 155 条失败仍存在，归属为并行工作区/配置基线，本轮未处理；提交前需由对应改动负责人收口。
