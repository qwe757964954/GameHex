4. **不引入大而全工具类/基类/单例**。所有方案都是“窄函数/既有 core 件/既有加载器”，不新增页面基类，不改 MVC 归属。
5. **证据不足标“待确认”**；不估算没有依据的性能、耗时、token 收益；不做全局格式化。

if (!this.alive) return;

**全部相关使用方**

- `onRewardCompleted`（5 份 95 字符完全相同）：`LeagueDiscountPage.ts:436`、`LeagueNorthExpeditionPage.ts:376`、`LeagueNorthRewardPage.ts:261`、`LeagueStorePage.ts:200`、`LeagueTaskPage.ts:406`；

**为什么值得精简**

不是“6 个短函数看着像”，而是这 6 处共同承载**同一个用户可见契约**：`alive` 后置守卫、`ok` 才 `reload`、`offline` 与其它结果各给一条固定提示。任何一处改动（例如新增 `timeout` 提示、把 `reload` 改成带 revision 的重读）都必须同步 6 个文件，漏一处就出现“同一联盟操作在不同页提示不同”的分歧。`Join`/`Controller` 的变体证明这层契约确实存在，只是 6 个页面恰好一致。

**最小完整修改方案**

1. 新增一个窄模块 `assets/script/app/league/LeagueWriteFlow.ts`（单函数，无类、无基类）：

   ```ts
   import { FW } from '../../framework/FW';
   import type { LeagueRequestResult } from './LeagueRepository';
   import { LEAGUE_TIP_FAILED, LEAGUE_TIP_OFFLINE } from './LeagueTexts';

   export async function settleLeagueWrite(
       result: LeagueRequestResult,
       alive: boolean,
       reload: () => Promise<void>,
   ): Promise<void> {
       if (!alive) return;
       if (result === 'ok') {
           await reload();
           return;
       }
       FW.showTip(result === 'offline' ? LEAGUE_TIP_OFFLINE : LEAGUE_TIP_FAILED);
   }
   ```

2. 6 个页面的 `afterWrite` 方法体替换为：

   ```ts
   private afterWrite(result: LeagueRequestResult): Promise<void> {
       return settleLeagueWrite(result, this.alive, () => this.reload());
   }
   ```

   保留方法名与 `private` 修饰（测试和调用链仍以方法为锚点）。
3. **保留** `beginWrite` 与 `onRewardCompleted`：前者是页面本地 busy 闸门，后者是 `EventMgr.on(..., this)` 的绑定对象，抽工厂反而更长；`Join`、`Controller` 不动。
4. 同步测试：`tests/league-task.test.ts:1143-1145` 现在直接读页面源码断言 `if (result === 'ok')` 与两个 tip 常量。改为读 `LeagueWriteFlow.ts` 断言同一契约，或断言页面源码含 `settleLeagueWrite(`；`tests/league-north.test.ts:767`、`tests/league-apply-edit.test.ts:779` 只断言 `beginWrite`/`busy`，不受影响；`tests/reward-popup-wiring.test.ts:232` 只断言事件订阅，不受影响。

**需要保留的行为边界**

- `alive` 判断必须在 `reload` 之前；`ok` 只 `reload`，不弹 tip；`offline` 与 `failed` 的提示文本保持 `LeagueTexts` 唯一来源；
- `busy = false` 仍由 `onRewardCompleted` 的 `finally` 负责，共享件**不碰** busy；
- `Join` 的 `notifyJoined`、`Controller` 的 `ILeagueRewardResult` 分支保持原样；
- `LeagueRepository.ts` 当前是 M（在途），`LeagueRequestResult` 类型若被调整，先以最新版为准再落地。

**风险**

低。新增文件只被 6 个页面依赖，无循环（`LeagueRepository` 不反向依赖页面）；唯一明显改动是 `league-task.test.ts` 的源码文本断言。

   /** 品质档位 → 相对 image/ 的路径（不带 /spriteFrame；给控制器级 loader 用）。 */
   export function itemQualityFrameRelPath(quality: number): string {
       return `${ID_ART_ROOT}/${qualityFrameArtPath(qualityFrameSuffixOf(quality))}`;
   }

   /** 品质档位 → resources.load 用的完整装配路径。 */
   export function itemQualityFramePathOf(quality: number): string {
       return spriteFramePathOf(itemQualityFrameRelPath(quality));
   }

   /** 品质档位 → 模块缓存取图。 */
   export function loadItemQualityFrame(quality: number): Promise<SpriteFrame | null> {
       return cache.load(itemQualityFramePathOf(quality));
   }

   - `RoleArtLoader.ts:115`、`ItemDetailPage.ts:287`、`GetHeroEntry.ts:67`：`loadItemQualityFrame(quality)`。

| 方法 | 行 | 重复内容 |

**为什么值得精简**：4 个方法的守卫条件、response 捕获、`sent && !isDisposed && isOwnerCurrent()` 收口完全同构；任何一条生命周期规则变化（例如新增 `net.isConnected` 之外的通道状态）都要改 4 处。`requestMove` 的 `allowRetry=false`/5s 过期是写操作特有，应该作为参数而不是再写一套骨架。

**最小完整修改方案**

1. 在 `GameNetBigMapCampGateway` 增加私有入口：

   ```ts
   private async send(
       make: (receive: (rsp: unknown) => void) => RequestMsg<unknown, unknown>,
       expiresMs?: number,
   ): Promise<unknown> {
       const net = GameNet.instance;
       if (this.isDisposed || !net.isConnected || !this.isOwnerCurrent()) return null;
       let response: unknown = null;
       const request = make((rsp) => { response = rsp; });
       if (expiresMs !== undefined) {
           const expiresAt = Date.now() + expiresMs;
           request.canSend = () => !this.isDisposed && this.isOwnerCurrent() && Date.now() < expiresAt;
       }
       const sent = await net.send(request, false);
       return sent && !this.isDisposed && this.isOwnerCurrent() ? response : null;
   }
   ```

**需要保留的行为边界**

- 三个前置守卫的顺序与含义不变；`isOwnerCurrent` 在 send 前后各判一次；
- `response` 只在 `sent` 且未 dispose/owner 未切换时返回，否则 null；
