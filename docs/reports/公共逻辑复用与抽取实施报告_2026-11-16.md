## 3. 改造后的组织方式

```text
core（纯 TS）
  value / types / time / math / layout / table / text / config
        ↓
app/common（cc / 资源 / UI 公共件，禁止 import app/<feature>）
        ↓
app/<feature>（只保留 feature 私有解析、文本、布局、页面辅助）

app/net（协议 / 请求 / 超时 / 状态，禁止 import app/<feature>）
        ↓
app/<feature>
```

依赖规则：

- `core` 不 import `cc` / `framework` / `app` / `platform`，不直接 I/O，不取全局单例。
- `app/common` 不 import 任何 feature；需要跨 feature 的件先移到 `common` 或 `core`。
- `app/net` 不 import 任何 feature；feature 之间不通过“公共件”互相 import。
- 不为目录整齐新建 `Utils.ts` / `Common.ts` / `Manager.ts`；按职责命名，一个文件一件事。
- 迁移期只允许一层 re-export；禁止多跳转发。

## 5. 后续复用规范

1. 新增公共件前先搜 `assets/script/core`、`app/common`、`app/net`，确认没有同义实现；被两个以上 feature 使用的件禁止留在 feature。
2. 只是“结构像”时，先列输入、输出、错误、边界、重复键差异表，再决定是否抽取；同名不同义不合并。
3. 纯逻辑进 `core`，cc/资源/UI 进 `app/common`，网络/协议进 `app/net`，feature 私有逻辑留在 feature。
4. 入参用 `unknown` 收边界，内部窄化；返回类型显式；接口/类型用 `I` 前缀；常量用 `UPPER_SNAKE_CASE`。
5. 不堆 boolean 参数，用 options 对象；默认值写在签名上并注释业务口径。
6. 不静默吞异常；需要降级时由调用方显式选择 `safe` 版本。
7. 不改变公开导出名；迁移期用 re-export，并在注释写退场条件。
8. 公共件测试直接 import 真源，不复制算法；源码文本断言只钉接线，不钉函数体实现。
9. 审查时检查：feature 反向 import、`common -> net` 反向依赖、重复 `readRows` / `asRow` / `toCount` / `easeOutCubic` / `clamp01`、同值常量散落、同形 `*RequestResult` / `I*Reward` 新定义。
