## 2. 公共实现落地

本轮没有扩大公共工具抽取范围，只做收尾与契约修正：

| 模块 | 本轮动作 | 边界 / 行为 |
| --- | --- | --- |
| `core/value/Coerce` | `toCount(value, fallback = 0)` 增加可选 fallback | 默认仍为 0，旧调用语义不变；Long 先取 `low/high`，与 `TimeMs.toMillis` 的 `toNumber()` 优先级不同 |

## 7. 语义边界（待核实，不认定为缺陷）

以下差异按原契约保留，未在本轮合并：

1. **奖励数量是否只允许整数**：`RewardRows` 默认 `minNumber = 1` 只表达“小于 1 丢弃”，正小数（如 1.5）是否属于合法数量需按业务契约确认；不能把 `minNumber = 1` 当作“只允许整数”的证明。
2. **缺失 / 非法 / 显式零**：`toCount` 可能把缺失、非法和显式 0 都归一为 0；`minNumber = 0` 不能描述为“仅保留显式零”，需按调用场景分别测试。
3. **`toCount` 与 `toMillis` 的 Long 差异**：`toCount` 先取 `low/high`，`toMillis` 先取 `toNumber()`；两者不能因代码相似再次合并，差异说明保留在对应实现处。
4. **三种 `parseItemRows` 的重复键 / 默认品质**：itemdetail、gift、activity 等调用方的重复键策略和默认品质不同，本轮未强行统一；需要按各表契约分别补测试。
5. **文本占位缺参 / null**：`Placeholder` 通过 `missing` / `nullish` 选项表达不同口径；`GiftTexts` 当前是 `missing: keep`、`nullish: string`，不代表其他调用方相同。
6. **`readRefRowsSafe` 适用场景**：只用于允许空数据降级的读表；必需配置读取失败仍应走 `readRefRows`，不能用 safe 版本掩盖失败。

## 9. 改造后的组织方式

```text
core（纯 TS，不 import cc/framework/app/platform，不做 I/O/全局单例）
  value / types / time / math / layout / table / text / config
        ↓
app/common（cc/资源/UI 公共件，禁止 import app/<feature>）
  TableRead / RewardIcon / RewardEntries / ResTypes / QualityFrameLoader / TaskOrder / PayChannelRows
        ↓
app/<feature>（feature 私有文本、布局、业务函数；公共符号直接指向 common/core）

app/net（协议、请求、超时、状态；禁止 import feature）
        ↓
app/<feature> 的 repository / gateway
```

迁移期兼容规则：

- 只允许一层 re-export；禁止多跳转发；同一符号不得同时存在两个公共入口。
- 仍承担业务职责的文件不因“路径不纯”整体删除；只删除无调用方的公共转发符号。
- 业务别名（如联盟奖励图标、挂机资源根）保留语义，不强行并入 `common`；新增调用禁止走旧路径。
- 兼容导出统一注明 `@deprecated 请从 common/... 导入；调用方及测试迁移完成后删除。`，行为差异写在策略处，不重复整段迁移史。

## 10. 后续复用规范

1. 新增公共件前先搜 `assets/script/core`、`app/common`、`app/net`；被两个以上 feature 使用的件禁止留在单一 feature。
2. 仅“结构相似”时先列输入、输出、默认值、错误、重复键、空值/缺失口径差异表；同名不同义不合并。
3. 纯逻辑进 `core`，cc/资源/UI 进 `app/common`，网络/协议进 `app/net`，feature 私有逻辑留在 feature。
4. 公共函数入参用 `unknown` 收边界，内部窄化；返回类型显式；接口/类型用 `I` 前缀；常量用 `UPPER_SNAKE_CASE`。
5. 公共奖励入口统一 `common/RewardEntries`，公共图标解析统一 `common/RewardIcon`，品质框统一 `common/QualityFrameArt`；禁止再经 feature re-export。
6. `TableRead.readRefRowsSafe` 只用于允许空数据降级的表；必需配置失败必须让错误可见。
7. 视图按钮统一只绑 `Button.EventType.CLICK`；不再引入 CLICK/TOUCH_END 分流 helper，prefab 必须挂 `cc.Button`。
8. 改动公共契约时同步补行为测试和源码守卫；禁止只改注释或只改测试单侧。

## 11. 结论

本轮完成了“迁移收尾、契约验证、注释纠偏”的指定范围：公共真源已落地，指定的跨 feature 公共 import 已收口，`ClickBinding` 已退场，firstRecharge/gift/guide 延后文件已接入公共件，关键注释和方案状态已纠正。

但不能声明仓库全绿：`npm run verify` 与 `npm run verify:full` 仍有当前工作区并行改动导致的新增失败；这些失败的证据已在本报告列出。下一轮只需在工作区稳定后重跑门禁，并按第 8 节完成剩余兼容层/边界项，不需要继续扩大公共工具抽取范围。
