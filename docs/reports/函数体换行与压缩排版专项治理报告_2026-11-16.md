判断规则与结论：

1. **生产代码（`assets/script`）没有必须展开的压缩函数。** 372 处 B 中最长为 109 字符、仅 1 条语句（`MainTabsComposition.ts` 的 telemetry 箭头）；≥3 条语句的只有 3 处，均为 63–75 字符的短方法：`CardUpgradeModel.confirm:29`、`LineupBoardModel.selectPreset:30`、`LineupBoardModel.reset:68`。按“未触及的历史单行函数不强制批量展开”，本轮保留。
2. **测试替身与短回调保留。** `tests` 的 1438 处中 1465 处是单语句、407 处为双语句，典型形态是 `deferred()` 延迟器、`Node.addComponent / setParent` 等 mock、`cache.load` / `sprite` / `label` 的桩。这些属于任务明确要求不直接认定为错误的“简短回调和测试替身”。
3. **开发工具脚本的历史紧凑写法保留。** `tools` 的 138 处集中在 `tools/map-editor/*.js`；>120 字符的 8 处长体量项全部在 `tools/map-editor/territory-app.js`，例如 `save`（455 字符 / 11 条语句，第 936 行）、`publish`（251 / 5，第 937 行）、导出按钮回调（315 / 6，第 1092 行）。该文件是本地地图编辑工具，不进入游戏构建，且整文件均为紧凑风格；只展开个别函数会制造不一致，本轮不触达。
4. **B 类不阻断。** 检查器只把 B 作为报告项；门禁只拦 A。

如后续希望治理开发工具的长单行函数，可单独发起一次 `tools/map-editor` 排版变更，仍用同一检查器的 `--list-b` 与 AST 指纹对比。

## 4. 防复发：规则、检查器与门禁

### 4.1 规则位置（单一真源）

- `docs/agent/开发细则.md` → 「代码风格与交付」新增一条：
  - 新增或修改的具名函数、方法、构造函数、getter/setter 及块体回调，非空函数体从下一行开始；不得为减少行数把首句拼到签名后。
  - 简单表达式箭头函数（`x => x.id`）可保持单行；未触及的历史单行函数不强制批量展开。
  - 门禁命令：`npm run verify:layout`（A 类阻断、B 类仅报告）。
- `AGENTS.md` → 「按需读取」既有入口行改为：`引用、类型、命名、风格、函数体换行 | [开发细则](docs/agent/开发细则.md) 的引用与类型、命名与风格、代码风格与交付`。只引用、不复制规则正文，避免两处维护。

### 4.2 检查器

| 文件 | 作用 |
| --- | --- |
| `tools/verify/function-body-layout.mjs` | AST 检查器：`scan` 全量报告、`check` 增量门禁、`baseline` 快照、`compare` AST 指纹对比 |
| `tools/verify/function-body-layout.d.mts` | 类型声明，供测试直接 import |
| `tests/function-body-layout.test.ts` | 12 条最小护栏 |

检查覆盖：函数声明、方法、构造函数、getter/setter、函数表达式、块体箭头函数。字符串与注释是 trivia，AST 不会把它们当函数；`interface` / `type` 声明没有函数体，对象字面量属性不会被当成函数。B 类单独标注、不阻断。

### 4.3 基线口径

- 基线文件：`tmp/verify/function-body-layout-baseline.json`（本地快照，`tmp/` 不入库）。
- 身份：`文件 + 限定名 + 类型 + 形参原文 + 同名序号`，**不含行号**；函数整体平移不会误判。
- 没有基线文件时，回落到 VCS 中该文件的上一版：`git show HEAD:<file>`，失败再 `svn cat`；两边都拿不到时按新增处理，并打印“无可比基线”，不允许“比较不了 = 通过”。
- 改动集：`verify.mjs` 的 `changedFiles()`（优先 SVN）与 Git `status --porcelain` 的并集，覆盖本仓库“父目录 SVN + 本目录 Git”双库场景。

### 4.4 门禁接入

- `package.json` 新增 `"verify:layout": "node tools/verify/function-body-layout.mjs check"`。
- `package.json` 的 `verify:guards` 追加 `node tools/verify/function-body-layout.mjs check`（`verify:guards` 是代码审查规范 G1 命令序列中的护栏单一入口）。
- `verify:guards` 用例清单加入 `tests/function-body-layout.test.ts`，并同步 `tests/verify-gate.test.ts` 的 `GUARD_TESTS` 期望集（G7 防止两份清单漂移）。
- 未改 `verify.mjs` 的三道门结构（`route → defs → check`）：主路由只筛 `ts/json/prefab/meta`，`.mjs` 检查器改动的用例由 `verify:guards` 固定带上，不为此改动门禁契约。
