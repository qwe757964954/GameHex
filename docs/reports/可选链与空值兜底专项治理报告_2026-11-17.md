## 2. 判据

一条 `?.` / `??` 只有在下列三条**同时**成立时才改：

1. **类型上是必填**：声明没有 `?`，也不含 `| null` / `| undefined`；
2. **生产侧恒写**：构造点、解析点或协议映射处无条件赋值，且能列出具体位置；
3. **无「未就绪 / 未命中 / 旧存档」分支**：调用链上不存在加载中、查表未命中、老数据缺字段等可达路径。

反过来，下列情形一律保留：

- 查表 / `Map.get` / `find` 的未命中（`RefUtil.getRef` 在资源未加载时直接 `return`，见 `framework/ref/RefUtil.ts:161-163`）；
- 协议回包可选字段（`rsp?.tlCmdGoods`、`row as { id?: unknown }`）；
- 引擎对象与生命周期（`node?.isValid`、`getComponent(...)?.`）；
- 可选参数、可选依赖注入（`options?`、`deps.slgRepository?`）；
- 旧存档 / 异步快照兼容（`TerritoryProgressData` 全字段可选、`ZCSnapshotCodec` 的 `??=`）；
- 对 `0` / `false` / 空串有业务含义的 `||` 与三元判断。

## 3. 已修改项（必有依据）

### 3.1 `territory/model/TerritoryProgress.ts:135,148,149`

| 原写法 | 新写法 |
| --- | --- |
| `for (const cell of state.passCells ?? [])` | `for (const cell of state.passCells)` |
| `if (options?.replaceUnlocks && (state.unlockCells?.length ?? 0) > 0)` | `if (options?.replaceUnlocks && state.unlockCells.length > 0)` |
| `for (const cell of state.unlockCells ?? [])` | `for (const cell of state.unlockCells)` |

**必有依据**

- 入参类型即契约：`applyServerState(state: { readonly unlockCells: readonly number[]; readonly passCells: readonly number[] }, ...)`，两个字段都是必填数组。
- 生产侧全部显式给两个字段：
  - `TerritoryModel.ts:1942` 字面量 `{ unlockCells: [], passCells: cellIds }`；
  - `TerritoryModel.ts:1992` 传入 `ITerritoryCellState`（`unlockCells` / `passCells` 均为必填）；
  - `tests/territory-cell-protocol.test.ts` 12 处、`tests/territory-progress.test.ts` 7 处调用，全部显式给出两个字段。
- 「只讲通关的广播」这条业务路径也**显式传 `unlockCells: []`**（`tests/territory-progress.test.ts:170-176` 固化该口径），说明调用契约本就是「必填、可空数组」，不是「可省略」；`?? []` 反而把「忘了传」和「传了空」混为一谈。

**保留** `options?.replaceUnlocks`：`options` 声明为可选参数，属真实可空。

### 3.2 `zcds/model/systems/ZCAttackResolutionSystem.ts:359-362,368`（`castFanSkill`）

| 原写法 | 新写法 |
| --- | --- |
| `Math.max(0.1, parameters?.secondaryRadiusScale ?? 1.4)` | `Math.max(0.1, parameters.secondaryRadiusScale ?? 1.4)` |
| `Math.min(180, parameters?.secondaryFanDeg ?? 120)` | `Math.min(180, parameters.secondaryFanDeg ?? 120)` |
| `parameters?.secondaryDamageRate ?? 1` | `parameters.secondaryDamageRate ?? 1` |
| `parameters?.secondaryKnockback ?? 0` | `parameters.secondaryKnockback ?? 0` |
| `(parameters?.secondaryAppliesHitStatus ?? 0) > 0` | `(parameters.secondaryAppliesHitStatus ?? 0) > 0` |

**必有依据**

`parameters` 来自 `context.skillRuntime[owner].get(key)?.parameters`，是**真实可空**（Map 未命中）。但紧接着的守卫

```ts
if (!(Math.max(0, parameters?.secondaryCooldown ?? 0) > 0)) return false;
```

在 `parameters` 缺失时读到 0，`Math.max(0, 0) > 0` 为 false ⇒ 整个 `if` 成立 ⇒ 提前返回。也就是说**能走到第 359 行，`parameters` 必然存在**。守卫保持 `?.`（它正是允许缺失的那一处），守卫之后 5 处 `?.` 属重复兜底。

**保留** `?? 1.4 / 120 / 1 / 0`：`parameters` 是 `Readonly<Record<string, number>>`，键缺失是配置常态，默认值是参数语义而非空值兜底。守卫加了注释说明这条不变量，避免后来者以为可以直接省掉守卫。

### 3.3 `card` 模块：`ZCArmySkill.levels` 非空契约

`CardSkillList.ts:45-46` 的类型注释即契约：「按 `level` 升序的档位；**非空**（没档的行在建表时就被丢掉）」。两处生产侧强制：

- `buildArmySkillTable`：`if (byLevel.size === 0) continue;` —— 没有合法档位的技能不进表；
- `parseArmySkillLevelRow`：`const level = toPositiveInt(row.skilllevel); if (level === null) return null;` —— 档位是正整数，不会是 0 / 负数。

因此下列「空数组 ⇒ 0 / true」兜底是死分支，且会把配置错误伪装成合法结果：

| 位置 | 原写法 | 新写法 |
| --- | --- | --- |
| `CardSkillList.ts:145` | `return skill.levels.length > 0 ? skill.levels[0].level : 0;` | `return skill.levels[0].level;` |
| `CardSkillList.ts:147` | `const max = skillMaxLevel(skill); return max > 0 ? Math.min(current, max) : current;` | `return Math.min(current, skillMaxLevel(skill));` |
| `CardSkillList.ts:157` | `return skill.levels.length > 0 ? skill.levels[...-1].level : 0;` | `return skill.levels[skill.levels.length - 1].level;` |
| `CardSkillList.ts:170` | `if (skill.levels.length === 0) return true;` | 直接 `return !skill.levels.some(...)` |
| `CardSkillController.ts:107` | `levelRow?.desc \|\| lastLevel?.desc \|\| ''` | `levelRow?.desc \|\| lastLevel.desc \|\| ''` |
| `CardDetailPresenter.ts:108` | `if (!skill \|\| skill.levels.length === 0)` | `if (!skill)` |

`lastLevel` 取的是非空数组的末元素，本就是 `ZCArmySkillLevelRow`；`levelRow` 来自 `skillLevelRow()`（按档查找，真实可能未命中），其 `?.` 保留。

**保留** `skills.some(row => row.level === level + 1)` 这类查找：档位可能不连续（配 1/2/4 缺 3），「查不到 ⇒ 满级」是业务规则，不是空值兜底。

## 4. 删除的无用计算

| 位置 | 删除内容 | 理由 |
| --- | --- | --- |
| `CardSkillList.ts:147` | 局部变量 `const max` | 只服务于 `max > 0 ? … : current` 这条死分支，内联后无用途 |
| `CardSkillList.ts:145/157` | 两个 `length > 0` 判断及其 `0` 分支 | 空数组不可达；`0` 会让「下一档」指向不存在的档 |
| `CardSkillList.ts:170` | `levels.length === 0 ⇒ true` 分支 | 同上，且「满级」结论会让按钮无声失败 |
| `CardDetailPresenter.ts:108` | `levels.length === 0` 的第二个条件 | 与 `!skill`（查表未命中）不同源，属重复防御 |
| `TerritoryProgress.ts:135/149` | 两处 `?? []` 及 `?.` 链 | 数组必有；兜底会把缺字段解释成「没有格」 |
| `ZCAttackResolutionSystem.ts:359-362/368` | 5 处 `?.` | 守卫已证明非空，属重复兜底 |

**未删除**：`CardSkillPage.ts:59` 的 `row?.skill.levels.length ?? 0` 保持原样。`render(null)` 是真实可达的关页/无数据路径，`row` 确实可能为空；`?? 0` 是「清空列表」语义而非兜底伪装。这里应保留的正是 `row` 的 `?.`，而 `skill` / `levels` 段本就没有兜底。

## 5. 保留项与理由（按类别）

| 类别 | 命中行数（同一行可命中多类，不做去重） | 代表位置 | 保留理由 |
| --- | --- | --- | --- |
| 默认值与旧存档 / 异步快照兼容 | 1705 | `TerritoryProgressData`（`ownedCells?` 等全字段可选）、`ZCSnapshotCodec` 的 `??=` / `?? 'legacy'` | 存档可能是旧版本；`TerritoryModel.ts:2456-2458` 注释明确「存档还没读到时就当 0，此时 `ready` 为 false」 |
| 引擎对象与生命周期 | 253 | `node?.isValid`、`getComponent(...)?.width`、`camp && camp.isValid` | 节点/组件可被销毁；开发细则禁止用同步生命周期重复判 `isValid`，但跨异步与预加载路径可空 |
| 查表 / Map 未命中 | 147 | `RefUtil.getRef(...)` 调用点、`buildingIdOfQueueAt`（注释「查不到返回 0」）、`this.progress?.`、`this.saveState?.` | `RefUtil.getRef` 在资源未加载时 `return`（`RefUtil.ts:161-163`），`TerritoryModel.map/progress/saveState` 三个 getter 返回 `… ?? null` |
| 可选参数 / 可选依赖 | 90 | `options?.replaceUnlocks`、`deps.slgRepository?.ready` | 类型上就是 `?`，属设计上的可选 |
| 协议回包可选字段 | 68 | `rsp?.tlCmdGoods ?? []`、`(row as { id?: unknown } \| null)?.id` | proto 可选字段与 Long 拆包，缺字段是常态 |

另有两类**显式可选配置**同样保留：

- `TerritoryMapConfig.randomSites?`：`parseRandomSites` 可返回 `undefined`，`this.map.randomSites?.candidateCells.length ?? 0` 是「没配随机点 ⇒ 0 个」；`this.map` 本身还可能是章节未加载时的默认布局。
- `ZCMapConfig.homes?`：与 `playerHomeId / enemyHomeId` 二选一，`map.homes?.length ? … : [playerHomeId, enemyHomeId]` 是配置口径而非空值兜底。

`||` 与三元兜底只在**存在业务 0 / false / 空串语义**处保留（如 `levelRow?.desc || lastLevel.desc || ''`、`union?.name || LEAGUE_INFO_PLACEHOLDER.name`、`Number(...) || 0`）；本轮未发现「必填对象用 `||` 兜底」的站点，未做无证据替换。
