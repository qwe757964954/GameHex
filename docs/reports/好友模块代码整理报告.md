## 2 改动前先确定的边界

1. **测试是硬边界**。`tests/friend.test.ts` 的 D 段是源码文本断言，下列字面被钉死，全部原样保留：`private suggestRaw: unknown[] = []`、`private readonly appliedIds = new Set<string>()`、`private readonly localPatches = new Map<string, IFriendPatch>()`、`const id = toIdString(targetId)`、`if (!id) return Promise.resolve('failed')`、`new RequestFriendsRemove({ targetId: ids }`、`new ${cls}{ targetId`（GetEnd / SendEnd / Black 三条）、`const FRIEND_CHAT_AVAILABLE = false`、`chatAvailable: FRIEND_CHAT_AVAILABLE`、三个页面各自的 `private get alive`、`this.revision += 1`、`this.rowList.renderItemFn =`（在 `onInit` 内、`onOpen` 之前）、`FriendTable.ts` 仅 import `../net/RequestGuard`。
2. **页面类没有运行时测试覆盖**：`cc` 无法在 Node 里加载，三个弹窗与五个行组件的重构只能做「表达式等价 / 分支等价」，**不抽公共基类**去合并三页的 `bind` / `runRequest` / `dispatchRow` / `reload`。该结构重复保留，理由见 §4。
3. **prefab 决定哪些字段不能动**：`@property background` / `headFrame` / `lvTag` 在 `FriendApply.prefab` / `FriendGetEnd.prefab` 里有序列化绑定（`"background": {__id__: 97}` / `51`），磁盘上暂时没人代码消费也必须留着。
4. **行组件的回调对象写法是全仓库约定**：`onAction` / `onChat` / `onCheck` 与 `gift` / `sevenDay` / `activity` 的 Row 组件同款，不改。

## 7 风险与后续

### 7.1 `tests/friend.test.ts` 的改动（如实说明）

测试文件不是「零改动」，共 3 处，都是跟随被整理的字面，不是放宽断言：

| 改动 | 位置 | 原因 |
| --- | --- | --- |
| `FriendTab.list/add/black` → `FriendTab.List/Add/Black` | 29 处 | 枚举成员改名；断言的期望值（0/1/2 与按钮语义）未变 |

| `if (this.appliedId === id)` → `if (this.appliedId === avatarId)` | D9 | 变量改名；「同 id 直接返回」的契约未变 |

A 段（纯函数行为）、B 段（美术常量）、C 段（prefab）、E 段（文案）断言未作任何放宽。

### 7.2 未覆盖风险

- 三个弹窗与五个行组件的改动只经 `tsc` 与源码契约测试校验，**没有运行时验证**（`cc` 无法在 Node 加载）。其中 `FriendRow` 的 `getComponent(Button).interactable`、`FriendTabButton.render` 的直接赋值都依赖「prefab 上这些节点确实挂了对应组件」。若某处 prefab 漏挂，改动前会静默跳过一行，改动后会抛一次异常 —— 这是本次唯一一类「从静默变显式」的行为差异，属有意的失败前置（与工程「不以 `?.` 掩盖错误」的规定一致）。
- `FriendPage` / `FriendApplyPage` / `FriendGetEndPage` 关闭按钮改走 `bind` 后，依赖 `closeButton` 必绑；若 prefab 绑定丢失，点击落空（改动前 `close?.node.on` 同样是空转，故不新增风险等级）。
- 工作树仅保留改动，未提交、未建分支；入库按 `docs/agent/版本库约定.md` 由人工确认。
