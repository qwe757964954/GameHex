## 2. 判据

1. 只有同时满足以下三条才判"重复转换"：
   - 实参的**静态类型已经是目标类型**（`ts.TypeChecker.checker.getTypeAtLocation`，排除 `any`/`unknown`）；
   - 生产侧（构造点、解析点、函数契约）在该值到达本处之前**已经强制成该类型**，能列出具体锚点；
   - 转换后没有额外的语义（不承担 `NaN→0`、`null→''`、跨源 ID 归一、显示格式化）。
2. 反例一律保留：数字 ID 与字符串键互转、协议/Long 编解码、显示格式化、存档清洗、旧表兼容、业务取整/夹取。
3. 不引用 TypeScript 声明单独定罪：本工程 `strict: false`，`row as Partial<IRef…>`、`Record<string, unknown>`、`any` 都很常见，声明可能比运行期乐观。
4. 不机械批量替换，不为统一写法新增抽象；每条建议都给出可回滚的最小改动。

## 3. 配置链路与"类型是否已明确"的事实基础

### 3.1 加载器只还原结构，不做类型转换

CodeGraph 定位到的入口与调用链（`codegraph explore "config json load parse ConfigService"`、`"RefConfigService remoteRef json parse table"`）：

```
assets/remoteRef/*.json（100 张压缩列存 {c:1,k,v} + 51 张行对象数组）
  → RefUtil.loadRefAsset / getAssetData_          framework/ref/RefUtil.ts:462、324
  → tryGetCompressKeyRefData                      RefUtil.ts:367
      → compressKeyRefDataFix                     RefUtil.ts:385（只把 k/v 还原成行对象；仅对 `>}` 重复值做 sv 还原）
      → MergeKeyRefMgr.Merge / RedirectRefMgr.Redirect（结构合并/重定向）
  → RefAssetCache.getRef/getTlRef                  RefUtil.ts:550、577（键统一 toString）
  → RefConfigService.getTable                     platform/config/RefConfigService.ts:24（`as T[]`，无校验）
  → 各 feature 的表解析器（Number/String/toCount …）  ← 归一与校验的唯一位置
```

关键事实：`RefUtil` 与 `RefConfigService` **没有任何数值/字符串强制**，`getTable<T>` 只是把 `any[]` 断言成 `T[]`。因此表解析器里的 `Number(row.x)` 不是"重复转换"，而是"把 JSON 的运行时真值收敛到声明类型"的**唯一**动作——除非该字段由严格解析器二次加工。

### 3.2 生成类型 vs 真实导出值（全量审计）

脚本按 `ref_type_all.d.ts` 的 `interface IRefXxx` 字段声明，对照 `assets/remoteRef/*.json`（压缩表按 `k` 索引还原）逐值比对：

| 指标 | 数值 |
| --- | --- |
| JSON 表 | 152（压缩 100、行数组 51、对象 1 未参与） |
| 匹配到生成类型 | 151 |
| 校验的 number/string 字段 | 953 |
| 声明 number 但出现 string | **1**：`battleTokenConfig.value`（1 行，即 `lotterylevelUpCostEnd` = `"10"`） |
| 声明 string 但出现 number | **1**：`zcGuideParams.value`（1 行） |
| 数值列出现 null | 1：`pvpSkillPlan.value`（156/2209 行） |

对照代码里的显式说明，两处不一致都是**已知**而非生成器错误：

- `BattleTokenTable.ts:231-232`：「`lotterylevelUpCostEnd` 的 value 在表里是**字符串** `"10"`，别假定全是 number」，取值走 `configNum`（`:246-255`，`typeof number` → `typeof string` 再 `Number(v)`）。
- `BattleTokenTable.ts:93`：`key → 原始值` 的注释同样点名该 key。

结论：**"生成类型声明 number" 不等于 "运行期一定是 number"**。这正是不建议按声明批量删除 `Number()` 的直接证据；同时，除这两张表外，当前导出配置的字段类型与声明一致，为"可删"的判定提供了数据面。
