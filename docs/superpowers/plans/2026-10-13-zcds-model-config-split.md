# ZCDS 配置与模型职责拆分

用户已确认按三步渐进迁移，目标是在不改变对局快照、随机消费顺序、公开入口和策划表口径的前提下缩小 `ZCGameRuntimeConfig` 与 `ZCGameModel` 的职责。

## 1. 配置编译

- 把外部表 DTO、数值规则类型和纯解析函数移到专门模块。
- 新建纯函数 `compilePvpTables(tables)`：输入表数据，输出全部已校验的卡牌、单位、技能、地块与规则；错误直接抛出，编译期间不写模块级目录。
- `loadPvpTables` 保留原入口，先编译成功，再安装各运行时目录。原导出做兼容转发。
- 用真实表及损坏表验证成功结果和失败时目录不被污染。
- 成功重载合法空克制表时清除上一次规则，避免本局配置捕获到旧目录。

## 2. 本局预计算

- 从 `ZCGameModel` 构造函数提取纯 `compileZCMatchRuntime(config)`，输出按 owner 分隔的有效单位定义、技能运行时、旧属性、卡牌索引和卡组加成。
- 模型保留随机源、状态、System context、快照恢复与重置；预计算不得消费随机数或读取全局配置。
- 用同种子快照、分帧等价与存档恢复测试验证。

## 3. 逐块迁出战斗细节

- 将强化攻击冷却规则迁至现有 `ZCCombatSystem`，模型仅传入单位、技能配置和当前时刻。
- 将持续区域的波次、范围命中、减速和到期结算迁至 `ZCGroundZoneSystem`；模型通过 context 提供索引、伤害和状态能力，仍在 `advance()` 中决定时序。
- 保留 `sendAttack` 对事件、弹道、状态及伤害的编排顺序；后续更大块迁移可沿同一 `state + context` 边界继续进行。
- 覆盖强化攻击首次不触发、到期触发、快照恢复后的绝对时刻，以及持续区域多波和到期的一次性伤害。
