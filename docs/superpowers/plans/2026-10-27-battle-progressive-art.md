# 首帧优先与渐进战斗特效

使用 executing-plans 在当前绑定编辑器的工作区内执行，不提交。用户已接受入场初期通用表现，沿用此前明确方案。

契约：正式战斗(scope+server battle)的数值、地图、所有必要单位模型、HUD/棋盘/建筑/选点图/卡牌外壳完整后即可进场；专属弹道、公共出生/受击/阵亡/拆建筑特效、地图装饰在真实首帧后才派发，单项完成显式通知视图。规则、随机源、阵容不变。无scope的独立加载/离线旧入口保持全量就绪，便于既有调用兼容。

未就绪的弹道/近战/范围攻击用通用几何，受击用通用闪光；失败保持可用通用表现并告警。本次用户指令覆盖旧“必须全Prefab、不得矢量兜底”的视觉约定，完整素材加载后恢复Prefab表现；不改任何资产尺寸、动画时长和播放速度。已在播的通用特效自然收尾，下一次复用节点重新绑定最新Prefab。

Task 1: 首帧/增强资源契约与加载器。先测试增强任务不阻塞/不提前派发、同一任务重复启动合并、取消后不继续派发、提前捕获真实阵容避免全局配置变更，再实现loadDeferredArt回调及日志。
Task 2: 首帧after-draw接入与显式视图更新。现有ZCGame生命周期负责启动/取消；EffectPool.setArt更新后续事件资源；CombatEffectView按纯now时间提供通用几何，池复用时重新initialize；新增热切换/取消测试，绑定原hit/spawn/渲染生命周期验证。
Task 3: 前台优先队列及8核心外壳保留。AssetLoadOptions.priority传入调度和Cocos，缓存键不包含priority，同路径在途合并升权，排队按priority/FIFO并处理取消。8个外壳用会话scope租约留在64条预算内，退出登录清理。逐项RED/GREEN。

验收：首帧前不派发增强资源；专属弹道未就绪时有通用视觉且不影响伤害；已完成增强按下次事件接入；退出/下一局不受迟到结果影响；资产保留/引用释放和既有表现测试。真实浏览器用同阵容和冷状态量测首帧与完整特效就绪两项，目标3秒左右为待测目标，不作保证。

Review Focus: 延迟任务是否过早排队；类型/读取全局表的时机；池中的旧通用节点是否永久滞留；after-draw是否解绑；会话保留是否重复引用/突破预算；优先级升权/取消是否死锁或重复I/O；旧退出共享帧修复是否保持。
