# 基地连续场景地图实施计划

**Goal:** 使用主基地BG.jpg替换基地旧地面，支持最多20×20逻辑格、拖动缩放和原有建筑操作。

**Architecture:** 基地沿用现有六边形逻辑坐标和服务端位置编号，正常浏览不显示格面。背景、建筑与拾取共用世界坐标；纯函数负责布局和相机边界，组件负责输入与绘制。保留当前5×5默认配置，配置可扩至20×20，不擅自改变线上位置编码。

**Tech Stack:** Cocos Creator 3.8、TypeScript、tsx/node:test、Cocos MCP。

**Spec:** 用户已确认本聊天中“整幅背景、移除旧地面、最大20×20、拖动缩放”的方案。

## 约束与验证重点

- 保留用户现有工作区及默认位置编号；偶数尺寸合法，单边上限20。
- 2048×2048原图通过MCP导入bigmap分包，不重复平铺，不修改源图。
- 拖动、双指缩放、取消事件不能误触建造或收取；相机不能露出地图外部。
- 空地仅在建造/搬移时提示，400格屏外隐藏；无逐帧资源加载、无新tween。
- 资源加载关闭安全、AssetService/ResourceScope归属保持不变。

## 执行

- [x] 布局/配置：先补20×20、偶数尺寸、旧ID、相机边界和锚点缩放测试，再实现固定格距及纯相机函数。
- [x] 资源：通过MCP导入新背景，替换基地加载路径，更新加载回归，旧概念图不再用于基地底图。
- [x] 视图：背景和建筑挂同一内容节点，移除Foundation；接入拖动/缩放、统一拾取、屏外隐藏、进基地定位主城和搬移格提示。
- [x] 验证：运行bigmap相关测试、view-intent-events、callback-owner；MCP刷新与检查导入，运行时视图桩验证手势和收取，检查改动与已知失败。

## 执行记录

- Ruling: 20×20是支持上限，保留既有默认5×5与服务器编号；将默认列数直接改为20会改变旧建筑行列含义。
- Ruling: 整幅有限场景而非重复纹理，原图边缘有独立装饰，不具备可平铺边缘。

- 验证结果：419项相关测试，418通过；唯一失败为既有headquarters.png与概念图manifest的SHA256不一致，与新背景无关。新增场景/相机/手势回归均通过。
- 全局tsc存在仓库/引擎既有诊断，本次改动的BigMapBase/BigMapPage/BigMapConfig/BigMapArt文件无诊断。
- 独立只读review：指定22项测试通过，无有证据的严重/中等问题。
