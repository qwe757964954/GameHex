# bootstrap 装配方式统一

范围：应用启动入口及 login、post-login、matching、main、card、battle 七个组合对象。

## 设计边界

- Composition 通过具名方法创建视图、Model、Controller 和依赖，生命周期入口仅负责步骤编排。
- 依赖按仓库/网络、展示、弹窗、时钟、导航等实际职责组织；本局参数与可释放句柄仍由原宿主持有。
- 先持有或登记清理，再启动异步用例；失败保留原错误并清理已创建对象。
- 退出先断输入并停止控制器，再释放视图与资源；保留登录遮罩及匹配云层的显式交接。
- 沿用现有 ControllerBase、ResourceScope、资源/网络服务，不新增通用组合基类或另一套生命周期。

## 实施步骤

1. 统一依赖契约和调用点，更新直接构造控制器的测试夹具。
2. 将组合对象的大块内联初始化提取成具名创建/适配方法，统一失败和退出顺序；启动入口按服务、框架、路由分步骤装配。
3. 验证各功能行为、装配失败、取消和资源交接，更新架构规范与护栏。

## 已落实

- 各组合入口使用具名创建方法；运行服务按职责分组，同步迁移九个控制器的依赖契约及测试夹具。
- 应用入口拆分服务、展示出口、支付、音频和路由装配。
- 登录、登录后、匹配、主界面和卡牌弹窗按先登记再启动、先控制器再视图资源收尾；异常清理保留原始初始化错误。
- 保留匹配云层和登录遮罩的既有交接方式；新增装配方式护栏、登录失败/迟到弹窗和登录后构造失败回归。
- 同步更新资源 scope、云层交接、加载器归属等直接相关源码护栏；返回焦点验证调用真实入口参数构筑函数。
