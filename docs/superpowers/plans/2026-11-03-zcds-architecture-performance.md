# zcds 架构与性能优化实施计划

**目标：** 按本次审查优先级修复资源生命周期、去除展示层对当前流程的依赖、减少重复派生计算，并补齐可复现的性能测量。

**依据：** 本次聊天中已确认的五项审查意见；`docs/agent/MVC设计规范.md`、`docs/AI架构与代码规范.md` §2、§3、控制器资源归属。

**架构：** 保留 BattleComposition → ZCBattleController → Runtime/Settlement 的装配和释放链。展示资源使用现有 AssetService/ResourceScope；补图需求由展示意图进入运行控制器。模型缓存属于单局实例，连通关系随 terrainRevision 失效；渲染派生值随逻辑步及同步业务操作失效，插值余量每帧更新。

**约束：** 单 Agent、当前工作区；不提交版本库、不修改 prefab/配表/生成文件；不新增平行资源管理器；20Hz、全图最近索敌及平局规则保持。

## 重点边界
- 弹窗关闭而节点尚有效、关闭后重开、加载拒绝与迟到成功。
- 多个同兵种视图同时缺图、两个 owner、运行期释放后返回。
- 开发/破墙/占领改变连通关系；缓存不能混入另一局。
- 未够 0.05 秒的帧只推进插值；同步操作的展示立即刷新。
- 基准哈希覆盖规则及一次性表现；Node 计时不替代 Cocos GC/DrawCall/设备帧率采样。

## 执行结果

五项已实施；具体测量、验证结果与未覆盖项见 [zcds 性能优化](../../zcds-performance.md)。全量扩展检查仍有存量失败；与 HEAD 对照无新增失败/生产类型错误，未修改基线。真实 Cocos/目标设备的 GC、DrawCall 与 FPS 尚未采样。工作区后来出现的 card/阵容相关改动保留，不属于本计划。
