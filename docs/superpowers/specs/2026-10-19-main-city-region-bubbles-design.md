# 自选主城区域气泡提示设计

## 目标

在玩家自选主城时，用地图上的前区、中区、后区气泡表达各区的配置倾向，帮助玩家在落点确认前快速判断区域节奏。玩家能随时收起或重新显示这些气泡，避免遮挡棋盘操作。地图策划可为每个前 / 中 / 后区单独选择「速攻、控场、发育」之一；新区域按深度提供推荐默认值。

## 已确认的产品规则

- 气泡显示在玩家自己的半区，每个已配置的前、中、后区域最多一个；气泡文案是区域名和倾向，例如「前区 · 速攻」。
- 倾向集合固定为 `rush`（速攻）、`control`（控场）、`develop`（发育）。
- 新建区域默认映射为前区速攻、中区控场、后区发育；地图编辑器允许逐区改选。
- 自选主城阶段沿用现有「收回提示 / 显示提示」按钮控制区域气泡；气泡仅提供信息，不拦截格子点击。
- 既有地图缺少倾向字段时按区域深度补默认值，以维持旧地图兼容性。

## 方案与边界

复用地图 JSON 已有的 `regions[].tendency` / `regions[].text` 和客户端 `ZCTendency` 规则，不新增第二套区域数据或状态机。地图编辑器在区域配置工具箱中为每个深度提供倾向选择，并在导入、撤销 / 重做、预设保存和导出时保留选值；未显式选择时使用该深度的默认值。客户端显示文案由既有倾向文案映射产生，避免 `text` 与 `tendency` 不一致时显示过时文案。

自选主城气泡作为棋盘上的表现层覆盖物，由现有 `ZCGameRenderWorld.renderSpawnSelection` 随当前选择阶段和 `hintsVisible` 全量刷新。每个气泡依据玩家半区对应深度的格子中心坐标计算锚点；覆盖物不参与 `ZCSpawnSelection` 的可落点规则、地图格归属或服务器消息。使用非交互的视图元素，保证触摸落到棋盘格。不得在格子内容标签上复用区域文案，以免把区域提示误认为地块属性。

地图编辑器和客户端读取同一份地图 JSON。导入旧图时保留兼容默认；导入含未知倾向值的新图时将其作为配置错误提示，不静默保存成不同倾向。编辑器与运行时文案共用 `rush/control/develop` 的固定映射。

## 主要交互

1. 策划在地图编辑器中配置前 / 中 / 后区格子，并可分别选择速攻、控场或发育；默认值清晰显示，修改后在 JSON 中写入对应 `regions[].tendency`。
2. 进入自选主城阶段后，玩家半区中存在的每个已配置区域显示一个气泡，展示区域名与倾向；未配置或没有可用格子的区域不显示气泡。
3. 玩家点击现有提示开关时，所有区域气泡一起隐藏或显示，按钮文案和箭头维持现有状态语义。
4. 气泡位置固定在区域格子中心坐标的均值上，并在当前棋盘变换下跟随棋盘。它不改变选格、确认、倒计时或网络操作。

## 验收标准

- 前、中、后默认分别显示速攻、控场、发育；任一区域改选后，导出的 JSON、重新导入的编辑器状态和客户端气泡文案保持一致。
- 编辑器导入旧版区域配置、导入 / 导出和撤销 / 重做不会丢失已有倾向；无倾向字段的旧配置使用深度默认值。
- 自选主城时只显示玩家半区实际存在的区域气泡；切换收起 / 显示后与按钮状态同步，格子触摸选择不受气泡影响。
- 确认、倒计时结束、结束选择阶段后气泡按阶段隐藏或清理；重复渲染不会累积节点或残留旧文案。
- 沿用既有地图区域、主城候选和主城确认规则；本功能不改服务端协议。

## 实现与验证边界

实现前按仓库流程检查工作区，保留当前未提交的 `AGENTS.md`、`select_river.json` 和 `tools/map-editor/presets/select_river.json` 改动。地图编辑器逻辑和客户端展示分开验证：覆盖倾向默认值 / 覆写 / 导入导出和旧数据兼容的配置测试；覆盖玩家半区气泡选择、文案、显隐、清理与非交互行为的主城选择视图测试；运行仓库对应的地图配置和主城确认最小测试集。若需修改 Cocos Prefab，必须经 Cocos MCP 定位、修改和刷新验证；优先评估能否复用现有节点树或由视图组件创建轻量非交互覆盖物，避免手改 Prefab。
