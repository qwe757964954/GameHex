# 工程架构迁移清单

更新时间：2026-11-09（联盟创建 / 捐献 MVC 批次收口）。按现有实现排查；登录、匹配、主 tab 已采用外部组合层拥有控制器。本清单描述后续范围，不将待办记成已完成。当前使用情况与本轮升级见[架构使用情况与升级](工程架构使用情况与升级.md)。

统一边界：Procedure 转发流程生命周期，Composition 拥有 Controller、View 和适配器；Controller 编排业务，Model 保存本轮状态和纯规则，View 读取输入、渲染并派发意图。公共机制复用 ControllerBase，不把业务状态塞进基类。

业务弹窗已建立可复用的“每次打开创建组合会话、关闭释放”的外部装配入口（PopupCompositionHost + PopupManager 注入工厂），目前接入卡牌升级、布阵、联盟编辑、联盟创建和联盟捐献。不能为了接入 Controller 又让 PopupBase 子类自行 new/保存 Controller，也不能让 framework 直接依赖 app feature。

RewardItemView 的 ComponentController 目前主要承载展示资源租约；它与业务 Page 持有 Controller 的问题性质不同，后续可改成明确的展示资源契约，优先级低于上述业务拆分。不能因删除字段名而让资源生命周期失去归属。

后续批次：按业务域迁移邮件、好友和玩家资料（联盟业务弹窗本批已收口）。每批沿用已有 Repository 和纯规则，并增加所有权、意图作用域、请求取消与迟到回包测试；未迁移的业务不加入“必须已解耦”的阻断守卫。
