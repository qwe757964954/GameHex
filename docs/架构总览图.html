占城大师 · 架构总览图

Cocos Creator 3.8.8 + TypeScript · 分层架构 / 玩法模块 / 对局数据流

本图为规范的可视化配套，完整规则见 docs/AI架构与代码规范.md，精简入口见 AGENTS.md。

一、总体分层架构（依赖只能从上往下）

app业务层
bootstrap（组合根）、procedure（页面阶段）、各 feature：zcds / login / battle / mail / store / role / league / territory …
职责：业务功能、用例编排、页面阶段；feature 内分 application / model / view / ui。
禁止：不允许在 model 层 import 'cc'；不直连 fetch / resources.load / socket。
▼
platform平台实现
cocos / config（RefConfigService）/ network（FetchNetworkTransport）/ hotupdate / payment
职责：把引擎与外部服务适配成 core 端口；只实现端口，不写玩法规则。
禁止：依赖具体页面、在 adapter 中放业务规则。
▼
core契约 / 纯规则
asset（AssetService、ResourceScope）/ config（ConfigService）/ network（NetworkTransport）/ runtime（GameContext、GameRoute）/ update
职责：稳定端口、纯规则、值对象、资源作用域；纯 TypeScript。
禁止：import cc、framework、app、platform；禁止直接 I/O 与全局单例。
▼
framework通用框架
procedure / fsm / event / ui（PopupBase、PopupManager）/ pool / net / cache / log / task / timer
职责：跨玩法可复用的 UI、弹窗、流程基础设施。
禁止：依赖任何具体 feature 或 Procedure*。
▼
engine引擎入口
EngineMain：平台判断、刘海屏适配等设备能力。
核心规则：framework / core 不得 import app；core 不得 import cc。framework 需要业务能力时，用 FW 上的静态注入槽 （showTip / showReward / pay），由组合根 app/bootstrap/ProcedureBootstrap.ts 注入，未注入时静默丢弃。 页面切换统一 ProcedureManager.navigate(GameRoute.X, params)。

二、玩法模块（zcds）内部结构

ZCGame.ts —— 对局组合根（Component）：创建并连接 model / view / ui；每帧驱动逻辑与渲染。
application 应用层
  • ZCGameLoader（首屏资源）
  • ZCGamePreload（预加载包装）
  • ZCClientCombatConfig（构筑装配）
model 纯逻辑层
  • ZCGameTypes / ZCGameModel
  • ZCSnapshotCodec（快照）
  • ZCGameRuntimeConfig（数值）
  • ZCMapConfig / ZCCombatCatalog
  • systems/ 纯规则系统
view 渲染层
  • ZCGameRenderWorld（渲染世界）
  • ZCHexView / ZCUnitView
  • ZCGameHUDView
  • ZCNodePool / ZCTheme
ui 弹窗层
  • GameRunAway（结算/统计）
  • GameVS / GamePlayerItem
  • ZCGuidePanel（战斗指南）

application 不持有场景节点；model 禁止 import 'cc'；view 只读快照、不裁决规则；ui 继承 PopupBase。 新 feature 按同样四层组织（小功能可不建空层）。

三、对局数据流（每帧）

1逻辑推进 model.tick
固定步长 0.05s（20Hz），单次 tick 上限 5s
  • 累加器按步长 advance()
  • 各 System 依次推进
  • 产出快照 + 瞬时事件
→
2动态层每帧
renderDynamic(model)
  • 单位 / 特效 / 飘字
  • 节点池复用
→
3静态层低频（0.15s）
hudView.render + renderStatic
  • HUD / 地块刷新
→
4结算分支
status ≠ playing
  • 胜利扫场演出
  • 结算弹窗 + 上报
应用/组合 纯逻辑/数值 渲染 弹窗/框架

铁律：渲染层只读 model.snapshot（DeepReadonly）；所有状态变更只能经 model 公开方法发生。 随机由组合根注入（createSeededRandom）、模型唯一消费；冷却时间用绝对时刻，保证同种子可复现。
