# 领地随机资源格开启规则

客户端预览规则在 `assets/script/core/territory/TerritoryRandomResourceRules.ts` 的 `canOpenTerritoryRandomCell`，六边相邻关系来自 `assets/script/core/hex/HexGridLayout.ts`。服务端负责最终校验、扣费、发奖与记录开启状态。

## 当前交互

- 地图起初只显示起点、已开启格及它们六边形相邻的站点或随机候选格。远处格子、据点和开启条件都隐藏；每次解锁后重新计算可见边界。
- 边界上的未开启格显示银币与体力消耗，不提前展示建筑。随机格的银币来自 `randomSites.triggerSilver`，体力来自地图默认 `staminaCost`；固定站点使用自身 `unlock.silverCost` 和 `unlock.staminaCost`。本地条件满足时字色为白色，否则为红色，点击会提示缺少的条件。
- 点击符合条件的格子直接发送 `CmdCityChapterUnlockCellReqMsg`，无需详情弹窗。请求处理中不重复发送。仅在服务端 `succ=1` 后记为已开启；失败时保留原状态。
- 随机格解锁成功即由服务端发奖，客户端显示随机资源建筑，不再发送通关请求。客户端按「解锁即通关」处理：解锁回包 `succ=1` 后，除记账 `unlockCells` 外，还按回包 `cellId` 清单逐格记为已占领（`TerritoryProgress.markCellsPassed`），地块底色立即变绿（`mapOwned`）；不写入 `pendingPassCells`、不发送 `CmdCityChapterPassCellReqMsg`。固定资源点先发送解锁请求，成功后显示宝箱；再次点击才发送 `CmdCityChapterPassCellReqMsg`。通关成功后记为已领取，失败可重试。
- 银币和体力由服务端扣除。客户端读取服务端推送的 `CmdRole` 缓存来更新领地页余额及所有候选格字色，不自行扣费。解锁回包仅含成功标记，没有余额。
- 例如第 1 章格子 346 与已解锁的 326、347 相邻；角色余额满足 10 银币及默认 5 体力时，346 显示白字，可直接开启。

## 协议与数据边界

`CmdCityChapterCellInfoRspMsg.unlockCells` 是已开启格的权威快照，`passCells` 是已通关格。`CmdCityChapterUnlockCellReqMsg` 携带章节号与格子号，`CmdCityChapterUnlockCellRspMsg.succ` 决定开启是否成功。重新进入章节时优先合并服务端快照；断线或请求超时不能推断开启成功。

`randomSites.rewardPoolId` 不参与客户端扣费或发奖。客户端目前只根据解锁成功标记更新地图；奖励结算与 `succ` 的一致性由服务端保障。

同一规则文件里还保留 `selectTerritoryRandomResourceCell` 和旧的 `claimTerritoryRandomResource` 纯规则，用于本地随机位置存档兼容。这些旧规则不限制当前候选格的点击，也不对应当前解锁协议。移除旧位置存档逻辑时，再连同相关测试一起清理。
