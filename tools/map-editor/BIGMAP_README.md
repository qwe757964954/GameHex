# 大地图布局编辑器

三套编辑器并列在 `tools/map-editor/`，各有入口，**互不干扰**：

| 入口 | 页面 | 编辑什么 | 产物目录 |
| --- | --- | --- | --- |
| 对战地图 | `index.html` | 关卡地图（站点/装饰/背景） | `presets/*.json` |
| 章节领地 | `territory.html` | 领地章节（20×20 以内） | `presets/territory/` |
| **大地图** | **`bigmap.html`** | **世界布局（城池/野怪/基地/据点/障碍/地形/势力范围）** | **`presets/bigmap/`** |

```powershell
tools\map-editor\open-bigmap-editor.cmd    # 双击也行：起服务 + 直接打开大地图编辑器
node tools/map-editor/server.mjs --open --bigmap   # 等价的手写命令
node tools/map-editor/server.mjs           # 只起服务，手动访问 http://127.0.0.1:8787/bigmap.html
```

三个编辑器共用同一个服务，靠启动参数决定打开哪个页面：
`open-editor.cmd`（对战地图）/ `open-territory-editor.cmd`（章节领地）/ `open-bigmap-editor.cmd`（大地图）。

---

## 1. 编辑器管什么，不管什么

| 管（存进布局 JSON） | 不管（在别处） |
| --- | --- |
| 城池落位、占格块、环号、势力范围、相邻、编号 | 城池等级数值（战功倍率/占领积分/门槛）→ `BigMap-城池等级` |
| 野怪落点与占格 | 野怪掉落/刷新/战功 → `BigMap-野怪配置` |
| 基地落点（离线调试档用） | 真实玩家基地坐标（服务器下发） |
| 障碍、地形手改、出生区块、活动据点 | 归属、积分、榜、快照、基地防御值 |

一句话：**编辑器决定「东西在哪」，配置表决定「东西值多少」。**

坐标**只写布局**，不要往 `BigMap-城池配置.hexPos` 里填 —— 那边跑一次 eSon 导表就会把编辑器成果静默覆盖回去。

## 2. 操作

| 工具 | 用法 |
| --- | --- |
| 选择 | 点格子看信息；点实体选中它，右侧出属性面板 |
| 城池 | 先在左侧选一个「未放置的城」，再点空地 —— 自动按 `layer` 占 4 格（王座 6 格，选不到空位会提示） |
| 野怪 | 选一个野怪配置，点空地 —— 占格数取配置里的 `occupyHex` |
| 基地 | 点空地放一个 NPC 基地；玩家基地由服务器下发，一般不手摆 |
| 据点 | 挂机资源田 / 地图 BOSS，占 1 格 |
| 出生区块 | 没选中区块时新建一个，选中了就继续往里加格；区块里不能有城/怪/基地/据点/障碍 |
| 障碍 | 点一下加、再点一下去（不能压在城/怪/基地上） |
| 地形 | 选地形后刷格子；**刷回原种子值会自动删掉覆盖**，不占存档体积 |
| 势力范围 | 先用「选择」选一座城，再刷格子；或用右侧「铺范围（半径 N）」一键铺 |
| 擦除 | 删掉该格上的实体 / 障碍 / 地形覆盖 / 出生区块归属 |

右侧面板：改编号、铺/清势力范围、删实体。
左侧批量：给全部城池按半径铺范围、按范围自动推导相邻关系。

> 势力范围目前只是**布局标注**：游戏里的势力范围判定仍走 `radiateCapacity` 距离，
> P1 联盟层做「范围染色 + 进出增益」时才接进规则。别以为刷了范围游戏里就生效。

快捷键：`Ctrl+S` 保存；有未保存改动时关页面会拦一下。

### 快捷键与鼠标（2026-10-20 补齐）

原来只有 `Ctrl+S`，现在与领地编辑器同一套肌肉记忆，另外补了工具切换和删除：

| 操作 | 作用 |
| --- | --- |
| `Ctrl+S` | 保存（校验不过会拦住） |
| `Ctrl+Z` | 撤销 |
| `Ctrl+Y` / `Ctrl+Shift+Z` | 重做 |
| `Esc` | 取消选中，并回到「选择」工具（画图时按一下就能停） |
| `Delete` / `Backspace` | 删除当前选中的城池 / 野怪 / 基地 / 据点 / 出生区块 |
| `1` ~ `9` | 按左侧工具顺序切换 |
| **右键单击** | 该格**擦除**（与领地一致，不用先切擦除工具） |
| **右键拖动** | **平移画布**（100×100 靠滚动条太难受） |

右键「擦除 / 平移」靠按下后的位移区分：移动 < 4px 当单击擦除，超过就变成拖动平移。
在输入框 / 下拉里按这些键不会触发编辑器（已排除 `INPUT` / `SELECT` / `TEXTAREA`）。

## 2.1 出生区块与容量模拟（M3）

用法：选「出生区块」工具，在低级区域连点几格 → 右侧出现区块面板 → 点「算能放几个」。

它会按**最小间距**在区块里撒基地点，把「实测能放几个」和「你填的计划容量」并排列出来：

```
格数 91 格 · 计划容量 40 个 · 实测（间距 2）30 个
容量填大了：按这个间距放不下        ← 红色时就是这个问题
```

算法是**离散泊松采样的贪心版**，三条要点：

1. 「间距 2」= 不能相邻 ⇒ 求的是六边格独立集，**上界正好是格数 / 3**（六边格 3-可着色）。
   所以 91 格最多 30 个，填 40 就是自欺欺人。
2. **确定性**：同一份区块同一间距必得同一结果，改完参数可以直接对比效果。
3. 城/怪/据点/障碍所在的格自动排除（基地不能落在它们上面）。

「批量 → 算全图容量」一次算完所有区块，结果写进右下校验面板，并把撒点画成黄点。
撒点只是**预览**，不进布局文件。

## 2.2 导出

| 按钮 | 产物 | 说明 |
| --- | --- | --- |
| 截图 | `<预设 ID>.png`（2×） | 当前视图整张图，给评审用。**不含背景图**（SVG 光栅化时移除 `<image>`，否则 canvas 被污染会直接抛 SecurityError） |
| CSV | `<预设 ID>-cities.csv` | 城池清单：id/名称/等级/层级/坐标/环/占格数/范围格数/相邻。带 BOM，Excel 打开中文不乱码 |
| 导出 JSON | `<预设 ID>.json` | 当前工作稿原文 |

背景图：左侧「显示 → 背景图」填资源名（相对 `assets/resources`、不带扩展名，如 `image/bigmap/world_01`），
点「应用」。编辑器通过 `/bg/` 路由读工程里的图，所见即游戏里那张。

## 3. 保存 vs 发布

| 动作 | 做了什么 | 落到哪 |
| --- | --- | --- |
| 保存 | 校验 → 归一化 → `PUT /api/bigmap-presets/:id` | `presets/bigmap/<id>.json`（工作稿） |
| 发布到客户端 | 校验 → **与配置表对账** → 写产物 | `assets/resources/config/bigmap-maps/<id>.json` + `.meta` |
| 导出 JSON | 下载当前工作稿 | 浏览器下载目录 |

对账规则：布局里出现的 `cityId` / `monsterId` 必须在 `BigMap-城池配置` / `BigMap-野怪配置` 里存在，
否则拒绝发布（否则进游戏就是「图上有城、表里没数值」）。

命令行发布（同时写策划侧 `doc/塔防数据配置/json/{sever,client}` 两份）：

```powershell
python tools/map-editor/copy_bigmap_maps.py --dry-run
python tools/map-editor/copy_bigmap_maps.py --id world_01
tools\map-editor\copy-bigmap-maps.bat --id world_01
```

校验规则只有一份权威实现（`BigMapLayout.parseBigMapLayout`），python 侧通过
`npx tsx tools/map-editor/validate_bigmap_layout.ts <file>` 调它 —— 不在 python 里抄第二份。

### 发布之后，游戏里怎么生效

客户端启动时（`ProcedureBootstrap`）把 `AssetService` 注入 `BigMapEntry`，
打开大世界时按 `config/bigmap-maps/world_<worldId 两位>` 找布局：

| 情况 | 结果 |
| --- | --- |
| 文件存在且合法 | 世界完全按布局落位（城池/野怪/基地都是策划摆的位置） |
| 文件不存在 | 按种子生成（当前 40×40 的默认地图） |
| 结构非法 / 尺寸与配置表不符 | 打一条 `console.warn`，退回种子生成 —— **不会白屏** |

`worldId` 改了文件名就跟着变（`world_01` → `world_02`），不会误读上一张图。

**改完图想确认游戏里会变成什么样**，不用开引擎：

```powershell
npx tsx tools/map-editor/verify_bigmap_world.ts world_01
```

它打印「已发布布局」与「同种子生成」的差异清单。第一份 `world_01` 是从种子导出的，
所以正常输出是「完全一致」；策划改过图之后，这里就是「动了哪几座城」的逐条列表。

## 4. 从零生成一张底稿

```powershell
npx tsx tools/map-editor/gen_bigmap_preset.ts world_01          # 用当前配置 + 默认种子
npx tsx tools/map-editor/gen_bigmap_preset.ts world_01 12345    # 换种子（地形会变）
```

产物 `presets/bigmap/world_01.json`。写完会立刻读回来重建一遍，逐格比地形/环号/落位 ——
「导出看着对、加载回来偏一格」这种问题不会流到编辑器。

## 5. 几何口径（改代码前必读）

编辑器用**逻辑网格** 36×42（与 `core/hex/HexGridLayout` 一致），客户端渲染用 92.25×90 ——
两者**不是等比**：`x` 放大 2.5625、`y` 只放大 2.142857（底图 130×119 是压扁画布）。

这就是「编辑器里摆 A、游戏里显示 B」最常见的成因。`tests/bigmap-layout.test.ts` 最后一条
断言的就是这两个比值，别去「统一」成一个数。

另外两条踩过的坑：

- 奇数列偏移 → axial 的 `r = row − (column + (column & 1)) / 2`，写成减号会让每格 6 个邻居里
  有一个算成 2 环。
- `territory-format.js` 的 `hexNeighbors` 是另一套 offset 约定，**不要抄到大地图**。
  `tests/bigmap-format.test.ts` 逐格对拍了编辑器的 `hexNeighbors` 与客户端 `hexGridNeighborIds`。

## 6. 校验不过怎么办

右侧「校验」面板会列出全部 issues（一次给全，不是修一条报一条）。常见几类：

| 报错 | 原因 |
| --- | --- |
| `格 N 被 X 和 Y 同时占用` | 两个占位物压在同一格（含障碍） |
| `城池 N 的锚点 M 不在自己的 hexIds 里` | 手改过锚点没同步占格块（删了重放） |
| `尺寸不一致` / 配置表是 40×40 | 布局尺寸与 `BigMap-世界地图配置` 不符，运行时会拒绝加载 |
| `布局里的城池 N 不在 BigMap-城池配置 中` | 配置表删了城 / id 改了，重新放置 |

warning 不阻断保存：相邻关系单向、出生区块容量偏大、配置里有城没在图上。
