# 地图编辑器

Windows 下双击 `open-editor.cmd`，会用 Node.js 启动本地服务并打开可保存的编辑器。也可以在项目根目录手动运行：

```powershell
node tools/map-editor/server.mjs --open
```

服务窗口保持打开时，访问 `http://127.0.0.1:8787/`。默认只画 1 区那一侧（上下镜像），对侧自动生成——**2 人固定这么画、关不掉**；顶栏可以切对局人数（2 / 3 / 4）与主城模式（固定 / 自选）。列数与行数都是 4–60 的任意整数，行数为奇数时中线行镜像到自身。

### 画布几何（改动前必读）

编辑器画布画的是**工程渲染间距的 1:1** —— 画布上一个用户单位就是游戏里一个渲染单位，不是"把逻辑网格等比放大 N 倍"。常量只有一个来源：`assets/script/app/zcds/view/ZCGameViewUtil.ts`。

| | 工程渲染（权威） | 编辑器画布 |
| --- | --- | --- |
| 列距 | `ZC_HEX_COLUMN_SPACING = 84` | `HEX_COL = 84` |
| 行距 | `ZC_HEX_ROW_SPACING = 98` | `HEX_ROW = 98` |
| 列相位 | 逻辑 `ZC_HEX_COLUMN_PHASE = 10.5` × (`98 / 42`) = **24.5** | `HEX_PHASE = HEX_ROW / 4 = 24.5` |
| 格子外框 | `ZC_HEX_VIEW_WIDTH = 112` × `ZC_HEX_VIEW_HEIGHT = 98` | `HEX_R = 56` / `HEX_HALF_H = 49` |

`hex_nor` 原图画布是 **128×128**，有效六边形像素范围是 **112×98**（左右各 8px、上下各 15px 透明边）。蜂窝间距按有效正六边形计算：列距 `112 × 3/4 = 84`，行距 `98`；透明画布不参与拼格。

⚠️ **两侧都别写死系数。** 3 人图的三点等边、`cellAtLocal` 的越界判定这类几何都得**按当前画布现算**：`threeHomes()` 用 `hexCenter()` 的实际像素距离枚举措最优（三边极差最小，并列取更宽的解），不再套一个"每宽 N 列、下移 M 行"的魔数。写死的系数会在几何一变时静默退化——本轮从"逻辑网格 ×2.5"改成 1:1 时就撞上过：旧系数 `1.48462` 让 11×9 的三边极差从 0 涨到 12.6%。

⚠️ 压扁的格子**不能再用"离中心最近"判命中**。`cellAtLocal` 必须**分轴**判越界（`|dx| ≤ HEX_R` 且 `|dy| ≤ HEX_HALF_H`），否则横向 92 的列距配 124 的格宽会让相邻格互相抢点击。

改这几个常量要同步 `index.html` 的 `viewBox` 与 `app.js` 的 `baseHalfW / baseHalfH`。`tests/map-editor.test.ts` 有守门用例：从 `ZCGameViewUtil.ts` 现读常量比对 `window.__editor.geometry`、量相邻格实际距离、并从六边形 `d` 的包围盒断言有效轮廓为 112×98。

## 画图操作

| 操作 | 效果 |
| --- | --- |
| 左键按住拖动 | 连续涂当前笔刷。指针轨迹会按格插值，**拖多快都不掉格** |
| 右键按住拖动 | 临时擦成虚空（不改当前笔刷）；**选中装饰时改为擦掉装饰**，虚空本身不动 |
| 悬停 | 预览这一笔会覆盖哪些格，左下角实时显示 `(行, 列) · 分区 · 笔刷大小` |
| 滚轮 | 以指针为中心缩放（0.4×–6×） |
| 中键拖动 / `空格` + 左键拖动 | 平移画布（不改地图内容） |
| `[` / `]` | 笔刷调小 / 调大（1 格 → 7 格 → 19 格） |
| `0` / 「复位」 | 缩放与平移复原 |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 撤销 / 重做。**一次按下到抬起算一步**（最长 80 步），切人数、改尺寸、载入预设同样进历史 |

笔刷半径按六边形邻接扩散，靠近棋盘边界时自动裁掉出界格。镜像开启时，笔刷落在对侧的格会统一映射到存储侧，再由镜像统一生成。

### 默认底图：全中立格 + 各方主城盘

「清空重画」（以及 3 人图改尺寸时的整体重建）给出的底图是**全中立格**，只在各方主城那一小块上色：

- 上色范围 = 主城 + 6 个邻格（**7 格**）。主城必须落在自己的分区里，所以这几格必然是分区色；它同时就是该方的开局领地（客户端 `ZC_INITIAL_TERRITORY` = 地图上 1 区的格数）。邻格是虚空时跳过，由校验面板提示「压在虚空上」。
- 其余全是 `0`（中立格，可通行、不属于任何分区）。领地、障碍、河道一律用笔刷按需圈画。
- 反过来做不合适：本作地图的中立格占比高，先铺满分区色再一格一格擦成中立，既费事又容易漏。

**主城盘是布局产物，不是策划画的内容。** 切人数、切主城模式（固定 ↔ 自选）时会先收回旧盘（还原成中立格）再给新主城盘上色，所以切到 3 人不会再残留 2 人图那两块"没有主城的色块"（不收的话 11×20 会变成 14 / 14 / 7 这种畸形比例）。收回只认「颜色恰好等于该座位号」的格，策划手画的其它领地与虚空不受影响。

> 镜像开启时收回要按**存储侧**归一化：flat-top 的奇列相位让"主城的 6 邻"在行镜像下不是行对称的，只按邻居表退会漏格。收回逻辑因此同时退原格与存储侧对应格，再由紧随其后的 `applyMirror()` 把非存储侧整片重算。

## 虚空装饰

虚空格（字符画里的 `.`）上可以摆**装饰**：礁石、沉船、残骸这类纯美术点缀，用来让海面不单调。

**唯一硬约束：装饰格必须是虚空格。** 两层含义各有各的实现：

- **约束层** —— 落笔只看宿主格：点在可通行格上会被跳过并提示「装饰只能摆在虚空格上」。反向也守住：把一块带装饰的虚空涂成中立 / 分区色时，该格装饰**自动收回**（`pruneDecor()`）。不这么做就会导出"陆地上摆礁石"的图，客户端只会照画。
- **渲染层** —— 装饰层 `<g class="decorLayer">` 排在所有六边形格之后。SVG 的绘制顺序 = 文档顺序，排在后面才真的"在虚空格上面"；光标预览层再排在它之后。

| 项 | 做法 |
| --- | --- |
| 选装饰 | 左栏「虚空装饰」= **按主题分组的缩略图网格**（3 列 × 44px，见下）；清单里没有的名字可以手填资源名（出图前先排位置用） |
| 摆放 | 点 / 拖虚空格；同样吃笔刷半径（1 / 7 / 19 格），可通行格一律跳过 |
| 擦掉 | 选「不摆装饰」后左键点，或**装饰笔刷下右键**（右键在装饰模式不再擦成虚空） |
| 清单来源 | 服务端 `/api/decor` 扫 `assets/resources/image/decor/`（**递归**，子目录也认），返回 `image/decor/<子目录>/<名字>`；目录不存在就返回空清单 |
| 分组 | 按 `image/decor/` 之后的**第一段子目录**分组；没有子目录的归「其他」，不在资源目录下的自定义名归「自定义」。分组只是"好找"，**不影响落盘** |
| 画布上画什么 | **出了图的画真图**，没出图的画占位菱形 —— 见下 |
| 落盘 | 写进 `art.tiles` 的 `"行,列"` 键，值 = 资源名（**不新增 v3 字段**） |

### 选择器：按主题分组的缩略图网格

`assets/resources/image/decor/` 下已有 **6 个主题目录、35 张 128×128** 的图。竖排文字列表既滚得慢、22px 缩略图也看不出画的是什么，所以面板改成网格：

- 每组一行组标题（主题名 + 张数），组内 **3 列**，每张卡片是 44×44 缩略图 + **末段名**（`image/decor/sea/whirlpool` 只显示 `whirlpool`，全名挂 `title`，悬停可见）；
- 顶部固定一张「不摆装饰」卡片，它不参与分组；
- 分组由 `app.js` 的纯函数 `groupDecorEntries(names, images)` 算（不碰 DOM，`tests/map-editor.test.ts` 直接测它）：组按标题字典序、组内按全名排序 —— 顺序稳定，刷新不跳位。

⚠️ 卡片上写的是**末段名**，但落盘、`/decor/<名字>` 取图、`art.tiles` 里存的**一律是完整资源名**。分组与显示都只是渲染层的事。

### 看得见的装饰：真图 vs 占位菱形

画布上分两路画（`app.js` 的 `decorImages` 决定走哪条）：

- **出了图的**（服务端在 `assets/resources/image/decor/` 真的扫到了文件）—— 画 `<image class="decorImage">`，贴在有效格面 **112×98** 上，`preserveAspectRatio="xMidYMid meet"`（**只缩不裁、绝不拉伸**）。尺寸与工程渲染的格子面一致，所见即游戏里的大小。面板里配 44px 缩略图。
- **还没出图的**（自定义资源名）—— 画占位菱形 `path.decorMark`，颜色按资源名稳定取（同一种装饰全图同色），挂 `<title>` 悬停显示名字；面板里显示同色菱形 + 「未出图」。

✅ **工程侧已接装饰渲染（2026-09-23）。** 链路：`ZCMapConfig` 把 `art.tiles` 结构校验后透传进 `ZCMatchConfig.art` → `ZCGame.installMapDecor()` 读 `model.mapConfig.art.tiles`、按 `/\d+,\d+/` 挑出装饰键、`resources.load` 加载、`ZCGameViewUtil.buildDecorPlacements()` 算摆放 → `ZCGameRenderWorld.installDecor()` 在 `mapLayer` 下铺一层 `DecorLayer`。

装饰层**独立于地块**：虚空格（`playable === false`）在客户端没有 `ZCHexView` 节点，装饰没东西可挂，所以单独铺一层，siblingIndex 夹在**地块之后、建筑与状态条之前**。

贴图口径与编辑器**逐条对齐**（`tests/zcds-decor.test.ts` 钉住）：

| 口径 | 编辑器 | 客户端 |
| --- | --- | --- |
| 缩放 | `preserveAspectRatio="xMidYMid meet"` 贴在 112×98 上 | `decorFitScale()` 取 `min(112/w, 98/h)`；128×128 的图 → 98×98 居中 |
| 用哪张图 | 整张 PNG | `SpriteFrame.originalSize`（原图，不是 trim 后的 `rect`）+ `Sprite.trim = false` |
| 尺寸落点 | SVG `<image>` 贴在格面框上 | `Sprite.sizeMode = CUSTOM` + `UITransform.setContentSize(fit 后宽高)` |
| 位置 | 格心 | `mapToViewX/Y(hex.x/y)`，与地块同一套换算 |
| 层内顺序 | 装饰层排在所有六边形格之后 | 按屏幕位置从高到低（与地块同一套画家算法） |

客户端**不做"只摆虚空格"的二次校验**（照画）—— 这条约束由编辑器守（`pruneDecor()`），所以数据侧必须自洽，`tests/zcds-decor.test.ts` 有一条用例拿 `corset` 的真实数据验这件事。

### 自定义资源名会被记住

手填一个还没出图的资源名（例如 `image/decor/new_reef`）时，`setDecorBrush()` 会顺手 `POST /api/decor`，服务端把它追加进 **`tools/map-editor/decor-library.json`**。于是：

- **刷新页面不用重填** —— 启动时 `/api/decor` 的 `custom` 数组会一起并进清单，点一下就能继续摆。
- **不污染游戏资源目录** —— 记在工具自己的目录里，不会往 `assets/resources/` 塞空文件（那会连带产生 `.meta`，进版本库纯属噪音）。
- **这份文件进版本库**，所以自定义名是**团队共享**的；但它同时是运行时产物 —— 你每次起手新名字都会把这个文件改成 dirty，别顺手 commit 进去。

**没连服务端**（直接双击 `index.html`）时 `rememberDecorName()` 静默失败，名字只留在当前页面；此时左栏提示会明确写「没连服务端，只在当前页面有效、刷新要重填」，不会谎称已保存。

装图后缀：`/decor/<名字>` 会自动试 `.png / .jpg / .jpeg`；名字里已经带后缀（策划手填常见）时按原名原样试一次，不会拼成 `reef.png.png` 而后静默 404。名字必须以 `image/decor/` 开头且不含 `..`，越界一律 404。

**为什么复用 `art.tiles`**：客户端 `ZCMapArt.tiles` 的注释里本来就写明键可以是分区号（`'1'`~`'4'` / `'neutral'` / `'void'`）**或 `'row,column'` 按格覆盖**，解析层也已透传进 `ZCMatchConfig.art`。装饰正好是"按格覆盖"的一种，直接复用就免了改协议、改客户端解析、改三处校验。

透传与装饰**互不顶掉**：载入时把 `art.tiles` 拆成两半 —— `'行,列'` 键还原成装饰，其余键（分区贴图）留在透传里原样保存；落盘时再合并回去。透传里的旧格子键会被丢弃，格子坐标的权威来源永远是当前装饰，避免写出幽灵装饰。

装饰**跟随镜像**：与分区色同一套口径，只写存储侧，对侧由 `applyMirror()` 生成。不然会出现"编辑器里两边都有装饰、导出后只剩一侧"——装饰没有分区号，不会自然对齐。

载入外部 JSON 时压错格的装饰**只丢弃 + 提示格数**，不拒绝整张图：装饰是美术点缀而非玩法数据，为它把一张能用的图挡在门外不划算。

## 地图格式（v3）

`version: 3` 起地图按「分区」存储，字符画 token：

| token | 含义 |
| --- | --- |
| `.` | 虚空（不可通行） |
| `0` | 可通行、不属于任何分区（中立格） |
| `1`~`4` | 属于第 N 分区（分区数 = 对局人数） |

分区号按象限编码：**1 = 下左、2 = 上左、3 = 下右、4 = 上右**（`bit0 = 上下`、`bit1 = 左右`）。

**2 人的上下镜像默认开启，但可以自行关闭**（2026-09-22 从"强制开"改过来）：1 区在下、2 区在上是对峙关系，开着镜像时只编辑下半场、上半场对折生成；关掉就得手画整张场。默认开是因为 1 区格数直接等于该方开局领地（`ZC_INITIAL_TERRITORY`），镜像能保证两家一样多；**允许关是因为摆装饰** —— 对折会把对侧的装饰一起长出来，想摆非对称的礁石 / 沉船就碍事。⚠️ 关掉之后"两家一样多"改由策划自己保证：校验面板只报 warn「各方格数…（不强制相等）」，不拦。**4 人**默认开上下 + 左右镜像，只编辑左下 1/4；**3 人**镜像一律关闭 —— 3 是奇数，矩形棋盘上下翻转、左右翻转都配不出第三块分区，编辑器切到 3 人时强制清掉两个勾选并把「上下镜像」置灰，载入层也拒绝 `mirrorVertical: true` 的 3 人图。

⚠️ **180° 旋转镜像对 2 / 3 人都仍不成立**（2 人的 180° 会把 1 区转到对角 4 区，不是"上下对折"）。这条与"锁不锁镜像"无关，所以在 2 人放开之后必须**单独拦**，三处都各留了一条。

三个校验点（编辑器 `app.js`、网页服务 `server.mjs`、预设生成 `map_format.py`）共用同一口径，绕开编辑器也塞不进不合规的图。口径拆成两个函数、**别混**：`forcedMirror()` = **锁死项**（非 `null` 才不可改，现在只剩 3 人）；`defaultMirror()` = 切人数时落到的**默认值**（2 人上下开、3 人全关、4 人上下 + 左右开）。`sectionAt(row, column)` 是分区判定的唯一入口，切人数、改尺寸都经它重算。

镜像开启时字符画只存 1 区所在的象限：仅上下镜像存下半场（`ceil(行/2)` 行 × 全列），仅左右镜像存左半场（全行 × `ceil(列/2)` 列），两者同时只存左下 1/4；**全不开镜像则存全图** —— 4 人自选、以及 2 人关掉上下镜像之后都是这一种（2 人关掉后 `rows` 就是整场行数，载入时期望行数按 `mirrorVertical` 现算，两种都收）。**四象限建议用偶数列**，否则中线列会镜像到自身（编辑器会常驻提示，不拦截）。

### 3 人标准布局：三座主城必须等边

3 人局的公平骨架只有一条判据——**三座主城的相互距离必须相等**。只要有一条边偏短，短边两方就会提前接触、被第三家坐收。现状若按象限法给 3 人派主城，11×18 上会得到 15 / 8 / 19 的格距（极差 140%）：上点被孤立、下两点贴身，等于给 1 区送人头。因此 3 人改走专门的 `threeHomes()`：

- 分区：上带（`threeBand() = round(行数 / 3)` 行，向上取整）归 **2 区**，剩余 2/3 按列平分给 **1 区（左）/ 3 区（右）**，三块面积近似各 1/3。
- 主城：**上 1 下 2** 的等边三角形。顶点在上 `(col = 中线列, row = 顶行)`，底边两点在 `col = 中线列 ± W`、`row = 顶行 + Δ`。
- 等边条件（本工程 36 / 42 网格推导）：边长 `sqrt((36W)² + (42Δ)²)` 要等于底边 `72W`，解出 **`Δ = 1.48462 · W`**。`W` 取 **偶数** 时 `Δ` 正好是 `1.5W`，等边误差恒定 **0.78%**（`W` 取奇数误差会到 2%~7.54%），所以 `W` 一律取偶数；`COLS` 为奇数时上点才能严格压在中线列上。
- 常见尺寸的解：11×20 → `W=4, Δ=6`（三点格距 8/8/8，像素距约 726）；13×20 同解；17×20、19×19 → `W=6, Δ=9`。棋盘过窄时按 `W -= 2` 收缩，保证主城蜂巢不越界（主城至少离边 1 格）。

**从 2 人旧图切到 3 人时，默认三点只是骨架，内容得重画。** 切人数会保留原有内容、只重排分区编号（《地图编辑器需求文档》3.2），并收回旧的主城盘（见[默认底图](#默认底图全中立格--各方主城盘)），所以一张 2 人图切过去之后，新分区里会残留大片虚空，默认三点可能正好压在虚空上——这时校验面板会逐条报「N 区主城：(行, 列) 压在虚空上」，把那些格补画成对应分区即可。别把它当成 bug：主城默认点只在"布局重算"（新建 / 切人数 / 改尺寸 / 切回固定主城）时无条件给出；只有**用户手工编辑**才会让主城失效（把主城格改成别的分区或虚空）。

这些在 `tests/map-editor.test.ts` 里有 6 条用例守着：等边 + 上点压中线、默认只给三座主城盘上色（铺满时三块面积又近似相等）、常见尺寸都不越界、**三边极差等于独立枚举出的最优解**（守机制，不钉死某个魔数系数）、带虚空的旧图切 3 人时默认三点不被误杀，以及「清空重画只留各方主城盘、其余全是中立格」。

`version: 1` / `2` 的旧地图仍按 `#`（我方）/ `-`（敌方）/ `N`（中立）/ `.`（虚空）载入，再次保存时会升级到 v3。

- 主城：`cityMode: "fixed"` 时写 `homes`（下标 0 = 1 区，每方一座，必须落在本方分区内且位于中线己方一侧）；`cityMode: "select"` 时不写主城坐标，开局走选点流程。
- `regions`（前 / 中 / 后区域 + 打法倾向 + 气泡文案）、`spacing`（主城 / 点位最小间距）、`art`（背景图与地块贴图）目前由编辑器**原样透传保存**（UI 编辑待补），逐项合法性以游戏侧校验为准。
- `resourcePoints` 通过左栏的宝箱、金币、金矿图标笔刷配置：选择图标后直接点击中立格，右键删除；不输入坐标。每格一个资源，且资源点必须落在中立格、遵守配置的最小间距。该配置与 `cityMode` 无关，固定主城与自选主城地图都会保存和导出资源点。

> 地图合法性的**权威判定处**是游戏侧 `assets/script/app/zcds/model/ZCMapConfig.ts` 的 `configureZCMap()`。编辑器与 `server.mjs` 会提前拦截资源不在中立格等关键输入错误；其余玩法规则（分区非空、主城在哪、点位间距、区域不重叠）仍以客户端校验为准。

**新预设可以直接保存。**把顶部 `map-id` 改成一个新的英文、数字、`_` 或 `-` 组成的 ID，点击「保存当前为预设」，会新建 [`presets/<map-id>.json`](./presets)；使用已有 ID 则覆盖对应文件。列表可载入或删除。若从 `index.html` 或 IDE 文件预览打开，保存时页面会给出“在本地服务中继续编辑当前地图”的链接，点击后可保留当前地图并转到可保存的页面。

**拷贝地图不需要 Node.js。**双击 `copy-maps.bat` 会用 Python 3 将 `presets` 中的全部地图拷贝到游戏资源目录。也可在项目根目录使用 Python 命令预览或只拷贝一张：

```powershell
python tools/map-editor/copy_maps.py --dry-run
python tools/map-editor/copy_maps.py --id river
```

脚本保留已有 `.meta`；新地图会生成 Cocos 所需的 `.meta`。游戏每局从 `assets/resources/config/maps/` 里随机选一张 **2 人图**：3 / 4 人图不参与随机，入口是后续的「特定地图开启」（按 id 直接载入）。判据只有一处——`ZCMapConfig.isRandomMapCandidate()`，`playerCount` 缺省按 2 人（所以 v1 / v2 老图照旧进池）。于是拷进目录的 2 人预设自动进入随机池、无需改游戏代码，而 3 / 4 人预设拷进去也不会被随机抽中。

> 地图目录的唯一定义处是 `assets/script/app/zcds/ZCGame.ts` 的 `MAP_DIRECTORY` 常量（`resources/` 相对路径）。本脚本、`tests/zcds-map-loading.test.ts` 等都从那里读取，挪动目录时只改那一行。
